### MP run 3 — report `fe97dc1a-1a92-427f-8967-85f6842ec58e`, API `5b58d1d` (2026-09-23)

`OBSERVED IN PRODUCTION`: the 10-K is reused without a fetch (*"already searchable; no
fetch and no extraction"*), and **no finding carries `2027-Q1`** — periods are
`2026-Q2` (21), `FY2025` (14), `2025` (2). The correction holds and the reacquisition
does not repeat, which was the risk in changing what "ready" means.

And reading it found one more defect — in V3.18.12's own rule. The finding

> *"Named end-uses of NdFeB magnets are EVs, wind, robots, motors, pumps, compressors,
> elevators; **no data-centre or AI use is stated**."*

graded `ai_data_centres` **evidenced**. The dimension is named, and named only to be
denied: the sentence's whole point is that the company's own list of end uses omits data
centres. That is the "absence read as presence" defect inverted, produced by the rule
written to prevent its cousin.

V3.18.14 scopes a denial to its **clause**, which is both simpler and more correct than a
token window: "…elevators; no data-centre or AI use is stated" denies both mentions
however long the list, while "copper is not a semiconductor input, but our foil ships to
semiconductor packaging" denies only the first clause. One affirmative mention is enough;
only when every mention sits in a denying clause does the dimension go unnamed.
