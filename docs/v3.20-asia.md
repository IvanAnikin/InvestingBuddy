# V3.20 Phase 11 — Asian primary disclosure and grid plans (spec §3.13; D6)

Status: slice **11.1 implemented 2026-11-17** for the Taiwan Stock Exchange (V3 line, not
deployed). The other Asian sources were assessed and are recorded below. Most need an
owner decision: an API key the owner creates, or a terms question.

## 11.1 Exchange directories

Official exchange directories are discovery's first-ranked listing source
(`app/services/discovery/directories.py`, V3.19.10). A lead's listing on a venue is
verified when that exchange's own list carries it. The size constraint uses the
exchange's own market capitalisation when the exchange publishes one.

### Taiwan Stock Exchange — built

| | |
|---|---|
| Files | `https://openapi.twse.com.tw/v1/opendata/t187ap03_L` (listed company basic information) and `.../v1/exchangeReport/STOCK_DAY_ALL` (daily trading, closing price) |
| Licence | data.gov.tw, Open Government Data License v1.0: any purpose, royalty-free, **attribution required**. The OpenAPI is TWSE's agreed machine-access method. |
| Flag | `V3_DIRECTORY_TWSE_ENABLED` (default **on**) |
| Venue | `TW` (XTAI, TWD) |
| Name used | `英文簡稱` (English short name, e.g. "TSMC"); else the Chinese short name |
| Market cap | `已發行普通股數或TDR原股發行股數` (issued common shares) × `ClosingPrice` of that day. The basis names both figures, the price date and the attribution. |

Rules:
- A ticker match needs the name to agree. TWSE's English names are often acronyms, so an
  acronym now agrees when the ticker already matched, three to six letters, spelling the
  initials of the lead's full name in order with every word used, except legal words at
  the end ("TSMC" = "Taiwan Semiconductor Manufacturing Company Limited"). A real code
  paired with another company is still refused.
- No closing price that day (no trade) means no market cap, never a zero.
- A TDR (code `91xx`) gets no market cap: its file states the underlying shares, not the
  receipts the price is quoted for.
- TWSE's open data carries no ISIN. None is derived.
- ROC calendar dates (`1151116`) are read as ISO (`2026-11-16`).
- Each directory now has an optional flag. A directory whose flag is off is "no
  directory" (no request, no verdict), not "directory unavailable".
- Venue names: "Taiwan Stock Exchange", "TWSE", "KOSPI", "KOSDAQ", "Korea Exchange",
  "XTKS" and the Indian exchanges now resolve. Ticker suffixes `.TW`, `.KS`, `.KQ`,
  `.NS`, `.BO` are stripped.

## 11.2 EDINET — Japan (built 2026-11-17; XBRL facts not yet)

EDINET is the FSA's disclosure system. A Japanese company's own statutory filings now
reach the corpus through the same bridge as UK NSM and ASX documents
(`disclosures/acquisition.py`). Code: `app/services/sources/disclosures/edinet.py`.

| Step | How |
|---|---|
| Identity | The FSA's EDINET code list (`Edinetcode.zip`, public, Shift-JIS CSV) gives each filer's EDINET code, listed flag, Japanese and English names and five-character securities code. A company matches on its TSE code (`7018`, `7018.T`, `130A`) **and** an English name that agrees, the same rule as `find_listing`. An unlisted filer sharing the code is never matched. |
| Index | EDINET lists filings by **day** only. The window's days are read into `edinet_filings` / `edinet_index_days` (migration 059), newest first, at most `V3_EDINET_INDEX_DAYS_PER_RUN` (40) per run. `scripts/edinet_index_backfill.py` fills the whole window ahead of time. A day read on that same day (Japan time) stays provisional and is read again. |
| Listing | A query on the issuer's own EDINET code. A large-holding report filed by a fund *about* the issuer is not the issuer's filing. Withdrawn filings and filings with no PDF are refused. Unread window days are reported as holes (`pages_failed`): a hole is not evidence that a report is absent. |
| Content | `disclosure2dl.edinet-fsa.go.jp/searchdocument/pdf/<docID>.pdf`, the official PDF (public). It is what a citation opens, and it must name the issuer: its English name, or its official Japanese name (`内海造船株式会社`) compared after NFKC with spaces removed. |
| Period | Title only (`edinet_filing` is a title-only source type). The title is composed from EDINET's metadata: `Annual Securities Report for the fiscal year ended 31 March 2026`, `H1 FY2027 Half-year Report (six months from 1 April 2026)`, `Q3 FY2024 Quarterly Report`. A fiscal year is named by the year it ends in. |
| Ranks | Annual report (120) first, half-year (160), quarterly (140, until April 2024) and amended annual reports next, then extraordinary reports (180) and registration statements. Confirmation letters, buy-back status reports and large-holding reports are administrative. |

**The key.** `EDINET_API_KEY` is the owner's free key, issued by the FSA after
registration with SMS multi-factor authentication. It is needed only for the daily
document list. It is sent as the `Ocp-Apim-Subscription-Key` request **header**, which
was measured to work on 2026-11-17. It is never sent as the `Subscription-Key` query
parameter, so no URL that is built, stored or logged carries it. The code list and the
PDFs are public and are fetched without it. Without a key the source is off, whatever
`V3_EDINET_DISCLOSURES_ENABLED` says. In Azure it belongs in Key Vault as an app-setting
reference.

**Language.** The extractor's language detector knows Latin-script stopwords only, so a
Japanese filing was labelled English and would never be translated. It now falls back
to the writing system (`script_language`) when the stopword scan cannot tell. A
confidently English text keeps its label. A real half-year report (Naikai Zosen,
`S100ZFII`, 21 pages) became 33 indexed chunks labelled `ja`. Slice 10.1 can then
translate them.

**Measured on 2026-11-17.**
- With the key, one weekday listed 2,118 filings: 894 half-year reports, 868
  confirmation letters, 29 annual reports and the rest.
- The public PDF host served `%PDF` without a key.
- The real half-year report named its issuer in both scripts on the cover page.

**Not yet (11.2b).**
- XBRL statement facts: EDINET's `type=5` CSV of the tagged statements, which needs
  the key.
- English-language documents (`englishDocFlag`).
- An Azure-side scheduled backfill. Today the backfill is an operator job, and runs
  read at most 40 missing days each.

**Terms.** EDINET information is published by the FSA for reuse. Cite "EDINET" (Financial
Services Agency, 金融庁) as the source. The day listings are read one at a time and paced.

## 11.3 OpenDART — Korea (built 2026-11-17; XBRL financials not yet)

DART is the Financial Supervisory Service's disclosure system, and OpenDART is its
official API. A KOSPI or KOSDAQ company's own filings now reach the corpus through the
same bridge as EDINET, NSM and ASX documents. Code:
`app/services/sources/disclosures/opendart.py`.

| Step | How |
|---|---|
| Identity | OpenDART's corp-code list (`corpCode.xml`) gives each filer's eight-digit `corp_code`, its Korean and English names and, when listed, its stock code. A company matches on its KRX code (`005930`, `005930.KS`) **and** a name that agrees: the English name by the `find_listing` rule, or the Korean name exactly. The listed rows are held in `opendart_corp_codes` (migration 060), because the download is slow (see below). |
| Listing | `list.json` is per company (`corp_code`). Three disclosure types are read separately, so a filing's type comes from the query, never from its title: periodic reports (`A`), major-matters reports (`B`) and exchange disclosures (`I`). Each type reads at most 3 pages of 100. A row filed under another `corp_code` is refused. A refused key stops the listing and says so. |
| Content | `document.xml?rcept_no=…`: the filing's **original** document, a zip of DART's own XML markup (`dart4.xsd`). The main document (`<rcept_no>.xml`) must carry the issuer's `corp_code` in its own header (`<COMPANY-NAME AREGCIK="…">`). It is converted to plain HTML: tables stay tables, section titles become headings, images and the machine summary are dropped. The shared extractor then reads it, labelled `ko`. The citation opens the public viewer `dart.fss.or.kr/dsaf001/main.do?rcpNo=…`. A repeat run finds the held filing by its `rcpNo` (a document-id query parameter, like the ASX's `idsId`). DART's own PDF download needs a browser session and is not used. |
| Period | Title only (`opendart_filing`). The title is composed from the report name and the company's fiscal year-end month (`company.json` `acc_mt`). A December year gives `Q3 FY2026 Quarterly Report (period to September 2026) — 분기보고서 (2026.09)`. A March year gives `Q1 FY2027` for the June quarter. With no year-end month, no quarter is named. |
| Ranks | Business report (사업보고서) first, then half-year (반기보고서), quarterly (분기보고서), amended periodic reports and preliminary results (잠정실적). Major-matters reports come next. IR and AGM notices are administrative. |

**The key.** `OPENDART_API_KEY` is the owner's free key, issued by the FSS. The allowance
is 20,000 requests a day. OpenDART accepts the key **only** as the `crtfc_key` query
parameter, so these safeguards apply:
- The key is passed to the transport as a parameter (`transport.guarded_get`), never
  written into a URL that is built, stored or returned.
- The transport reports failures as codes, never as exception text, which can carry
  the URL.
- The `httpx` logger is capped at WARNING.
- The log redaction filter now scrubs `crtfc_key=` values. Before this slice, `\bkey=`
  missed them, because `_` is a word character.

Without a key the source is off. In Azure the key belongs in Key Vault.

**A slow host.** Measured from this project on 2026-11-17, OpenDART served about 7 KB/s:
- Samsung's quarterly-report zip (367 KB) took 52–59 s.
- The corp-code list (3.6 MB) took 499 s.

So each OpenDART request gets `V3_OPENDART_FETCH_TIMEOUT_SECONDS` (240). The shared
15 s default would have refused every real document, although every unit test passed.
The corp-code list is held:
- `scripts/opendart_corp_codes_refresh.py` reads it, allowing 900 s.
- A run trusts the held list for `V3_OPENDART_CORP_CODES_MAX_AGE_DAYS` (30). After that
  it downloads the list again, and uses the stale rows if the download fails.

**Measured end to end on 2026-11-17** (real API, scratch PostgreSQL, PostgreSQL search
backend):
- The corp-code list held 4,017 listed companies. Samsung Electronics (005930 →
  `00126380`), SK hynix (000660 → `00164779`) and LG Energy Solution (373220 →
  `01515323`) all matched.
- Samsung's listing found 118 filings in 5 requests (10.8 s).
- Its latest quarterly report (`20261116001482`, 4.6 MB of DART XML → 858 KB of HTML in
  0.34 s) became READY: 1,029 indexed chunks, all labelled `ko`, period `2026-Q3`.
- A second call reused it at once.

**Statements (11.3b, built 2026-11-17; [ADR-101](DECISIONS.md)).** When a business,
half-year or quarterly report is read, its consolidated statements as DART holds them
(`fnlttSinglAcntAll`, the filing's XBRL) become statement facts of the same document.
Code: `app/services/sources/disclosures/opendart_statements.py`.

| Step | Rule |
|---|---|
| Request | `corp_code`, `bsns_year`, report code (`11013` Q1, `11012` H1, `11014` Q3, `11011` annual), `fs_div=CFS`. The key is only `crtfc_key`. A non-December year end tries two business years; the receipt check decides. |
| This filing | Every row must carry the document's receipt number, the issuer's `corp_code` and the report code, or nothing is read. Amended reports are not read. |
| Frame | Kind and period end from the report name, plus the fiscal year-end month (`company.json` `acc_mt`): a half-year report must be 6 months in, a quarterly report 3 or 9, an annual report 12. Each row's own period name (`1분기` / `반기` / `3분기`) must agree. |
| Columns | BS: this period end and the last year end. IS/CIS: the three months (plus H1 in a half-year report) and the same spans a year earlier. CF is year to date, so it is read at Q1, H1 and the year only. An annual report gives three years. |
| Lines | Balances from BS, cash flows from CF, other flows from IS/CIS (which must agree). `ifrs-full_*` go through the shared concept map; `dart_OperatingIncomeLoss` (영업이익) fills `operating_profit` under its own label; every other DART concept and every non-standard row is skipped. |
| Store | `extraction_method = dart_xbrl`, locator `opendart:<concept>@<statement>/<column>`, scope Group, currency from the row (KRW), no scale. Text figures the statements cover are dropped. Downstream they count as tagged statement reads. |

**Checked live (2026-11-17).** Samsung's 2026 Q3 report gave 20 facts, its 2025 annual
report 42, about 18 s per request. Hand checks: Q3 profit (KRW 75.1 tn) plus H1 profit
(118.9 tn) equals the nine months the statement states (194.0 tn), and Q1 revenue
(133.9 tn) plus Q2 (171.5 tn) equals H1 (305.4 tn).

**Not yet.**
- Separate (parent-only) statements of a filer without subsidiaries.
- Re-reading filings held before 11.3b.
- A scheduled corp-code refresh in Azure. Like EDINET's backfill, it waits for a V3
  deployment; today it is the operator script.

**Major-matters decisions (11.3c, built 2026-11-17; [ADR-102](DECISIONS.md)).** The
report's change-events block lists a Korean issuer's major-matters decisions as typed
corporate actions. Code: `app/services/sources/disclosures/opendart_major_matters.py`,
wired in `pipeline/change_events_step.py`.

| Step | Rule |
|---|---|
| Which | One `list.json` request (`pblntf_ty=B`, the 180-day window). Then one request per decision type named there, at most 10, each to its own endpoint (`piicDecsn`, `cvbdIsDecsn`, `tsstkAqDecsn`, …). 25 types are read; others are counted in a note. |
| Identity | Held corp codes only (KRX code and an agreeing name). The list is never downloaded here. |
| Terms | Amounts in won, ratios as stated (shares on conversion vs. shares outstanding, deal vs. total assets), ISO dates, English enums (offering, capital-increase method), use of funds by purpose. A `-` is absent; nothing is derived. |
| People | Counterparties and targets are named only with a company marker; otherwise `individual_or_unnamed`. Lawsuit plaintiffs are never carried. |
| Events | A bond issue stated for debt repayment adds a `maturity_refinanced` change event. |
| Citation | Each action's own receipt, which can be a later re-filing of the listed decision, and its DART viewer address. |

**Checked live (2026-11-17), 5–6 s per issuer, safety gate clean.**
- Samsung Electronics: a KRW 15 tn buyback plan and three treasury-share disposals.
- A KOSDAQ issuer: a private convertible bond, with 2.19 m shares on conversion stated
  as 24.04 % of shares outstanding, plus two third-party capital increases and a bonus
  issue.
- A bond with warrants of KRW 6 bn stated for debt repayment, read as a refinancing
  event.

The web report shows these as "Corporate actions (major-matters reports)" in the
change-events section. That rendering has not been checked in a browser.

**Terms.** OpenDART publishes public disclosure information from the FSS. Cite "DART
(금융감독원)" as the source. Like the other private-use sources, the terms need a review
before any public launch.

## 11.4 Exchange announcements (built 2026-11-17; [ADR-103](DECISIONS.md))

**Terms first.** Each venue's terms were read before any code:

| Source | Decision | Why |
|---|---|---|
| TDnet (JPX) | **Excluded** | JPX's site terms prohibit collecting data or making secondary use of it for commercial purposes without permission or a paid contract, and generative-AI use that runs against the site's operational policy. Bulk access is the paid TDnet API; the public service keeps 31 days. EDINET (11.2) already gives the statutory filings. |
| BSE | **Excluded** | The website disclaimer prohibits any reproduction, redistribution or transmission of its information. |
| NSE | **Excluded** | Automated collection is prohibited (11.1). |
| TWSE | **Read** | The OpenAPI is TWSE's published interface, under the Open Government Data License v1.0 (attribution). MOPS pages are not read. |

**TWSE material announcements.** Code: `app/services/sources/disclosures/twse_material.py`;
table `twse_material_announcements` (migration 061); operator job
`scripts/twse_material_refresh.py`.

| Step | Rule |
|---|---|
| Feed | `openapi.twse.com.tw/v1/opendata/t187ap04_L` (上市公司每日重大訊息). Each row is a whole announcement: code, short name, ROC date and time (Taipei), clause (符合條款), fact date, subject, body. One announcement day only (measured: 115 rows, one date, about 170 KB, 3 s). |
| Holding | Every read is held, keyed `<code>-<yyyymmdd>-<hhmmss>-<digest>`. A re-read adds nothing; a corrected announcement is a second row. One process reads the feed at most once an hour. History starts with the first read. |
| Identity | The company must match TWSE's directory (`t187ap03_L`) on its code and an agreeing name. Rows are attributed by the feed's `公司代號` only. |
| Content | The held row rendered as HTML, every field escaped: one paragraph of the stated fields with the subject, one with the whole body (the shared extractor drops paragraphs under 40 characters, which most single Chinese lines are). Read by the shared bridge as `twse_material_info`, title-only period, language `zh`. |
| Citation | `…/t187ap04_L?announcement=<ref>`. The feed stops showing a row after its day, so the held row and the raw artifact are the record. |

**Checked live (2026-11-17).**
- The feed read in 3.1 s: 115 rows held, none refused.
- Silergy (6415) and YFY (1907) were verified and listed their announcements; the safety gate found nothing.
- TSMC (2330) was verified, and the listing honestly said nothing was held for it.
- Silergy's media-clarification announcement went through the full bridge into two `zh` chunks, header and body, with the issuer check passing.
- Code 2072 was refused: TWSE's directory gives its English short name as `CENE`, which does not agree with "Century Energy" under the 11.1 name rule.

**Not yet.**
- TPEx (OTC) companies.
- History before the first read.
- A scheduled daily refresh in Azure, which waits for a V3 deployment; today it is the operator script.
- English translation: the 10.1 parallel-corpus job covers these rows like any other held `zh` document.
