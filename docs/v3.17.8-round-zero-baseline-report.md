## 1. The defect, in the production record

`evidence_before_json` was written at exactly one place: `controller.complete_round`,
for the *next* round. `store.create_decision` built the row without it. So every **round
0** was measured against `EvidenceSnapshot.from_dict(None)` — all zeros.

All four live decisions carry the tell:

```
closable_gaps_closed: -14, -16, -28, -32        improved: true
```

Minus fourteen gaps were not closed. That number is `0 − 14`: the company's *pre-existing*
open gaps subtracted from a baseline that did not exist. `facts_added: 35` counted facts
the platform had held for weeks.

The consequence is not cosmetic. The improvement threshold exists precisely so that a
round which acquires nothing cannot buy another, and a missing baseline **inverts** it:
every round 0 reports `improved: true` regardless of what it acquired. It has cost
nothing so far only because `cost_unknown` stops every decision at round 0. **It becomes
live spend the moment a price book is configured** — which is why this slice lands
before one.

---

## 2. The contract, stated where it was missing

> **A round is measured against a snapshot taken before anything that could execute it
> exists — or it is not measured at all.**

| Rule | File |
|---|---|
| `create_decision` takes `evidence_before` as a **required** keyword and raises `MissingEvidenceBaseline` for a company decision without one | `app/services/escalation/store.py` |
| `escalate_discovery_run` snapshots **before** creating the decision — at that instant no job for it exists, so nothing can have moved the evidence | `app/services/escalation/controller.py` |
| `_enqueue` refuses to queue **any** round of **any** decision with no baseline | `app/services/escalation/controller.py` |
| `complete_round` reads the baseline with `EvidenceSnapshot.persisted`, which answers `None` for an absent measurement rather than zeros | `app/services/escalation/controller.py` |

`_enqueue` is the choke point on purpose: the discovery-council path, the next-round
authorisation and the recovery sweep all pass through it, so a producer written next year
inherits the guarantee without having to know it exists.

**Later rounds are unchanged in substance:** this round's `after` snapshot is still the
next round's `before`. What changed is that it is now **flushed before** the next round's
job is enqueued, so round *n+1* obeys the same rule as round 0. The job-before-status
ordering that makes a crash recoverable is untouched.

## 3. A missing baseline fails closed

A decision created before this slice has no baseline and its round may already have run.
Snapshotting "now" would produce an *after* measurement wearing a "before" label, so the
platform refuses to guess.

**New terminal reason: `evidence_baseline_missing`.** It is the third member of a family
whose members must never be confused:

| Reason | The claim it makes |
|---|---|
| `exhausted_no_improvement` | about the **world** — research ran and there was nothing new |
| `research_did_not_complete` | about the **platform** — we did not manage to look |
| `evidence_baseline_missing` | **neither** — we cannot compute the delta, so we will not authorise paid work on a guess |

`decide_next_state` asks it **after** "did research happen?" and **before** "did it
acquire anything?", because the second question has no answer without a baseline and the
old code answered it anyway.

`improvement_json` then carries `measurable: false` and **no numeric dimensions at all**.
Zeros there would be indistinguishable from a round that genuinely acquired nothing, and
the UI renders the sentence rather than a row of zeros.

### The recovery invariant

`recover_stranded_decisions` may snapshot a baseline **only** where it can prove the round
never began:

1. status is `research_required`;
2. `escalation_round == 0`;
3. **no `research_jobs` row exists under the decision's round-0 idempotency key.**

The third is the one that is not obvious. `JobStore` commits in its own session, so a
claimable — possibly already executed — job can outlive a decision rolled back to
`last_job_id IS NULL`. Without that check the repair path would reintroduce the defect it
exists to survive.

Everywhere else the decision is closed `abandoned` / `evidence_baseline_missing`. That
frees the company: `ux_research_decisions_one_open` stops blocking it and a fresh decision
carrying a real baseline can be made. Failing closed must not trade one permanent lockout
for another.

`recover_stranded_decisions` now also takes its rows `FOR UPDATE … SKIP LOCKED` and
re-checks under the lock, as `reconcile_terminal_decisions` already did. It writes a
baseline now, and two sweeps meeting the same row must not each take their own snapshot.

**The four historical production decisions are not rewritten.** Their deltas are the
evidence of the defect.

## 4. Gaps opened and gaps closed are two numbers

A single signed `closable_gaps_closed` cannot be rendered honestly — `-14 gap(s) closed`
is not a statement about anything. The delta now carries both, non-negative:

```
closable_gaps_closed   gaps that CLOSED during the round
closable_gaps_opened   gaps the round newly DISCOVERED
```

Discovering a gap is still a legitimate result of reading something new and still does not
count against improvement. It is now *reported* as what it is, in the API schema, the
TypeScript type and the queue UI.

### 9.5 What this round would have reported before the fix

Same company, same work, baseline NULL:

```
indexed_chunks_added: 383      <- a corpus acquired days earlier
closable_gaps_closed: -211     <- larger than all four historical rows
improved:             TRUE     <- on zero acquisition
```

`improved: true` with `open_closable_gaps_remain: true` and round 0 of 2 reaches the
budget clause — and **with a price book configured it would have bought a second paid
round on evidence the platform already held.**

### 9.6 The stronger result: it was the evidence that stopped it, not the cost mask

All four historical decisions terminated at `cost_unknown`. **This one did not reach the
cost clause at all.** `decide_next_state` asks "did it acquire anything?" before "may we
afford more?", and the honest delta answered first: `exhausted_no_improvement`.

That matters because `cost_unknown` was the *mask*. A validation that stopped at
`cost_unknown` would have proven only that the mask still works. This round proves the
**improvement threshold itself** now refuses to authorise paid work — which is the
property that has to hold once the mask is removed.

It also caught the exact failure the design was written to prevent, in production, on a
real round: **16 findings written, nothing acquired.** Model output did not buy a round.

## 11. Recommended next slice

**Durable-job → V3 research/tool/cost attribution — BEFORE configuring a price book.**

`cost_usd_total` is NULL on every decision, including the one validated above. A price
book configured now would price work the platform cannot attribute to the decision that
ordered it, and the first thing it would produce is a *number* rather than a *correct*
number — which is worse than NULL, because NULL is currently load-bearing: it is what
makes the budget clause refuse.

Order, and why:

1. **Attribution** — join durable-job execution to `research_tool_calls` / consumption and
   populate `research_decisions.cost_usd_total`. Until this lands, a price book has
   nothing correct to multiply.
2. **Price book** — only once a decision can state what it spent. The two spend guards
   are then both live and both honest: the evidence delta (this slice) and the budget.
3. Then the deferred items: Chair "0 findings" wording, the standalone worker (a container
   recycle is still a worker outage), European filing ingestion.

One observation from §9.4 that belongs to slice 1: the round wrote **16 findings and
acquired nothing**, and `open_closable_gaps` grew 176 → 211. MRNA keeps discovering gaps
it cannot close. That is honest behaviour by the loop, but it means a second round would
have to be justified by something other than gap count — worth knowing before any budget
is attached to one.
