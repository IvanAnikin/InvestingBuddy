## 2. What was wrong, restated precisely

```python
# investigator.py, before
payload = getattr(response, "payload", None)
return payload if isinstance(payload, dict) else {}
```

`ModelResponse` already carried `truncated` and `finish_reason`, and the DeepSeek provider
had already decided whether a JSON object could be read at all. Returning the dict threw
away all three. Downstream, two `return`/`continue` paths in `_write_up` then produced no
finding, no gap and no counter — so a run could retrieve six citable T1 chunks, spend the
tokens, and record nothing about why it produced nothing.

## 3. What the instrument now measures

Five states, deliberately separate counters, because each points at a different fix:

| State | Counter | Leaves a gap? |
|---|---|---|
| (a) valid JSON, empty object | `responses_empty_payload` | yes — `tool_unavailable` |
| (b) no JSON object could be read | `responses_unparseable` | yes — `tool_unavailable` |
| (c) reply hit the output ceiling | `responses_truncated` | (recorded on the gap text) |
| (d) statement citing nothing | `statements_dropped_uncited` | no — behaviour preserved |
| (e) findings produced | `responses_with_findings` | n/a |
| — fabricated citation | `fabricated_citations_discarded` *(existing, unchanged)* | yes |

Plus `responses_total` and `finish_reasons` (an allowlisted histogram, e.g. `{"length": 3}`).

(b) and (c) are counted **independently** and normally co-occur — a reply cut at the token
limit is usually also unparseable. Collapsing them would hide which one to fix.

**`responses_empty_payload` was added beyond the four you named** because without it (a)
cannot be distinguished from (b) — requirement (e) of the brief. It is the minimum needed
to satisfy "distinguish a) empty payload from b) malformed JSON".

## 4. Where it surfaces

`outcome.loop["investigator_diagnostics"]` — beside the existing
`fabricated_citations_discarded`, on the same path, merged per worker by
`_RoleRoutedInvestigator` (a fresh investigator is built per task, so an unmerged counter
would be discarded every task).

A run that produced no findings now **says why on the report**, via `degraded`:

> *"3 of 7 model repl(ies) could not be read as JSON, so the evidence retrieved for those
> questions was never interpreted"*

No schema change: the V3 panel already renders `degraded`.

Reporting numbers here would mean inventing them. The only figures that exist are from
test doubles, and those measure the instrument, not the model.

### 7.2 Does production/live evidence identify the actual cause?

**No — not yet.** What is established from the *old* runs remains exactly what the
forensic established, no more:

* evidence was retrieved and citable (6 hits each for `pipeline_state`, `regulatory_posture`);
* the ledger was never reached (the distinctive unsupported-draft gap is absent);
* `_write_up` returned `([], [], False)` via one of the two silent paths;
* `fabricated_citations_discarded = 0`, so the citation guard did not fire;
* 7 model calls, 7,285 completion tokens ≈ **1,041 average against a `max_tokens` of 1,200**.

### 7.3 What remains unproven

1. **Which silent path fired** — (a) empty, (b) unparseable, or (d) uncited. The
   instrument now separates them; nothing has measured them yet.
2. **Whether truncation is the cause.** The token arithmetic is suggestive and nothing
   more. It has *not* been treated as the answer, and `max_tokens` was deliberately left
   at 1,200 so the measurement is not contaminated by the fix.
3. **Whether the same failure affects the Chair and Red Team.** It almost certainly does:
   `chair.py:257` and `red_team.py:206` contain the *identical* `_complete_json` shape,
   returning `{}` on a non-dict payload. **Out of scope and not modified.** Worth its own
   decision once 1a has measured the investigator.

## 8. Recommendation for V3.16.1b

**Do not implement 1b yet. Measure first.** The sequence that yields a real answer:

1. Merge and deploy 1a (needs your authorisation — no production action has been taken).
2. Run MRNA once through the production website flow.
3. Read `investigator_diagnostics` off the run and the new `degraded` lines.

Then, and only then, the measurement selects the fix:

| Measurement | Indicated 1b action |
|---|---|
| `responses_truncated > 0` and `responses_unparseable > 0` | raise the investigator's output budget (make it configurable); consider trimming the JSON-dump evidence rendering, which wastes input and output tokens alike |
| `responses_unparseable > 0`, `responses_truncated == 0` | give the V3 provider branch the one-shot JSON repair the V2 client already has — a contract-parity fix, not a budget one |
| `responses_empty_payload > 0` dominant | a prompt/model-capability problem: the reply was read correctly and said nothing |
| `statements_dropped_uncited > 0` dominant | the model answers without citing; the fix is prompt or evidence *rendering*, and the citation rule stays exactly as it is |

If the measurement is ambiguous, the next step is more instrumentation, not a guess.

**One thing I would not do on any of these branches:** weaken the citation guard. A
statement citing nothing must still never enter the ledger. Only its silence was wrong,
and that is now fixed.
