# V3.19 — Implementation Plan

**Companion documents:** [spec](v3.19-dynamic-discovery-spec.md) ·
[acceptance report](v3.19-acceptance-report.md).

Each slice is one PR off `main`. A slice is merged and deployed dark before the next one
starts, unless it is docs-only. **No migration is planned** (spec §6). If one becomes
necessary, it is applied additively *before* the code that reads it is deployed.

The brief's suggested numbering was re-ordered after the forensics, for two reasons:

- The Kering defect is live in the current code and independent of Discovery, so it ships
  first.
- Constraint verification is pure logic, which can be proven offline before any network
  path depends on it.

## Gates for every code slice

- `ruff check` clean.
- `pytest` passes in both configurations:
  - on the default SQLite configuration;
  - with `V3_TEST_POSTGRES_URL` set to a real PostgreSQL 16 at head 041.

  State `ENABLE_INTEGRATION_TESTS` next to the counts.
- `mypy app` at or below the 71/10 baseline.
- Web slices: `npm run typecheck`, `npm run lint`, `npm run build`, and the Playwright
  discovery specs.
- Before every merge, an independent **code review** and **security/evidence review**
  (subagents). Blocking, high and medium correctness, security or evidence findings are fixed.

## Production activation order

1. Merge and deploy each slice. The new behaviour stays dark behind its flag, or is a
   correctness change with no new spend.
2. Set `V3_DYNAMIC_DISCOVERY_ENABLED=true` only after .4 and .5 are deployed. This is an
   app-setting change on the existing environment and needs no new infrastructure.
3. Run the acceptance queries. Read every output, then check the database through the
   lineage endpoints and `az webapp ssh` reads.

## Human-gated steps (the only planned stops)

- A new paid provider or new infrastructure: none is planned.
- A destructive migration: none is planned.
- Azure authentication that needs the user.

## Slice detail — as built

Every slice below was reviewed by at least one independent code review and, where it
touched a network or text surface, a security/evidence review. Each review returned
REQUEST CHANGES at least once; every blocking/high/medium finding was fixed before
merge. The list of what each review caught is kept here because it is the most useful
record of what this kind of code gets wrong.

### V3.19.1 — metric semantics + official critical-minerals list (PR #234, `a4cf283`)
- `sources/metric_semantics.py`: ONE span-anchored rule, `is_flow_or_ratio_at`, used by
  the prose parser, the table-row matcher, the excerpt ranker and the ambiguity check:
  a balance label next to a flow prefix ("cost of", "interest on", "an increase in") or
  a ratio suffix ("/ EBITDA", "to total capital", "cost") names another metric.
- A dated balance ("net debt at 31 December 2025 was €2,100m") no longer takes the day
  as the value (reproduced on main before the fix).
- `sources/critical_minerals.py`: USGS 2022 (50) and final 2025 (60) lists with Federal
  Register citations, every name checked against the official PDF. The
  `critical_materials` dimension becomes partially evidenced only when a finding states
  the company PRODUCES the designated commodity (verb-object, not proximity).
- Review caught: fixed-width lookbehind missed line-wrapped and suffix forms; the three
  matchers disagreed; the table check ran over the whole cell; a mention count was
  treated as production.

### V3.19.2 — Discovery Intent (PR #235, `65f7e55`)
- `discovery/intent.py`: closed-vocabulary intent; per-term polarity (positive /
  negated → `excluded` / not-a-filter); hard/soft cue rules with recorded basis; union
  geography; materials vs end markets; explicit selectors win.
- Review caught (two rounds): "non-US" filtered TO the US; "not large cap" requested
  large caps; a Country selector widened to its region; "help us" became a US filter;
  "Latin American" became the US; "silver lining" passed narrowing; a one-word slack in
  the negation regex made "non-cyclical European" exclude Europe; extra spaces lost "US".

### V3.19.3 — constraints, official FX, freshness (PR #236, `93d52eb`)
- `discovery/constraints.py`, `fx.py` (FRED H.10), `freshness.py`; council research
  signals follow the reuse contract (legacy = history only); engine stamp `v3.19`.

### V3.19.4 — dynamic discovery, dark (PR #237, `f164643`)
- `discovery/leads.py`, `identity.py`, `screening.py`, `pipeline.py`; orchestrated in
  `market_discovery_service._run_dynamic_discovery`; one consumption row per run.
- Review caught: generic-word and foreign-TLD issuer domains (mining.com, kering.xyz)
  verifying listings; the venue never checked on the page; short tickers and stray
  ISINs verifying; HK$/CA$/pence misread; "FY2025: 8%" read as 2025; revenue periods
  string-sorted; a held company's identity inherited by name; a failed stage reported as
  "no match"; scale/currency/date taken from the provider's claim, not the page.

### V3.19.5 — council contract (PR #238, `8044429`)
