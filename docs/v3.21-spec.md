## 1. Free-form segment discovery (F1, F2)

**Goal:** any segment the owner types ("cybersecurity", "OT security for utilities", "Japanese power semiconductors", "subsea cable installation vessels") is accepted. It drives candidate generation and is checked on each candidate, without a fixed taxonomy.

1. **Segment terms.** The parser extracts **segment terms** from the text when no fixed theme matches:
   - meaningful noun phrases from `unmatched_terms`, after stop-words, geography, size and style words are removed (deterministic, capped at 6 terms, each 3–40 characters, letters, digits, spaces and hyphens only);
   - plus any `industry_keywords` sent explicitly.

   A thesis that has segment terms is **not** "needs narrowing". A thesis that is only vague words ("good companies", "growth") still is.
2. **Optional model expansion.** `V3_SEGMENT_EXPANSION_ENABLED`, default on, needs the research model. One JSON call proposes up to 8 synonyms and 3 adjacent industry names for the terms:
   - Output passes the same sanitiser.
   - Nothing is kept that does not share a token with the terms or the text.
   - The call is recorded with its prompt version and model.
   - A failed call means terms only, never a failed run.
3. **Intent.** `DiscoveryIntent.segment_terms` and `segment_synonyms` are persisted in `parsed_thesis_json.discovery_intent`. When there is no fixed theme, the **industry constraint** is built from them: `requested = segment_terms`, **hard**.
4. **Exposure check.** `screening._terms` adds a word-boundary pattern per term and synonym. `verify_industry` then works unchanged:
   - a candidate passes only on a verified exposure passage (issuer page, filing or fetched page);
   - a candidate with no checkable text is `unknown` and is listed apart, as size-unverified names are.
5. **Recall and web planning.** Both use the sanitised terms as their focus. The "never the raw text" rule is kept in spirit: only the sanitised terms travel, never the free text. The universe builder skips the sector-wide registry fallback when segment terms exist. Curated names come only through a fixed theme, or by matching their registry keywords against the terms.
6. **API and UI.**
   - `POST /parse-thesis` and the run response show `segment_terms` and `segment_synonyms`.
   - The discovery form gets an optional "Segment keywords" field, sent as `industry_keywords`.
   - The parsed preview shows the terms as chips.

**Acceptance:**
- "US small-cap cybersecurity software companies" → 201.
- Recall queries contain "cybersecurity".
- A candidate without cybersecurity exposure is excluded or unknown on the industry check, never shortlisted.
- None of the 11 fixed themes changes behaviour (existing tests stay green).

## 2. Size words under a numeric ceiling (F3)

1. Under a numeric ceiling (explicit, or the platform default), size **words** that name small sizes ("small-cap", "smaller", "small and mid", "micro-cap") no longer cut the bands. `requested = buckets_below(ceiling)`, so the number decides. The words are kept as `size.words` for display.
2. The default ceiling now also applies when the words name a band that sits entirely below it. Example: "small-cap" with the 2bn default becomes ≤ 2bn including micro.
3. Words that name a band **above** the ceiling ("mid-cap", "large-cap") keep today's behaviour: no silent cap, and a warning.
4. An explicit `market_cap_bucket` from the API or form is still a hard band. It is a deliberate choice, not prose.
5. Recall's size phrase becomes "market capitalisation under USD {ceiling}" instead of "USD 300 million to 2 billion".

**Acceptance:** with the 2bn mandate, EGAN (0.14bn) and SMSI (0.01bn) pass size; AGYS (3.1bn) fails.

## 3. Watchlist and shortlist monitoring (F4)

**Lists.** The existing `watchlists` / `watchlist_entries` tables are used:
- **Two team lists** are created on first use: `Shortlist` and `Watchlist`. `owner` is NULL: one research space for the allow-listed admins.
- `watched_kinds_json` stays per entry.
- An entry records who added it (the proxied admin e-mail hash, as for portfolios), when, and from where: discovery candidate, report or manual.

**API** (`/api/v1/watchlists`, admin-proxied, added to the proxy allow-list):
- `GET /watchlists` returns lists with entry counts and open-signal counts.
- `GET /watchlists/{id}` returns entries, each with company, latest research record (verdict if any, date) and open signals.
- `POST /watchlists/{id}/entries` takes `{company_id | ticker+exchange, note, source}`.
- `DELETE /watchlists/{id}/entries/{entry_id}`.
- `GET /monitoring/signals?status=open&company_id=` and `POST /monitoring/signals/{id}/acknowledge`.
- `POST /monitoring/run` runs a manual pass for one list or one company. Admin only, and it is bounded.

**Scheduler (resolves Open Decision #15 for monitoring).** A periodic-task registry runs on the durable worker's existing sweep hook (every 300 s):
- Each task has a key, an interval and a `due()` check against the `source_poll_state` table (migration **062**).
- A due task is **enqueued** as a durable job with a date-bucketed idempotency key (`monitoring_pass:2026-11-22`). Restarts and multiple processes can never run it twice a day.
- No new process or dependency is added.
- Tasks are registered by later slices: monitoring pass (daily), trade press poll (every 6 h), coverage refresh (weekly), industry data refresh (weekly).
- `V3_PERIODIC_TASKS_ENABLED` (default on) is the master switch. Each task also has its own flag.

**Monitoring pass.** `monitoring_pass` handler, inside the `monitoring` package so the guard test stays meaningful.
- For every company on an active list, it calls `detect_for_company` and `persist_signals`.
- It adds **two signal kinds** (migration 062 widens the CHECK constraint):
  - `missing_information`: a blocking open question or gap in the latest research record that is still unresolved, with the question key;
  - `catalyst_window`: a dated catalyst or report date in the next 30 days, taken from the record (earnings date, auction or permit date).
- Bounded per pass at 200 companies × 25 signals.
- It **never starts paid research by itself**. The list view shows "Re-run research" next to material signals.
- `V3_MONITORING_ENABLED` is turned on with this slice. `V3_MONITORING_PASS_ENABLED` defaults to on.

**Web** (`/admin/watchlists`):
- the two lists, entries with verdict, last research date and open-signal badges;
- a signal feed with acknowledge;
- "Add to shortlist" and "Add to watchlist" buttons on discovery candidate rows and on the report header;
- a nav link.

**Acceptance:**
- A company added to the Shortlist gets signals from the next pass after a new filing is held.
- Acknowledge works.
- Two worker restarts on the same day give one pass.
- A Playwright spec covers the page with the mock backend.

## 4. Automatic report on the best candidate of each run (F5)

1. When a **thesis** run completes with at least one shortlisted, size-verified candidate (dynamic stage `eligible`, not `size_unverified`, not novelty-held), the rank-1 candidate's company gets a durable `company_research` job:
   - `research_mode=standard` by default (`V3_AUTO_REPORT_MODE`);
   - linked to the candidate (`discovery_candidate_id`).
2. **Bounds.**
   - One per run, idempotent per run (`auto_report:{run_id}`).
   - At most `V3_AUTO_REPORT_MAX_PER_DAY` (default 5) per UTC day.
   - Skipped when the company already has a completed report newer than `V3_AUTO_REPORT_FRESH_DAYS` (default 14); the existing report is linked instead.
   - Skipped when the run was a ticker run, or when the owner set `auto_report=false` on the request.
3. **Record.** The run records what happened in `auto_report_json` (migration **063**):
   - `{state: queued | skipped | linked | failed, reason, candidate_id, company_id, job_id, report_id}`.
   - The candidate row's existing analysis fields point at the job, so the UI shows progress where it already does.
4. **Shortlist.** The auto-reported company is added to the team **Shortlist** with `source=auto_report`.
5. **Flag.** `V3_DISCOVERY_AUTO_REPORT_ENABLED`, default **on**. This is an owner request: "one report on the most promising candidate from each run". Spend is bounded by the daily cap.

**Acceptance:** a thesis run on staging ends with a queued job for rank 1, a report appears, the run detail shows the link, and a second run the same day for the same company links instead of re-running.

## 5. Live industry data (F6)

These are numeric, dated, attributed series in the existing macro store (`macro_datasets` / `macro_series` / `macro_observations`, append-only vintages). They are read by `get_industry_series` and by a new `industry_context` block in the `industry_and_market` section.

| Source | Access | Licence | What |
|---|---|---|---|
| **Ember** yearly electricity data (`files.ember-energy.org` CSV) | keyless | CC BY 4.0 | generation by fuel, capacity, demand, by country |
| **IRENA** IRENASTAT PxWeb API (`pxweb.irena.org`) | keyless | IRENA terms (attribution) | renewable capacity (MW) and generation by country, technology and year |
| **EIA** API v2 (`api.eia.gov`) | `EIA_API_KEY` (free registration); off without a key | US public domain | US retail sales, generation by fuel, Form 860 planned capacity additions by technology and state |
| **FERC** | Assessed. Form 1 bulk is XBRL via eLibrary/PUDL, so it is a separate ingestion build. | — | Recorded as a gap, not built here |
| **IEA** | Assessed. Most datasets need login and IEA terms limit redistribution. | — | Stays reference-only, said so |

- **Selection.** A report selects series by the company's listing and operating countries and its electricity layer:
  - storage → battery capacity;
  - generation_fuel → generation mix;
  - transmission and distribution → demand growth.
- **Display.** Each figure shows source, series id, period and retrieval time.
- **Refresh.** Weekly periodic task, plus `scripts/ingest_industry_data.py`.
- **Flags.** `V3_INDUSTRY_DATA_EMBER_ENABLED` (on), `V3_INDUSTRY_DATA_IRENA_ENABLED` (on), `V3_INDUSTRY_DATA_EIA_ENABLED` (on, inert without a key).

## 6. Certification bodies (F7)

1. **Registry.** A registry of short-circuit and type-test bodies:
   - **STL members** are parsed from `stl-liaison.org/web/03_Members.php`, with attribution, refreshed monthly. A changed layout fails closed and the last good list is kept.
   - A curated list of other recognised labs and certifiers: KEMA Labs, IPH Berlin, KERI, TÜBİTAK MAM, CPRI, DNV, TÜV, UL Solutions, Intertek, CSA, Bureau Veritas, SGS. Each has a host, country and the accreditation scope it is known for.
2. **Verification state.** Each certification the real-asset block finds gets one:
   - `issuer_claim`: stated only in the company's own document;
   - `third_party_corroborated`: the same certificate (body + standard + product) appears on the body's own host or in a T1–T3 document from another party;
   - `body_unrecognised`: the named body is in neither list;
   - `unverified`.

   Corroboration uses held documents and, when web search is available, one search restricted to the body's host (`include_domains`). No certificate database is scraped. None is public in bulk.
3. **Qualification evidence summary.** The `competitive_position` section gets a summary:
   - certificates by body and date;
   - the share that is third-party corroborated;
   - whether any body is an STL member (the global short-circuit testing register).
4. **Flag.** `V3_CERTIFICATION_BODIES_ENABLED` (on).

## 7. Trade press by layer (F8)

1. **Feeds.** RSS/Atom feeds, mapped to electricity layers and DACH/CEE coverage. Verified live 2026-11-22:

   | Outlet | Feed |
   |---|---|
   | Utility Dive | `/feeds/news/` |
   | Energy-Storage.news | `/feed/` |
   | pv magazine | `/feed/` |
   | World Nuclear News | `/rss` |
   | Data Center Dynamics | `/en/rss/` |
   | Power Electronics News | `/feed/` |
   | offshoreWIND.biz | `/feed/` |
   | Power Engineering | `/feed/` |
   | WysokieNapiecie.pl | `/feed/` |

   T&D World, Recharge and energate have no reachable feed and are reached through layer-routed web search only.
2. **Polling.** Every 6 h through the periodic registry:
   - conditional GET (ETag / Last-Modified) through the safe fetcher, pinned to the feed host;
   - an XXE-guarded parser;
   - robots.txt respected.
3. **What is kept.** Items are stored as **theme documents** in the corpus: `subject_scope=industry`, `theme_key=electricity:<layer>`, `source_class=trade_publication`, T4. Only the title, summary and link from the feed are kept, never the article body: excerpt, not republish (§10).
4. **Company linking.** A company is linked as `mentioned` when its legal or short name appears in the title or summary, matched with word boundaries against the entity master.
5. **Change events.** `change_events` gains a `trade_press` input. The same title rules apply, with `source_kind=trade_press` and a lower weight. An event from trade press alone is labelled "reported by trade press", never "disclosed".
6. **Discovery leads.** When segment terms or layers match, recent press items (90 days) whose text matches the terms give **press leads**:
   - company names are extracted by the research model (JSON, sanitised);
   - then they go through the normal identity, venue and size verification.

   This is a candidate source that does not depend on Tavily.
7. **Layer routing.** Layer-routed web search: when web search is on, the `entity_trade_press` discovery template and the company web stage use the outlet hosts mapped to the candidate's layer as `include_domains`.
8. **Flags.** `V3_TRADE_PRESS_FEEDS_ENABLED` (on) and `V3_PRESS_LEADS_ENABLED` (on).

## 8. Sell-side and independent research coverage (F9)

1. **Coverage index.** A **coverage index**, `research_coverage_pages` (migration **064**): provider, URL, company slug, normalised name key, title, lastmod, first and last seen.
   - **Edison Group:** its public `sitemap.xml` (robots allows it) lists `/equity/<company>/` pages. It is refreshed weekly, and only URLs and titles are stored.
   - **Redeye, Research Tree, mwb research:** no usable sitemap. Redeye's sitemap is 403 to us, and Research Tree has none. They are reached only through web search restricted to their hosts, at most one query per company per 30 days, when web search is on. A hit is stored in the same table.
2. **As input.** The report's `evidence_quality_and_gaps.independent_research` block lists the coverage pages found:
   - provider, URL, date;
   - with the note that sponsored research is paid for by the issuer.

   A page is fetched and ingested as a T5 `research_consultancy` document only when it is public and robots allows it. Its claims are never used as company facts without a primary source.
3. **As a coverage-gap detector.** The obscurity score gains `independent_research_coverage`: 0 providers → highest points; 1 → middle; 2+ → low. `SCORE_VERSION` is bumped. Absence of coverage is labelled "none found in the indexed providers", not "none exists".
4. **Flag.** `V3_RESEARCH_COVERAGE_ENABLED` (on).

## 11. Out of scope

- Paid feeds (D7).
- A FERC Form 1 ingest.
- IEA data.
- Fetching Redeye or Research Tree bulk.
- Automatic position changes (ADR-100).
- Automatic re-research on a monitoring signal: it is proposed, never started.
