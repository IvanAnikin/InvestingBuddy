## 3. Design

### 3.1 Size mandate (N6)

- New `ResearchMandate` value object (thesis-level), field `max_market_cap_usd: Decimal | None`, default **2_000_000_000** for the electricity mandate and for discovery runs generally (D1). Optional `min_market_cap_usd`.
- **One size verdict**, reusing `verify_size` (`constraints.py:229`): `pass | fail | unknown | borderline`, with the components kept (shares, shares as-of, price, price date, currency, FX rate, FX date, method: `official_directory | sec_public_float_floor | shares_x_price`). ADR-061: issuer ≠ security — market cap is per issuer, summing share lines, not per listing.
- **FX**: keep FRED H.10; add ECB reference rates (`data-api.ecb.europa.eu`, `EXR/D.<CCY>.EUR.SP00.A`) for currencies H.10 lacks (PLN, CZK, NOK, SEK are covered by ECB; check H.10 coverage per currency). Rate date stored; stale > 5 business days ⇒ `unknown`.
- **Enforcement points**: (1) discovery `decide_eligibility` uses the numeric ceiling instead of bands; (2) universe generation (V3.2-5) gets the same filter; (3) legacy screener converts to USD and stops passing unknowns; (4) report-level `size_fit` re-checks at analysis time (market caps move) and states the as-of.
- **UI**: discovery form gets a "Max market cap (USD)" control, default 2bn, presets 300m / 2bn / 10bn / none; candidate rows show the size verdict and method.
- **Unknown** never silently passes: shown as "size unverified", excluded from shortlist ranking (D1).

### 3.2 Company relationship graph (N2, N3, N4) — the shared foundation

Extend the existing `entity_relationships` table (migration 028) rather than invent a new one.

**Vocabulary** (`services/entities/vocabulary.py`), new types:

| Type | Direction | Typical source |
|---|---|---|
| `parent_of` (exists) | parent → child | GLEIF L2, Exhibit 21, annual report |
| `ultimate_parent_of` | ultimate → entity | GLEIF L2 |
| `significant_holder_of` | holder → issuer, with `% held` | SEC 13D/13G (structured XML since 2024-12), UK PSC, TR-1 / major-holding notices |
| `customer_of` | customer → supplier, with `% of supplier revenue` when disclosed | XBRL concentration facts, 10-K / annual-report text, press releases of awards |
| `supplier_of` | supplier → customer | annual-report text, customer's own disclosures (inverse of `customer_of`), press releases |
| `fund_holds` | fund → security | SEC N-PORT (see 3.3; kept in its own table for volume, linked by security) |

**Evidence columns** (migration 047): every edge carries `evidence_id` (ledger/evidence ref — no uncited edges, CLAUDE.md rule 6), `source_kind`, `as_of`, `disclosed_share_pct` + `share_basis` (`revenue`, `receivables`, `purchases`, `voting_rights`), `counterparty_name_raw` (anonymous "Customer A" stays a row with no object entity — **an anonymous customer is still a concentration fact**), `extraction_method` (`gleif_api | xbrl_dimension | text_llm_verified | filing_xml`), `confidence`. The object entity may be unresolved (`object_entity_id NULL`, name only) — resolution via the V3.2-3 entity resolver when possible.

**Writers (populate — the missing half of V3.2-4):**

1. **GLEIF Level 2** — `lei-records/{lei}/direct-parent`, `/ultimate-parent`, `/direct-children`, `/ultimate-children`, `/direct-parent-reporting-exception`. A 404 means "no reported parent" — record the reporting exception (`NATURAL_PERSONS`, `NON_CONSOLIDATING`, …) instead of concluding "independent". CC0. Verified live 2026-11-14.
2. **SEC Exhibit 21** — parse the subsidiary list from the latest 10-K (US filers). Name + jurisdiction; children unresolved by default.
3. **SEC 13D/13G** structured XML — holder, % of class, date.
4. **XBRL customer concentration** — `us-gaap:ConcentrationRiskPercentage1` on `srt:MajorCustomersAxis` (benchmark axis = revenue or receivables). Customer names are filer extension members (often anonymous). `companyfacts` lacks dimensions, so read the instance XBRL of the held filing — ADR-085 already reads inline XBRL in held filings; extend that reader for dimensional contexts.
5. **Text extraction (all regions)** — an investigator task over *held* annual reports / 10-K Item 1 & 1A / ASX & NSM documents: "who are the named customers, suppliers, offtakers, framework partners; what share". Every extracted edge must pass the existing pipeline: passage-subject firewall (ADR-083) decides whose statement it is; the cited passage must contain the counterparty name and figure (verbatim check as for findings); period stated (ADR-080/093).
6. **Inverse inference** — when company X discloses Y as supplier, record `supplier_of(Y→X)` once, readable from both ends.

**Analyses (report sections, each fully cited, each with an explicit "not disclosed" state):**

- **Customers** — concentration (top-1, top-N, anonymous vs named), customer type (TSO/DSO/utility/OEM/EPC/data-centre), contract form (framework, tenor, price indexation where disclosed), dependency risk; for TSO/utility customers, the link to their published capex (3.7) — the vision's demand triangulation.
- **Suppliers** — critical inputs (GOES, copper, SiC substrates, cells …), named suppliers, single/dual-source statements, input-cost pass-through language, geographic exposure (e.g. China supply).
- **Parent & group** — direct and ultimate parent, controlling/significant holders with %, listed vs unlisted parent, subsidiaries (and listed subsidiaries — the SOTP hook for "a grid business buried inside a legacy industrial"), related-party flags.
- **Relationship map** — small graph in the web report (company in the centre, customers right, suppliers left, parent above), each edge clickable to its citation.

### 3.3 Passive / ETF ownership (N1)

**Interpretation of the ask.** "People buy it without knowing" = how much of the company is owned by index/ETF vehicles, which ones, and what that implies: flow-driven ownership, index inclusion/deletion risk, and — inversely — an obscurity signal (near-zero passive ownership = few index products cover it).

- **Source**: SEC **Form N-PORT** quarterly data sets (DERA bulk ZIPs, ~440 MB/quarter, 2019Q4–2026Q3 posted; public domain). Holdings table carries `ISSUER_CUSIP`, `ISSUER_LEI`, `BALANCE`, `PERCENTAGE` (of fund NAV); identifiers table carries ISIN/ticker. ISIN makes **non-US small caps findable** (AIM, ASX, Xetra names held by US-registered international small-cap ETFs).
- **ETF vs other fund**: N-PORT does not say "ETF" itself; classify from SEC **Form N-CEN** (fund type) — *to verify in slice 3a*; fallback: the SEC ETF company list / series names.
- **Storage** (volume-aware, B1 + Azure PG): ingest job runs as an offline worker task, keeps (a) a per-quarter **aggregate per security** (`security_passive_ownership`: ISIN/CUSIP/LEI, quarter, fund count, ETF count, total shares held, top-20 funds with weight and shares) and (b) a **fund registry** (`funds`: series id, name, sponsor, is_etf, net assets). Full raw holdings are not kept (raw ZIP stays in blob per V3.1-1 raw artifact store if retention allows).
- **Per-company outputs**: list of ETFs/funds holding it (name, sponsor, weight in fund, shares, value), **% of shares outstanding held by US-registered funds / by ETFs** (labelled exactly so — UCITS not included), quarter-over-quarter change, concentration (top-3 funds' share of passive holding). Freshness stated (N-PORT public data lags ~60 days after quarter end — *to verify*).
- **Uses elsewhere**: obscurity score input (3.6); a "theme ETF" check — if the company is in electrification/grid ETFs, its theme is *not* obscure (anti-convergence signal); index inclusion/deletion flow risk in the bear case.
- **Issuer holdings files (D8 — approved, private use, own risk)**: daily holdings CSV/XLSX from iShares (US + UCITS), SPDR, Vanguard, Invesco, VanEck, Global X, and further sponsors added one adapter at a time. They fill two gaps N-PORT leaves: **UCITS ETFs**, which have no regulator feed, and **freshness** (daily instead of quarterly with a lag). Fund universe: the electricity/grid/clean-energy/small-cap ETFs first (a curated, versioned list), then broad small-cap indices. Each adapter has its own parser and a schema-drift check, and fails closed on an unknown layout. The source registry labels them `private_use_own_risk` with redistribution `none`, the same class as FCA NSM and ASX. Ingested holdings write to the same `security_passive_ownership` aggregate with `source_kind = issuer_file`; when both sources cover the same fund and date, N-PORT wins.
- Per-company output then distinguishes **US-registered (N-PORT)** from **UCITS / issuer-file** holdings and states the date of each.

### 3.4 Earnings vs expectations (N5)

**Model** — table `earnings_results` (one row per issuer × fiscal period):
`period_end`, `fiscal_period_label` (ADR-091 fiscal calendar), `report_date`, `actual_eps` / `actual_revenue` (+ currency, evidence id — from SEC XBRL / held issuer filings, already extracted), `consensus_eps` / `consensus_revenue` (avg, high, low), `analyst_count_eps` / `analyst_count_revenue`, `consensus_source`, `consensus_as_of` (must be **before** `report_date`, else it is not an expectation), `surprise_abs`, `surprise_pct`, `consensus_status ∈ {available, thin (n ≤ 2), none, source_unavailable}`, `guidance_low/high/mid` + evidence id, `vs_guidance`.

**Sources (D2):**
- **Alpha Vantage** (free key, 25 req/day): `EARNINGS` → reported/estimated EPS, surprise, report date; `EARNINGS_ESTIMATES` → EPS & revenue estimate avg/high/low, analyst counts, revisions. EPS surprise is vendor-given; **revenue surprise is computed by us** from a revenue-estimate snapshot taken before the report date and the actual from filings — so the snapshot job must run ahead of report dates (earnings calendar from `ir_events` + Alpha Vantage). 25/day is enough for a shortlist, not a universe: budget enforced in the provider, cached.
- **Guidance-vs-actual fallback** for names without consensus (the common case < 2bn outside the US): guidance findings already exist in the ledger (`kind=guidance`, `models/ledger.py:352`); match guidance for period P to the actual for P. Sources: 8-K Item 2.02 / Ex-99.1, RNS trading updates (NSM), ASX guidance & 4C/5B.
- **Never** treat a missing estimate as zero; never invent consensus; a vendor with no coverage ⇒ `source_unavailable`, not "0 analysts".

**Outputs**: last 8 quarters table (actual, consensus, surprise %, analyst count, vs guidance), beat/miss streak, magnitude distribution, revision trend before the print, optional price reaction (close-to-close around report date from existing price providers, labelled as context). Analyst count also feeds obscurity (3.6).

**Safety (D3, [ADR-097](DECISIONS.md#adr-097-analyst-consensus-is-labelled-third-party-expectation-data-shown-only-where-earnings-are-compared-with-it))**: consensus enters the record as *third-party expectation data* — provider, as-of, analyst count always rendered — and is exempted from the estimate redaction only in this section; the platform still never states its own forecast, target or recommendation. `statement_kind` keeps withholding consensus claims found in free text (a web page saying "beat consensus" is not a consensus source).

### 3.5 Electricity vertical: taxonomy, playbook, real-asset block

- **Taxonomy** (versioned config, like playbooks): 9 layers from PDF 1 — `generation_fuel`, `transmission`, `distribution_grid_edge`, `sensing_protection_digital`, `storage`, `power_electronics`, `demand_side_decentralised` (incl. data-centre power), `utilities_grid_services`, `upstream_electrical_materials` — each with sub-segments and keyword/description anchors. **Exclusion rules**: general mining, O&G E&P/refining, coal — unless a revenue-mix test shows power generation / grid equipment dominant (the "dominant end market" rule).
- **Classifier**: assigns layer(s) + sub-segment with cited evidence (segment notes, business description); stores *primary layer* and *revenue share by layer* when segment data allows. Fixes the hardcoded `reshoring_supply_chain` tag.
- **Electricity playbook** (8th in `services/playbooks/industries.py`): blocking questions — backlog & book-to-bill, backlog quality (cancellable, price-indexed, margin-disclosed, financed/permitted), qualification evidence (type-test certificates & dates, grid-code approvals, OEM/TSO qualifications), capacity in natural unit, contracted vs merchant revenue (PPA, capacity payments, frameworks), customer concentration, input-cost pass-through, capex cycle stage, competitor capacity additions.
- **Real-asset block**: capacity units extended to MVA, GVA, km (line/cable), tonnes (core/steel), units/yr; replacement value only as cited context (D5); all fields from evidence or `not_disclosed`, never placeholders.

### 3.6 Discovery for the vertical

- **Supply-chain laddering**: start from a **driver** (config list: data-centre load, offshore-wind connection, transformer replacement, interconnection reform, capacity-market tightness) → **bottleneck catalogue** (config, versioned: short-circuit testing capacity, HVDC valves, subsea cable slots & vessels, bushings & tap changers, GOES, non-China LFP qualification, SiC substrates, queue position, HV labour) → walk the **relationship graph** (3.2) and value-chain web queries 2–3 steps upstream → candidates. `supply_chain_distance_from_obvious` becomes the actual number of hops.
- **Change-event screening**: event vocabulary from the contract's `event_trigger` enum, fed by: held-disclosure classification (ASX, NSM, Nasdaq Nordic, SEC 8-K), TED awards (later), Form 4 insider **cluster** detection (≥ 3 insiders buying within 30 days — SEC Form 4 is free).
- **Obscurity score** (positive input, components shown): analyst count (3.4), passive ownership % and theme-ETF membership (3.3), English news volume (GDELT, already connected), sector mis-tag (classifier layer ≠ exchange/SIC sector), non-English primary disclosure.
- **Anti-convergence**: a `discovery_seen` dedup store across runs; **novelty gate** — a name already researched in the last N days needs a new change-event to re-enter; **diversity quota** on layer × demand driver × regulatory regime within a run's shortlist.
- Size mandate (3.1) applies before anything is shortlisted.

### 3.7 Demand-side triangulation (customer-capex tracker)

- `grid_capex_plans` store: promoter (TSO/DSO/utility, linked to entity), plan name & edition, project, technology, capex amount + currency, period, commissioning date, status, source document (evidence).
- First sources (machine-readable, free): **ENTSO-E TYNDP 2026 project data**, **AEMO ISP**, **Berkeley Lab "Queued Up"** (project-level Excel), then German NEP, NESO/Ofgem RIIO-T3, PJM RTEP/MISO MTEP. Licences checked per source before ingest (SECURITY doc §10).
- **Triangulation check**: for a supplier with `customer_of` edges to TSOs/utilities, compare the supplier's claimed backlog/visibility with those customers' published capex in the relevant technology; report "corroborated / not corroborated / no customer named".

### 3.8 Valuation (D5: full valuation incl. fair value)

- Calc engine: EV (with net debt and its date), EV/Sales, EV/EBITDA, **EV/EBIT**, **EV per capacity unit**, **EV/backlog**; own-history range of each multiple (3–5y, from held statements + historical prices).
- Peers by **function & layer** (taxonomy 3.5) on top of ADR-089 comparability; peers come from the comparable-set store (3.10), not only "held" companies.
- **Precedent transactions**: curated `precedent_transactions` table (acquirer, target, layer, date, EV, multiple, source) — filled from cited press releases/filings.
- **Reverse DCF**: states the revenue growth and margin the current EV implies under stated discount-rate assumptions.
- **Fair-value engine (D5, ADR-099)**: a deterministic, auditable engine in `services/calculations/`. The LLM proposes assumptions; it never produces the number.
  - **Methods**: FCFF DCF; contracted-cashflow DCF for names with PPAs or frameworks; regulated-asset-base (RAB) valuation for network utilities; SOTP for a valuable grid business buried inside a legacy industrial; replacement cost of physical assets as a floor; peer- and precedent-multiple implied values.
  - **Output**: a **range**, never a point: bear / base / bull per method, plus a triangulated range. Every input is either a cited finding (period, currency, source) or an **explicit assumption** with its rationale and a sensitivity row. Assumptions include WACC (risk-free rate from FRED/ECB, cited equity risk premium, size premium flagged as an assumption), growth, margins, capex and terminal value.
  - **Upside/downside** versus the dated price is shown only beside the range, with the price date.
  - **Fails closed**: below a minimum evidence set (e.g. no audited period, unknown share count, unknown net debt) the engine returns `insufficient_evidence` instead of a number.
  - **Safety**: ADR-099 allows "fair value", "upside/downside" and "undervalued/overvalued" only inside the valuation section and the verdict; the phrase ban stays active everywhere else (council free text, memo body, web search findings). No "price target" wording, no BUY/SELL/HOLD.
- **Discount-reason classification**: when the multiple gap vs peers is material, the report must pick ≥ 1 cited reason from `{mis_tagging, size, liquidity, disclosure_language, one_off_year, governance_overhang, genuine_inferiority, unexplained}`; `unexplained` is a warning, rendered as such.

### 3.9 Financial depth

Margin bridge (price/volume/mix/cost — only where disclosed, else `not_disclosed`), incremental margin, ROIC vs WACC (WACC from the valuation engine's cited assumptions, D5), growth vs sustaining capex (where disclosed), quality-of-earnings flags (POC revenue, capitalised development, customer advances, contract assets/liabilities from XBRL), working-capital and customer-prepayment trend, full **debt maturity ladder** (XBRL `LongTermDebtMaturitiesRepaymentsOfPrincipalInNextTwelveMonths`…`AfterYearFive`), dilution history (share count series), FX exposure statements.

### 3.10 Output, rubric and comparable-set record

- **One structured record** per run → three renderings (PDF 2's suggestion): 1-page memo, 4–5 page report, and the structured record written to a **comparable-set store** (`company_research_records`: layer, size, multiples, real-asset block, rubric scores, as-of). This is what compounds.
- **8-pillar rubric** with real, evidence-derived scores (pillar definitions from the CFA Research Challenge rubric adapted; each score cites the findings it rests on; missing evidence lowers confidence, never raises a score) → verdict **PASS / WATCHLIST / SHORTLIST** (D4, ADR-098).
  - The verdict is computed deterministically from the pillar scores, evidence confidence and the valuation range. The LLM writes the rationale; it does not pick the label.
  - Thresholds are versioned config. Thin evidence caps the verdict at WATCHLIST: a name whose key pillars rest on D-quality data cannot be SHORTLIST.
  - The safety gate accepts the three tokens **only in the `verdict.recommendation` field** of the V3.20 report. `BUY/SELL/HOLD/REJECT` stay banned everywhere, and the free-text scan stays on.
  - Every rendered verdict carries the existing not-financial-advice disclaimer.
- New report sections: Customers, Suppliers, Parent & group, Passive ownership, Earnings track record, Relationship map.
- Bear-case steelman mandatory (red team output fills `self_critique`; a report without it is not publication-ready).

Cadence is Open Decision #15 — propose daily disclosure check, weekly estimates, quarterly N-PORT.

### 3.14 Portfolio review agent (D9, ADR-100)

- **Input**: a portfolio the user enters by hand (issuer, entry date, optional entry price and weight). It is stored as **private user data** in personal tables, never in public research tables (CLAUDE.md rule 10). No broker connection; it is never pulled from a broker.
- **What the agent does, per holding**:
  - checks the original thesis (the stored research record) against new evidence: monitoring signals, earnings vs expectations, relationship changes, competitor capacity, valuation-range drift;
  - reports **thesis intact / weakened / broken**, with citations;
  - sets the current rubric verdict beside the verdict when the position was entered;
  - lists the open questions to research next.
- **What it never does**: place orders, connect to brokers, suggest position sizes or rebalancing trades, or emit BUY/SELL/HOLD. ADR-100 narrows ADR-005 to exactly this. The output is a research review of the user's own list.

## 4. Invariants (unchanged, restated because these features touch them)

- Every relationship edge, holding, consensus figure and capex figure has a source, date, currency and retrieval timestamp. No uncited edge.
- Unknown is a state, not a zero: unknown market cap, no consensus, no reported parent, anonymous customer.
- No BUY/SELL/HOLD, no "price target", no position sizing, no trade execution. Consensus is shown as labelled third-party data (D3). PASS/WATCHLIST/SHORTLIST appears only in the verdict field (D4). Fair value, upside and under/overvalued appear only in the valuation section, and only as a cited, assumption-explicit range (D5). Private use only until a regulatory review.
- Private-use-only sources (Alpha Vantage, issuer ETF files, TDnet if used) are labelled in the source registry like FCA NSM/ASX and must be switched off or licensed before any public launch.
- Outbound requests use the central research User-Agent (ADR-081); no personal contact data.
