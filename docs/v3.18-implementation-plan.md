## Slice detail

### V3.18.1 — Research correctness guards
* `sec_fundamentals_normalizer`: a statement metric whose own period end differs from the
  headline period is **missing for that period** (value withheld, warning recorded, the
  stale period named). Derived ratios compute only from same-period inputs. The spread
  warning covers every statement metric.
* `snapshot_builder._val` / `final_report_generator._sec_dp`: each slot carries its **own**
  period, never the headline's.
* New `services/statement_consistency.py`: relationship checks with declared exceptions;
  inconsistent facts are flagged, derived metrics withheld, the conflict surfaced.
* `CalculationDefinition`: `numerator`, `denominator`, `directionality`,
  `interpretation`; new `cash_conversion`, `capex_to_ocf`, `fcf_margin`,
  `dividend_cover`. Evidence pack carries definition + interpretation beside each derived
  value; a guard moves self-computed ratios to `unsupported_claims`.
* Gap `knowledge_state` vocabulary; `_known_gaps` labelled; absence-claim guard.
* Tests: fixture cut from the real SCCO companyfacts payload; mutation tests for the
  period guard, the consistency check, the definition guard and the gap guard.
* No migration.

#### V3.18.1 as built

| Control | Where | What it refuses |
|---|---|---|
| Own-period rule | `sec_fundamentals_normalizer._metrics_outside_reporting_period` | A statement line whose period end is not the bundle's reporting period (`stale_period`), or a 10-Q value inside an annual bundle (`interim_in_annual_bundle`). Withheld to `withheld_fields` with its real period; absent from every ratio. |
| No legacy backfill | `sec_edgar_fundamentals.merge_fundamentals` | The period-blind parser handing back a figure the normalizer just refused. |
| Slot fails closed | `final_report_generator._sec_dp` + `snapshot_builder.field_period_ends` | Any figure reaching a report slot with an own period ≠ the reporting period, from any upstream path. |
| Statement consistency | `services/statement_consistency.py` | `contradiction` (gross profit > revenue, cash > assets, unbalanced sheet, conflicting duplicates) and `implausible` (operating income > gross profit). Ratios on a failed pair are withheld; neither figure is chosen. |
| Metric semantics | `calculations/definitions.py` | A definition without `directionality` and an `interpretation` rule cannot be constructed. New: `cash_conversion` (OCF / NI), `capex_to_ocf`, `fcf_margin`, `dividend_cover_by_fcf`. |
| Defined metrics in the pack | `calculations/statement_metrics.py`, `llm/evidence_pack._add_defined_metrics` | — (producer). Runs the **same engine**; delivers value + formula + direction + reading in one line; budgeted with the statements so it survives. |
| Self-computed ratio guard | `llm/ratio_guard.py` via `citation_checker` | A percentage no evidence item rounds to → `unsupported_claims`. |
| Whose gap is it | `services/knowledge_state.py` via `citation_checker`; `EvidencePack.known_gaps_meaning`; `RESEARCH_DISCIPLINE_RULES` | An uncited absence published as a business risk; an unevidenced "the company does not disclose …". |

**Found by the rule, not by the brief:** the same live report's *total debt 7,250.5* was
also wrong. It added a current-debt balance from the **prior** year-end (499.8 at
2024-12-31 — the comparative column of the FY2025 10-K, which carries the newest filing
year) to FY2025 long-term debt (6,750.7). Ranking on filing year reads last year's
balance as this year's; the own-period rule withholds it.

**Also new:** `dividends_paid` is read from the cash-flow statement
(`PaymentsOfDividendsCommonStock` …), so "no dividend information is available" stops
being said about filers that print it on the face of their statements.

No migration. No new setting.

### V3.18.3 — Active Evidence Acquisition
* Per-question ladder with contract re-evaluation between rungs; deterministic search
  intents; follow-ups advance to the next intent; external role eligible for any question
  whose ladder reaches rung 3.
* `verify_lead`: metric-proximity match, stored excerpt, unit/currency carried;
  previously verified leads re-citable.
* `ResearchBudget.check` wired: searches, fetches, documents, wall clock, no-improvement.
* 8-K EX-99.1 exhibits eligible for ingestion (bounded).

#### V3.18.3 as built

* **Ladder** (`LLMInvestigator._acquire`): platform tools → corpus by the question's
  search intents → one external search, taken only when the contract is unmet AND allows
  the web AND the role holds the ladder AND the run budget remains AND the question's
  own cap is not reached. Every step is logged with `why` (the missing contract
  dimensions) and `stopped` (the reason it stopped) — persisted on the question.
* **Follow-ups** start where the last round ended: no platform rung, the NEXT intent. A
  question answered with an unmet contract is re-asked while its ladder has a rung left
  (`loop._improvable`); a question whose contract forbids the web is not.
* **Budget.** `ExternalSearchBudget(limit=ModeLimits.max_web_searches)` shared by every
  task — the first enforcement of a ceiling that was declared and never checked.
* **Verification, tightened.** A numeric claim verifies only when its value sits within
  320 characters of two of the claim's distinctive words (unit words and generic terms
  excluded); "250 pages" no longer verifies "250 thousand tons". Prose claims verify
  against a document PASSAGE (≥70% of distinctive words, negations respected in both
  directions), and the evidence is that passage, verbatim, in the document's own case.
* **Re-citation.** A claim this platform verified earlier for the same company is cited
  again (same evidence id, no fetch, no duplicate row) instead of being rejected as a
  duplicate — re-runs no longer lose their external evidence.
* **Publisher tiers** (`sources/publisher_tiers.py`): filings T1, specialist agencies
  (USGS, IEA, study groups, exchanges) T3, governments T2, quality media T4, unknown T5.
  An issuer's own domain is never guessed.
* **What the writer sees**: the source excerpt first; the provider's sentence labelled
  `provider_claim_not_verified_wording`. The prompt carries the role's mission and the
  question's reason, and forbids restating another domain's figures.
* Provider prompt asks for `metric` and `geography`; both travel with the lead
  (migration 041 columns) as claim metadata, never as verified facts.

#### V3.18.4+5 as built

* **Commodities from the company's own documents** (`macro/commodities.py`,
  `director/subject_profile.py`): a 22-material vocabulary; mentions counted in the
  company's corpus (≥5 mentions and ≥5% of commodity mentions). Never a ticker table.
* **Per-commodity questions**: `PlaybookQuestion.per_commodity` is instantiated by the
  planner for the top two commodities (`commodity_market__copper`, …), with dependencies
  rewritten to the same commodity's instance; with none identified it is asked once
  about "the company's principal products". `replaces` retires the generic base question
  a sector question specialises; `optional_tools` run when available and never decide
  assignment.
* **`MINING_MATERIALS` playbook v1**: 15 questions — commodity exposure (the one blocking
  question), value-chain position, assets and production, reserves and mine life, unit
  costs, customers and offtake, commodity market and demand drivers (per commodity),
  growth projects, policy and state support, peer comparison, price sensitivity,
  jurisdiction and community, operational and environmental — and a 17-category risk
  framework. Applies to Materials / Metals & Mining. Nothing in it names a company.
* **Numbers** (`macro/commodity_sources.py`): IMF primary commodity prices via FRED (CSV,
  keyless; the guarded fetcher gained a per-call `extra_text_content_types` for it, the
  global allowlist unchanged) and USGS Mineral Commodity Summaries (PDF). USGS tables are
  read with **superscript footnote markers removed by font size** — naive extraction
  reads Australia's copper reserves as "7100,000". `W`/`NA` are not stored; `—` is zero.
* **`get_industry_series`** (flag `V3_COMMODITY_SOURCES_ENABLED`): fetch-on-miss into the
  macro store; returns latest price and 3/12/36-month changes computed deterministically
  with the input observation ids, world and top-country production and reserves with
  shares of world, and the survey's price statistics. Every figure is citable (`mo:<id>`).

### V3.18.6 — Competitive research
* `get_peer_set` (curated theme registry + SEC SIC peers, each peer verified as a real
  filer) and `get_peer_financials` (existing SEC normalizer, same own-period rule).
* Peer contract: ≥3 verified peers × ≥2 comparable metrics, else reported incomplete.

#### V3.18.6 as built

* `get_peer_set` — candidates are companies the platform HOLDS with the same canonical
  industry, ranked by whether their own documents show the same commodity. Fewer than
  three sharing the commodity is reported as a gap: producers the platform does not hold
  come from the question's verified external rung, not from this tool.
* `get_peer_financials` — each US registrant's SEC statements through the SAME
  own-period rule and SAME defined metrics as the subject (operating and net margin, cash
  conversion, capex/OCF, capex intensity, net debt), with definitions and directions.
  A peer whose statements do not normalise is not a verified peer.
* The investigator chains peer set → peer financials deterministically (US peers + the
  subject), like search → fetch. A peer's SEC filing is a `third_party_filing` source
  (tier T1), one per registrant — primary, but neither the subject's word nor an
  independent statistical authority (review of #222).
* Live check (2026-09-21): FCX FY2025 operating margin 25.1% vs SCCO 52.2%; MP's loss
  refuses the cash-conversion ratios; FCX's EPS was withheld because FCX last tagged
  `EarningsPerShareBasic` for FY2021 — the own-period rule's second real-world catch.

### V3.18.7 — Finding ownership & deduplication
* `topic_key`, `domain`, `references_finding_ids`; normalised claim key; reference-not-
  restate; counters in the run payload. Role-scoped V1 evidence packs.

#### V3.18.7 as built

* `director/ownership.py`: a new statement RESTATES an existing finding when they share a
  cited evidence item and every figure it states is one the existing finding states (or,
  with no figures, ≥60% of its distinctive words). Deterministic — no embeddings, no
  model. A restatement is not written: it is logged on its question as a reference to
  the owner's finding (`acquisition_log` rung `ownership`) and counted
  (`loop.restatements_referenced`).
* Writers receive `ALREADY ESTABLISHED BY OTHER SPECIALISTS` (up to eight findings from
  other domains, by id) and may put ids in `references`; only known ids are kept.
* **Decision: the V1 council is demoted, not role-scoped.** With the professional report
  (V3.18.8) as the reader-facing body, the V1 council's eight commentaries leave the
  reader view entirely when a professional report exists; scoping its evidence would
  have polished prose that no longer reaches the reader.

### V3.18.8 — Thesis-aware synthesis + professional report
* Lineage into job payload on both paths; `thesis_fit` questions; thesis in Chair input.
* `services/professional_report.py` assembles the 13 sections from the ledger, runs the
  safety gate + numeric verification, attaches to the report. V3 runs on the
  candidate-launched path.
* Web: typed reader, 13-section rendering, source-diversity panel, thesis-fit section,
  platform-gaps vs business-risks split; Playwright coverage.

#### V3.18.8 as built

* **Thesis carry-forward.** `director/thesis.py` resolves the candidate's thesis (text,
  parsed themes and size hints, match reason, discovery-council rationale, the market cap
  it was matched at) and derives dimensions from a closed vocabulary — never from a
  model. Each dimension becomes a `thesis_fit__<dimension>` question (owner
  `industry_analyst`, contract ≥2 items from ≥2 sources, external allowed) whose honest
  answer may be *weak* or *none*. **The user's thesis text is not put in question text**:
  question text reaches the external search provider's query context. The thesis is
  written to `research_runs.thesis_json` and the V3 payload's `thesis`.
* **Entry paths.** `POST /company-research/jobs` takes `discovery_candidate_id` (checked:
  exists, same company) and `research_mode`; both travel in the durable payload and the
  content record's inputs to `run_v3_research`. Escalation rounds carry the decision's
  candidate id. The candidate-launched path (`run_candidate_analysis`) now runs the V3
  pipeline with its candidate (closes S2).
* **The report.** `pipeline/professional_research.py` assembles the 13 sections from the
  ledger: each finding once, in the section its domain (or the question's
  `report_section`) owns, labelled `F1…`; per-section status and open questions with what
  they lack; thesis-fit dimensions and size fit; commodity and peer tables built from the
  exact tool payloads the specialists used; "what would change the thesis" by
  REFERENCE; evidence quality with source diversity by kind (distinct sources, not
  excerpts), contract and unresolved-reason counts, platform evidence gaps apart from
  business risks, and per-domain acquisition cost from the acquisition logs.
* **Editor.** One model call (the chair's routing slot) may write the executive synthesis
  and one lead per section. Every sentence must cite existing labels, introduce no figure
  its cited findings do not state, pass the shared safety scanner and the
  non-disclosure guard (a lead may cite only its own section). Failures are dropped and
  counted; under two surviving sentences the deterministic synthesis stands. A missing or
  failing model costs prose, never the report.
* **Screening.** Every finding is safety-scanned before display (withheld and counted
  on a hit); the whole block is scanned again and not attached if anything remains.
* **Web.** `readProfessionalResearch` + `ProfessionalResearchReport.tsx`; when present, it
  replaces the V1 council's narrative sections on the reader page (the decision recorded
  under 18.7); Playwright `professional-research-report.spec.ts`.

### V3.18.10 — Ask the corpus a query, grade a dimension on what names it

Run 4's report was the first that was *about the company*, and reading it exposed three
defects that no test could have found, because each needs a real corpus:

1. **The corpus was asked in prose.** `_corpus_arguments` sent `question.text` — a
   twenty-word analyst question — as the lexical query. The index uses PostgreSQL's
   `simple` configuration, which has **no stopword list**, and the backend ORs the
   query's lexemes, so `which`/`does`/`the`/`company` decided the ranking. Measured on
   SCCO's 10-K in production (939 indexed chunks, 401 of them tables): the question
   "Which commodities … what share of revenue …" returned six paragraphs of general
   narrative and the run recorded *"No revenue or profit figures by product, segment or
   geography appear anywhere in the evidence"* — about a corpus that holds *"Net sales
   in 2025 reached a record high of $13,420.0 million"*. The same corpus, asked
   `net sales product revenue share`, returns that passage in the top ranks.
   * `app/services/corpus/query_terms.py` — `keyword_query`, a pure reduction to
     distinctive terms. Curated against this corpus, not copied: `mine`, `value`,
     `level`, `state`, `list` and `reportable` are **not** stopwords here.
   * The query is now the question's own **first search intent** (the playbook already
     wrote one; the ladder simply never reached it), and the corpus rung continues from
     the next, so a question asks three different things instead of one prose query.
   * `top_k` 6 → 8: the passage carrying the year's headline revenue ranked **seventh**
     for the query that asked for it.
2. **A thesis dimension was graded on findings that were not about it.**
   "semiconductor supply chains" came back `evidenced` from a finding about the filing's
   exhibit index, and "What would change the thesis" then reported that no dimension was
   unestablished. `_dimension_view` now grades a dimension only on findings whose
   statement **names** it, by the same declared vocabulary that read the dimensions out
   of the thesis. Findings that do not name it are still shown, still citable, and
   counted in a note.
3. **Every finding built on the subject's own statements carried no period.**
   `get_sec_statements` stamps `"period": "FY2025"` on each line; `_harvest` read
   `period_key` and nothing else, so FY2025 revenue, both margins, cash conversion and
   the valuation inputs all reached the report with an empty period. `_period_key_of`
   reads the alias, shape-checked so prose never becomes a period key.
4. **A spacer grid outranked the paragraph with the figure.** An HTML `colspan` expands
   one header cell into N identical cells and a layout table is mostly zero-width
   spaces; `ts_rank_cd` counts every repeat, so such a grid took the top rank for three
   of seven questions. `_row_text` drops empty cells and collapses consecutive repeats.
   Forward-only: it applies to documents extracted after it ships.

## Human-gated steps (the only planned stops)
1. Applying migration 041 to the production database (`az webapp ssh`, per
   `docs/DEPLOYMENT.md`) — the agent has no database access by design.
   **Sequenced to be safe and to cost one stop:** 041 carries *every* V3.18 schema
   change and ships in a PR of its own with **no ORM change**, so deploying it is inert.
   It is applied while the code that needs it is still being written (V2/V3 code on a
   newer additive schema is fine; ORM columns on an older schema are not), and only then
   do the slices that map the new columns merge.
2. Any new app setting whose value is a secret. None is planned: every new source is
   keyless.
