## Slice detail

### V3.18.1 — Research correctness guards
* `sec_fundamentals_normalizer`: a statement metric whose own period end differs from the
  headline period is **missing for that period** (value withheld, warning recorded, the
  stale period named). Derived ratios compute only from same-period inputs. The spread
  warning covers every statement metric.
* `snapshot_builder._val` / `final_report_generator._sec_dp`: each slot carries its **own**
  period, never the headline's.
* New `services/statement_consistency.py`: relationship checks with declared exceptions;
  inconsistent facts are flagged, derived metrics withheld, the conflict surfaced.
* `CalculationDefinition`: `numerator`, `denominator`, `directionality`,
  `interpretation`; new `cash_conversion`, `capex_to_ocf`, `fcf_margin`,
  `dividend_cover`. Evidence pack carries definition + interpretation beside each derived
  value; a guard moves self-computed ratios to `unsupported_claims`.
* Gap `knowledge_state` vocabulary; `_known_gaps` labelled; absence-claim guard.
* Tests: fixture cut from the real SCCO companyfacts payload; mutation tests for the
  period guard, the consistency check, the definition guard and the gap guard.
* No migration.

#### V3.18.1 as built

| Control | Where | What it refuses |
|---|---|---|
| Own-period rule | `sec_fundamentals_normalizer._metrics_outside_reporting_period` | A statement line whose period end is not the bundle's reporting period (`stale_period`), or a 10-Q value inside an annual bundle (`interim_in_annual_bundle`). Withheld to `withheld_fields` with its real period; absent from every ratio. |
| No legacy backfill | `sec_edgar_fundamentals.merge_fundamentals` | The period-blind parser handing back a figure the normalizer just refused. |
| Slot fails closed | `final_report_generator._sec_dp` + `snapshot_builder.field_period_ends` | Any figure reaching a report slot with an own period ≠ the reporting period, from any upstream path. |
| Statement consistency | `services/statement_consistency.py` | `contradiction` (gross profit > revenue, cash > assets, unbalanced sheet, conflicting duplicates) and `implausible` (operating income > gross profit). Ratios on a failed pair are withheld; neither figure is chosen. |
| Metric semantics | `calculations/definitions.py` | A definition without `directionality` and an `interpretation` rule cannot be constructed. New: `cash_conversion` (OCF / NI), `capex_to_ocf`, `fcf_margin`, `dividend_cover_by_fcf`. |
| Defined metrics in the pack | `calculations/statement_metrics.py`, `llm/evidence_pack._add_defined_metrics` | — (producer). Runs the **same engine**; delivers value + formula + direction + reading in one line; budgeted with the statements so it survives. |
| Self-computed ratio guard | `llm/ratio_guard.py` via `citation_checker` | A percentage no evidence item rounds to → `unsupported_claims`. |
| Whose gap is it | `services/knowledge_state.py` via `citation_checker`; `EvidencePack.known_gaps_meaning`; `RESEARCH_DISCIPLINE_RULES` | An uncited absence published as a business risk; an unevidenced "the company does not disclose …". |

**Found by the rule, not by the brief:** the same live report's *total debt 7,250.5* was
also wrong. It added a current-debt balance from the **prior** year-end (499.8 at
2024-12-31 — the comparative column of the FY2025 10-K, which carries the newest filing
year) to FY2025 long-term debt (6,750.7). Ranking on filing year reads last year's
balance as this year's; the own-period rule withholds it.

**Also new:** `dividends_paid` is read from the cash-flow statement
(`PaymentsOfDividendsCommonStock` …), so "no dividend information is available" stops
being said about filers that print it on the face of their statements.

No migration. No new setting.

#### V3.18.2 as built

* **Graph.** `PlaybookQuestion` / `PlannedQuestion` carry `domain`, `why_it_matters`,
  `owner_role`, `depends_on`, `evidence_contract`, `search_intents`, `series_labels`.
  `playbooks.schema.planned_from` is the ONE producer, so no field can be dropped on the
  way to the planner again (S4 — `required_calculations` had been).
* **Base research model** (`director/base_model.py`): 18 questions across 14 domains
  (thesis fit is added only when a thesis exists), replacing a five-question baseline
  that was four-fifths financial statements. `identity` retired (no citable tool).
* **Roles.** `industry_analyst` added; business / risk / event / competitive roles
  re-scoped to distinct missions; `acquisition_tools` kept apart from `tools` so a
  ladder tool never changes which questions a role is ASSIGNED.
* **Planning.** The owner answers its question (least-loaded only as fallback);
  dependants after parents; a re-asked base question gets its whole definition back.
* **Contracts** (`director/contracts.py`) judged by the LOOP over what the tools returned,
  recorded per question with the missing dimension named; `unresolved_reason` from a
  closed vocabulary at run end; findings carry `domain`, `topic_key`, `source_kinds`;
  gaps carry `knowledge_state`.
* **S5.** A refused Council withholds the synthesis, not the research: findings come
  from the ledger, marked `council_convened: false`.
* **Payload.** `v3_research.question_graph`.
* **Schema readiness.** The pipeline checks the 041 columns before writing and degrades
  with a named reason if they are absent; `GET /api/v1/company-research/schema-readiness`
  answers the same question over HTTP.

### V3.18.3 — Active Evidence Acquisition
* Per-question ladder with contract re-evaluation between rungs; deterministic search
  intents; follow-ups advance to the next intent; external role eligible for any question
  whose ladder reaches rung 3.
* `verify_lead`: metric-proximity match, stored excerpt, unit/currency carried;
  previously verified leads re-citable.
* `ResearchBudget.check` wired: searches, fetches, documents, wall clock, no-improvement.
* 8-K EX-99.1 exhibits eligible for ingestion (bounded).

#### V3.18.3 as built

* **Ladder** (`LLMInvestigator._acquire`): platform tools → corpus by the question's
  search intents → one external search, taken only when the contract is unmet AND allows
  the web AND the role holds the ladder AND the run budget remains AND the question's
  own cap is not reached. Every step is logged with `why` (the missing contract
  dimensions) and `stopped` (the reason it stopped) — persisted on the question.
* **Follow-ups** start where the last round ended: no platform rung, the NEXT intent. A
  question answered with an unmet contract is re-asked while its ladder has a rung left
  (`loop._improvable`); a question whose contract forbids the web is not.
* **Budget.** `ExternalSearchBudget(limit=ModeLimits.max_web_searches)` shared by every
  task — the first enforcement of a ceiling that was declared and never checked.
* **Verification, tightened.** A numeric claim verifies only when its value sits within
  320 characters of two of the claim's distinctive words (unit words and generic terms
  excluded); "250 pages" no longer verifies "250 thousand tons". Prose claims verify
  against a document PASSAGE (≥70% of distinctive words, negations respected in both
  directions), and the evidence is that passage, verbatim, in the document's own case.
* **Re-citation.** A claim this platform verified earlier for the same company is cited
  again (same evidence id, no fetch, no duplicate row) instead of being rejected as a
  duplicate — re-runs no longer lose their external evidence.
* **Publisher tiers** (`sources/publisher_tiers.py`): filings T1, specialist agencies
  (USGS, IEA, study groups, exchanges) T3, governments T2, quality media T4, unknown T5.
  An issuer's own domain is never guessed.
* **What the writer sees**: the source excerpt first; the provider's sentence labelled
  `provider_claim_not_verified_wording`. The prompt carries the role's mission and the
  question's reason, and forbids restating another domain's figures.
* Provider prompt asks for `metric` and `geography`; both travel with the lead
  (migration 041 columns) as claim metadata, never as verified facts.

## Human-gated steps (the only planned stops)
1. Applying migration 041 to the production database (`az webapp ssh`, per
   `docs/DEPLOYMENT.md`) — the agent has no database access by design.
   **Sequenced to be safe and to cost one stop:** 041 carries *every* V3.18 schema
   change and ships in a PR of its own with **no ORM change**, so deploying it is inert.
   It is applied while the code that needs it is still being written (V2/V3 code on a
   newer additive schema is fine; ORM columns on an older schema are not), and only then
   do the slices that map the new columns merge.
2. Any new app setting whose value is a secret. None is planned: every new source is
   keyless.
