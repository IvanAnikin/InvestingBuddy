# V3.1 Slice 1.1 — Raw artifact store

**Branch:** `feature/v3-1-1-raw-artifact-store` → `develop/v3`
**Status:** `IMPLEMENTED`
**Migration:** 021 (created; **not applied to any deployed environment**)

## Objective

Persist the raw bytes of every retrieved document, addressed by their own
SHA-256, behind an InvestingBuddy-owned storage interface — and make
`ExtractedDocument.blob_path` a real retrieval path for the first time since it
was created.

## Why now

It is the only V3.1 slice with no open decision in front of it, and it is the
prerequisite for everything else in the phase. Re-extraction (Slice 1.7) is
impossible without the original bytes; the full parsed representation (Slice 1.3)
is a derivation *of* something, and today that something is thrown away.

The repository's own history is the argument. `CURRENT_EXTRACTION_PIPELINE_VERSION`
is at **15**. Versions 9-15 each changed how already-fetched text is read, and
several of them — the two-column PDF layout fix, the geometric five-year table
reconstructor, the gutter-threshold recalibration, the extraction wall-budget
increase — could only be applied by re-fetching documents from issuer sites that
may no longer serve them. `EXTRACTION_TEXT_LAYER_MIN_VERSION = 11` exists
precisely because a document below it "must undergo a full re-extraction (never
an excerpts-only replay)". That re-extraction currently means a network fetch.

policy value that decides whether bytes may be kept at all, one lineage table,

## Provider dependency

None at runtime. `azure-storage-blob` is a new **optional** extra (`.[blob]`),
deliberately not in `dev`: the adapter takes an injected client factory, its tests

## Feature flags

`v3_corpus_enabled` (default `False`) is the master gate: with it off, nothing in
`app.services.corpus` issues a query, writes a row or stores a byte.

`v3_artifact_store_backend` defaults to `none` **even when the corpus is on**, so
enabling the corpus does not by itself start writing bytes anywhere — retention is
a second, deliberate decision. Also `v3_artifact_store_local_root`,
`v3_artifact_store_account_url`, `v3_artifact_store_container`,
`v3_artifact_max_bytes`, `v3_artifact_retention_days`.

**Deprecation plan:** `v3_corpus_enabled` is removed once the corpus is validated
in live use and the V2 excerpt-only path is retired (V3.1 phase gate at the
earliest, realistically after V3.3 consumes the corpus). It exists to make the
migration safe, not to be permanent.

## Security considerations

- **No secret can reach a key or a log.** The key scheme is
  `sha256/<aa>/<bb>/<digest>.<ext>` — pure hex plus a closed extension map. No
  URL, ticker, issuer name, company id or date appears in it, so a storage listing
  discloses nothing about what is being researched and no credential-bearing URL
  fragment can leak into a path. Asserted by test.
- **A hostile `Content-Type` cannot choose a filename suffix.** The extension
  comes from a closed map; anything unrecognised is `.bin`.
- **Path traversal is unreachable twice over.** Keys are generated, never
  caller-supplied, and the local backend still validates against the closed
  pattern and re-checks that the resolved path is inside the root — the same
  belt-and-braces reasoning as the IP-literal check behind `safe_web_fetcher`'s
  host allowlist.
- **No connection string, anywhere.** A connection string is a key. The Azure
  adapter takes an account URL and `DefaultAzureCredential`; there is deliberately
  no setting to put one in, asserted by test.
- **Policy decides retention, not the code path.** `licensed_private` and any
  unrecognised access class deny by default. A document that may not be retained
  keeps its lineage and loses its bytes.
- **Nothing is logged.** No module in this slice logs a key, a byte or a path.

## Unit tests

`tests/test_v3_raw_artifact_store.py` — **91 tests**, no network, no clock
dependence (every expiry test passes an explicit `now`). The three backends are
exercised as *real* implementations through a parametrised contract fixture, not
as mocks.

Covers: key determinism, opacity and fan-out · closed extension map · refusal of a
non-SHA-256 identity · traversal-shaped keys · put/get/exists/delete contract ·
deduplication · exactly-one-of-created/deduplicated · concurrent puts producing one
artifact · size ceiling enforced before any write · conflict on a truncated prior
write · no partial file survives · Azure adapter round-trip against a fake client ·
conditional write (`overwrite=False`) · client always closed · AST assertion that
no corpus module outside `azure_blob.py` imports an Azure SDK · the full governance
permission table · `derived` inheriting the most restrictive input · store
resolution from configuration · policy refusal keeping lineage · store failure
degrading to a named failure code · retention sweep dry-run and delete · an AST/text
assertion that **nothing in the codebase schedules a sweep** · `blob_path` wiring
with the corpus on and off · fetch-path integration for both legs.

## Acceptance criteria

1. **The same document stored twice produces one artifact, one key and one row.**
   ✅ `TestBackendContract::test_the_same_document_twice_deduplicates`,
   `TestLineagePersistence::test_one_row_per_distinct_document` (`seen_count == 3`
   after three ingestions), and the database's own UNIQUE constraint.
2. **An artifact is never overwritten with different bytes.** ✅ Different bytes
   are a different key by construction; a same-digest disagreement raises
   `ArtifactConflictError` on all three backends
   (`test_a_truncated_prior_write_is_a_conflict_not_an_overwrite`,
   `test_a_disagreeing_existing_blob_fails_closed`).
3. **`blob_path` is a real retrieval path.** ✅
   `TestBlobPathWiring::test_ingestion_persists_the_storage_key_on_the_document`
   persists a document, asserts `blob_path` is a valid artifact key, and reads the
   original bytes back through it.
4. **The research domain does not import a vendor SDK.** ✅
   `test_no_domain_module_imports_an_azure_sdk` parses every module under
   `app/services/corpus` and asserts only `azure_blob.py` may reference Azure —
   and `test_the_adapter_never_imports_the_sdk_at_module_scope` asserts even that
   one imports lazily.
5. **No V2 regression.** ✅ full suite 4647 → **4738 passed**, 12 skipped; `ruff`
   clean; `mypy app` 71 on both `develop/v3` and this branch (unchanged, same
   scope). With `V3_CORPUS_ENABLED` off, `blob_path` stays NULL and no
   `research_artifacts` row is written — asserted by test.

## Non-goals

- The document/version records (Slice 1.2).
- Full parsed text, pages, sections, tables (Slice 1.3).
- Any search (Slices 1.4-1.6).
- Actually re-extracting anything (Slice 1.7).
- Deciding the retention TTL — OPEN DECISION #12 is the user's. What ships is the
  primitive and a safe default of "no TTL configured".
- Scheduling the expiry sweep. Deliberately absent, and a test keeps it absent.

## Rollback

`git revert` the merge commit on `develop/v3`, then `alembic downgrade 020` if 021
was ever applied anywhere. Stored bytes are orphaned but harmless — they are
content-addressed, so a later re-enable finds them again rather than duplicating
them.

## Dependencies

None. Slices 1.2, 1.3 and 1.7 depend on this.
