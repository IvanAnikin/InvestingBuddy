# V3.10 Slice 10.2 — real Investigator / Red Team / Responder / Chair

## Objective

Production-capable implementations behind the protocols V3.5 and V3.7 defined, with
configurable routing — and one guard that decides whether any of it means anything.

## Why now

The RC report names this as a critical gap: every agent protocol had a fake and no real
implementation, so the pipeline's *behaviour* was unmeasured.

## The guard that matters

> **A model may write prose about evidence the platform fetched. It may not supply
> evidence.**

The ledger's CHECK requires *an* evidence id, not a *real* one. Without this guard the
whole promotion path is decoration: a model that invents `ev:c:9f2a…` produces a finding
that satisfies every constraint and cites nothing.

So the flow is:

```
tools run first  ->  a set of REAL ids  ->  the model writes findings citing only those
                                       ->  any other id is a FABRICATION
```

A finding citing an unknown id is **discarded** and recorded as a gap **naming the
fabricated id**. A partly-fabricated citation discards the whole finding, because a
statement resting on one real id and one invented one is a statement whose support cannot
be trusted either.

The same guard applies three more times: the Red Team may only challenge a `finding_id` in
this run; the Responder's citations are filtered to what the run holds (which usually
leaves it with none, and therefore unresolved — the correct outcome); and a Chair key point
citing nothing in the run is dropped.

## Two more things the model is not allowed to do

- **Choose a tool argument.** An LLM composing a filter is an LLM composing a plausible
  answer about the wrong population. Every argument is derived from the question and the
  subject, both of which the platform owns.
- **Set the chair's label.** The five allowed labels are enforced **after** the reply, not
  requested in the prompt — the vocabulary being closed is a safety property and a prompt
  is a request. `"STRONG BUY"` becomes `insufficient_data`.

## Two things the platform will not let the Chair drop

- **Unresolved disagreements.** Taken from the ledger *before* the model is asked
  anything, so they cannot be dropped by omission — which would be exactly the silent
  selection the Chair rule forbids.
- **Open questions.** Sourced from the ledger, not invented by the chair. The live trap
  carried forward: the chair's own `primary_open_questions` degraded into machine-record
  noise on real data.

## Routing

[ADR-050](../../DECISIONS.md): cheap bulk research to DeepSeek, difficult synthesis to the
existing Azure OpenAI. Preference per slot, first that resolves wins, and a slot with
nothing configured resolves to `None` with a reason so the caller keeps its deterministic
path.

**`shares_vendor_with_chair` is reported, not hidden.** With no DeepSeek key every slot
resolves to Azure OpenAI, so the Red Team currently shares the Chair's vendor and therefore
its blind spots. That is a real limitation of this environment and stating it is the point.

A client is built **per slot** rather than shared: `LLMClient` accumulates usage on the
instance and pops it on `consume_usage`, so two slots sharing one would attribute one's
tokens to the other — and per-slot cost is the whole reason for measuring it.

## Live verification

Run against the real Azure OpenAI deployment (`gpt-4.1-mini`) during this slice:

```
chair    -> label=internal_research_candidate  setup=cautious
            deterministic_fallback=False  key_points=2  discarded_citations=0
red team -> 1 challenge, weakness_class=single_source, discarded_targets=0
```

Both are now opt-in tests gated on `ENABLE_INTEGRATION_TESTS=true` **as well as** a
credential — deliberately, so an ordinary local run does not spend on every invocation.

## Unit tests

34, none needing a network. The fabrication guard from four angles; the allowed ids stated
in the prompt; untrusted payloads fenced and declared data; the safety vocabulary present
in the instruction region; no model still running the tools and reporting an honest gap; a
model failure as a gap rather than a crash; the tool budget stopping a task and naming
itself; the model never choosing an argument. Red Team: unknown target discarded, invented
weakness class normalised, failure yielding nothing. Responder: invented citation leaving
it citing nothing. Chair: a forbidden label normalised, a bogus key point dropped,
unresolved conflict surviving omission, open questions from the ledger, deterministic
fallback on absence and on failure, and no reachable label being a recommendation.

## Acceptance criteria

1. A model cannot introduce an evidence id the platform did not mint. ✅ four guards.
2. Routing is configurable, degrades with a named reason, and reports when Red Team and
   Chair share a vendor. ✅
3. The real adapters work against a real provider. ✅ live-verified on Azure OpenAI.
