# V3.5 Slice 5.3 — the bounded investigation loop

## Objective

Turn a gap into a follow-up task, within limits that are enforced **before** the spend and
reported **by name** when they stop the run.

## Why now

This is the one structural limitation V3 exists to remove. V2's council receives a frozen
evidence pack and cannot go and look: it can report a gap beautifully and cannot close
one. 5.1 gave gaps a durable home and 5.2 produced a plan; this executes it.

## Current implementation

`company_research_service.execute_company_research` assembles evidence, runs the council
once, and returns. There is no round, no gap review and no follow-up.

## Proposed changes

`app/services/director/loop.py`: `run_investigation`, four `TaskOutcome` shapes, and a
closed stop-reason vocabulary.

### Every limit is checked before the work it would authorise

`max_rounds` · `max_tasks` · `max_tool_calls` · `max_wall_seconds`, all from `ModeLimits`
(4.11). A budget satisfied by noticing afterwards is a budget that was exceeded, and a
test asserts the investigator is **not called** for the task that would have breached the
cap.

### The run says which limit stopped it

`LOOP_STOP_REASONS` is closed at six and every member is either a limit or a completion
state — **there is no "other"**, because a run that stopped for an unnamed reason is one
nobody can widen a budget for. `ck_research_runs_stopped_names_a_limit` makes the
alternative unstorable.

### Completion is not "did the agents finish"

`is_complete_analysis` is True only when the work finished **and** the Council may
convene. A run whose agents all returned successfully but whose blocking question is
unanswered is not a complete analysis, and calling it one is the specific lie this
property exists to prevent.

An **unrecognised completion rule never declares success**. A rule the platform cannot
evaluate must not be able to complete a run by being ignored.

### A gap is not automatically a follow-up

Only a **closable** one. An unclosable gap — no source publishes the figure — would
consume a whole round to fail again, so it is *accepted*: the run finishes with it open
and says so. That is the difference between a bounded loop and a loop that happens to have
a counter.

A follow-up also reuses the plan's own assignment, so it goes to the specialist that
already holds the tools, and a question nobody could answer in round one is not
re-assigned in round two to fail identically.

### An unsupported statement becomes a gap, not a finding

An investigator that returns a statement with no evidence and no calculation has produced
a **claim**. The ledger refuses it, and the loop records *what was asserted and why it was
not accepted* rather than dropping it silently.

### Nothing investigates here

`Investigator` is a Protocol the caller supplies. The loop owns the control flow — rounds,
limits, gap review, termination reason — and nothing about how a specialist does its work,
which is what makes every guarantee above testable without a model, a network or a corpus.

## Security considerations

An agent that researches indefinitely is the security-relevant failure, and it is now
bounded in four dimensions, each checked before the spend. One role raising an exception
is caught, recorded as a failed task and does not end the run — so a hostile or broken
specialist cannot deny the rest of the investigation.

## Unit tests

Termination: the closed vocabulary refusing an invented reason; a run that answers
everything completing; each of the four limits stopping the loop and being named, with the
task budget asserted by the investigator **not being called**; a run with nothing left to
do stopping and accepting its unclosable gaps. Gaps: a closable gap becoming a second
round that closes it; an unclosable one buying no round at all. Findings: an unsupported
statement becoming a gap; a supported one persisted. Completion: an open blocking question
making `is_complete_analysis` False even though every agent returned; an unrecognised rule
never declaring success; a known rule honoured. Resilience: one role exploding not ending
the run; a partial task recorded with its reason; the result serialising what was still
open. Plus an end-to-end pass over the **Director's own plan**, not a hand-built one.

## Integration tests

None new. Every write goes through the ledger, whose schema guarantees were exercised
against real PostgreSQL in 5.1.

## Live issuer acceptance

Not performed. No investigator implementation exists yet that calls a model or a tool; the
loop's first real caller is a behaviour change on a live path and gets its own slice.

## Acceptance criteria

1. The loop terminates on a stated limit, and the limit is recorded on the run.
2. A gap becomes a follow-up task — and an unclosable gap does not.
3. A finding without evidence ids cannot be persisted; the attempt is recorded as a gap.

## Non-goals

- Implementing an investigator. The Protocol is the contract; a real one wires the V3.3
  tool surface to a model and is its own slice with its own live acceptance.
- Convening the Council. V3.7 consumes the ledger this produces.
- Parallel task execution. Sequential is bounded and debuggable; concurrency is an
  optimisation with its own failure modes and no evidence yet that it is needed.

## Rollback

Delete the module. Nothing imports it at runtime.
