## The original V3.16 plan was wrong, and the forensic is why

The slice opened on the assumption that `backfill_from_extracted_documents()` would make
Moderna's historical filings searchable. It would not, and it never could.

`backfill_from_extracted_documents` calls `upsert_document_version` **and stops**. It
creates corpus documents and versions and **zero** derivations, pages or chunks. Its own
docstring said nothing about that, so "N versions created" read as success.

`search_company_corpus` searches `research_document_chunks` and nothing else.

So a completed backfill can report documents created and leave every search returning
nought. That is the false success §3 of the brief told me to refuse, and I did not run it.

**Two independent breaks, not one.** The second was invisible until a real PostgreSQL
search ran against real rows:

| # | Break | Why it was invisible |
|---|---|---|
| 1 | No **chunks**. `persist_chunks` runs only when `build_parsed_document` returns non-`None`, which needs `extraction.blocks`. A cache hit rebuilt from bounded `excerpts_json` has none, and the backfill never parses at all. | A version row exists, so every "does the document exist?" check passed |
| 2 | No **index entries**. The lexical query filters `indexed_at IS NOT NULL`. Only `index_version` sets it, and its **only caller was `corpus/reprocessing.py`** — never the live ingestion path. | SQLite has no search backend, so no unit test could ever execute the query |

Break 2 means that even a *freshly fetched* filing produced chunks that were never
findable. That is the half that explains why the production MRNA run got `0 hits`.

There is also **no `excerpts_json` fallback** anywhere in `corpus/retrieval.py`,
`corpus/indexing.py` or the Postgres backend, despite migration 022's prose and
`ingest_extracted_document`'s docstring both claiming one. Both are corrected (§10).

## What was built

### `corpus/filing_evidence.py` — one definition of ready

A filing is corpus-search ready for a company when **all** hold:

1. a `ResearchDocumentVersion` for *that company* (joined through `ResearchDocument`,
   which is where `company_id` lives), `is_current`;
2. an `is_active` `ResearchDocumentDerivation`;
3. at least one `ResearchDocumentChunk`;
4. that chunk both `indexable` **and** carrying `indexed_at`.

Condition 4 is two conditions because the corpus has two failure modes. `indexable` is a
governance permission stamped at write time; `indexed_at` is index state. A chunk with
permission and no index entry is returned by nothing.

`filing_evidence_state()` classifies into the brief's states A/B/C without touching the
network — answerable from the accession alone, which is what makes a repeat run free.

### `ensure_filing_corpus_evidence()` — the bridge

Two outcomes and no third: the backend can return content for this filing afterwards, or
the result carries a structured reason. **It re-reads readiness rather than believing the
acquirer** — which is what caught the dedup collision below.

It takes a company, CIK, accession and form. **It takes no URL.** A model can influence
*which of the issuer's own filings* is fetched; it cannot influence *what host or path*,
because it never supplies one. A non-18-digit accession is refused before any URL could
be constructed.

### `corpus/filing_acquisition.py` — a caller, not a downloader

Reuses `live_sec_primary_document_extractor` (which reuses `sec_filing_documents`'
allowlist, SSRF-safe fetcher, traversal guard, byte cap, timeout and SEC rate limiter),
then `persist_primary_document_artifacts`, **then `index_version`** — the call the live
path never made.

Bounded: `max_documents=1` per accession, a 45s wall-budget, and the existing
`PRIMARY_DOCUMENT_SEC_BODY_ENABLED` flag. No new budget framework.

### Integration (§6) — pattern B, deterministic after discovery

`get_recent_filings` keeps its contract exactly: metadata, no prose. The platform then
runs the bridge and adds one field per item, `corpus_ready`, plus a `corpus` summary block.
A specialist can now tell *"the filing says nothing about this"* from *"this filing was
never read"* — a distinction it previously could not make.

Acquisition is capped by `V3_FILING_BODY_BRIDGE_MAX_DOCUMENTS` (default **3**). A filing
already held costs no budget, so a repeat run does not starve itself.

### New flags (both default **off**)

| Flag | Meaning |
|---|---|
| `V3_FILING_BODY_BRIDGE_ENABLED` | may the platform acquire filing **bodies** |
| `V3_FILING_BODY_BRIDGE_MAX_DOCUMENTS` | how many bodies one discovery call may acquire (3) |

Separate from `V3_FILINGS_TOOL_ENABLED` on purpose: enabling metadata discovery must not
silently start fetching bodies.

## Review findings (§17)

Twelve of the fourteen attack items are covered by the tests above. Two are worth stating
outright.

### 1. V2 document dedup is not company-scoped — REPORTED, not fixed

`_get_or_create_document` dedups `extracted_documents` on `content_hash` **alone**
(`extracted_document_service.py:300-304`). When two companies' documents are
byte-identical, the second company reuses the first's row and the corpus version stays
attributed to the first. The second company then has no searchable filing of its own.

Found by the bridge itself: the acquirer returned
`acquired=True, documents created=0 reused=1 corpus versions=0`, and the bridge's
verify-after-acquire step correctly answered `unavailable` instead of `ready`.

**Not fixed here** because the fix changes V2 document *identity*, which changes dedup for
every company and every document ever written and needs its own acceptance. V3.16's scope
is the corpus bridge. Shipping is safe because the bridge refuses to claim success it
cannot verify; `TestKnownLimitationV2DocumentDedupIsNotCompanyScoped` pins exactly that,
so whoever changes the dedup key learns what else moves.

Real-world likelihood for SEC filings is low (two issuers' filing bodies are not
byte-identical), but it is not zero for co-filed documents.

### 2. The suite could reach the SEC by accident — FIXED

`ensure_filing_corpus_evidence` falls back to the real acquirer when none is injected, and
one unit test duly fetched from www.sec.gov. `tests/conftest.py` now carries an autouse
guard making acquisition inert, plus a `real_acquire_sec_filing` fixture for the tests
that genuinely mean to exercise it.
