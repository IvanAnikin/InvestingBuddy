# V3.4 Slice 4.11 — research-depth presets with real ceilings

## Objective

Implement [ADR-052](../../DECISIONS.md). QUICK / STANDARD / DEEP / MAX become depth
presets carrying **finite technical ceilings**, and the one ceiling that stays unset is
the monetary one.

## Why now

This is a **corrective**, not a new capability. ADR-052 was accepted on 2026-09-05 and
never implemented: `ResearchBudget` still defaulted every limit to `UNBOUNDED` with a
docstring citing two decisions that had already been taken, while
[CAMPAIGN_STATE.md](../CAMPAIGN_STATE.md) asserted "the technical ceilings are now real
numbers". Code and docs had diverged, which CLAUDE.md rule 2 forbids — and the direction
of the divergence is the dangerous one: the record claimed a safety property the system
did not have.

It matters more now than when the ADR was written. Slice 4.3 shipped adapters that can
issue web searches and call an external model, and 4.9 gave the platform something to
search. An unbounded budget on that system is a runaway waiting for an occasion.

## Current implementation

- `app/services/consumption.py:300-380` — `ResearchBudget`, `UNBOUNDED`, `check()`,
  `BudgetExceeded`. The enforcement mechanism, complete and correct; only the numbers
  were missing.
- `app/core/config.py` — `v3_run_max_*`, all defaulting to `0`.

## Proposed changes

`app/services/research_mode.py`: the `ResearchMode` enum, a `ModeLimits` record whose
constructor **refuses a non-positive ceiling**, the four presets, and `budget_for()`.

Three rules the module encodes:

1. **MAX is the highest and is still finite.** An unbounded ceiling is not a generous
   one, it is an absent one.
2. **Configuration narrows, never widens.** `V3_RUN_MAX_*` is the operator's hard cap;
   `0` means "no opinion", and any other value takes effect only when it is *smaller*
   than the mode's. A mode cannot widen a ceiling somebody deliberately narrowed.
3. **`max_external_cost_usd` is set by no mode.** Money is derived from a price book
   nobody has filled in, so a monetary ceiling would be a limit in a unit the platform
   cannot currently measure — it would stop nothing while looking like a control.

## New modules

`app/services/research_mode.py`, `tests/test_v3_research_mode_budgets.py`.

## Existing modules reused

`consumption.ResearchBudget` / `UNBOUNDED` / `BudgetExceeded` — unchanged. Its stale
docstring is corrected: it keeps permissive defaults because it is the *mechanism*, and a
mechanism that could not represent "no limit on this dimension" could not express the one
limit the decision deliberately left open.

## Security considerations

A runaway loop is the security-relevant failure here, and it is now bounded in seven
dimensions rather than none. An unrecognised mode name resolves to **STANDARD**, never to
MAX — a typo must not buy the deepest run available.

## Unit tests

Every limit of every mode is finite and positive; the modes are ordered by depth; MAX
dominates all of them and is still finite; a zero ceiling cannot be declared; an unknown
name runs STANDARD; configuration narrows and does not widen; the monetary ceiling is the
only unset one; and the budget **actually stops a run**, raising before the spend rather
than noticing after it.

One of those is an invariant rather than a preference: a QUICK run's wall ceiling must
stay under the deployed gunicorn `--timeout` of 300s. A run the platform promises to
finish and the process kills is the defect that cost six live outages.

## Integration tests

None. No I/O, no database, no provider.

## Acceptance criteria

1. Every ceiling of every mode is a positive finite number, and MAX is the deepest.
2. `V3_RUN_MAX_*` narrows a mode and can never widen one.
3. `max_external_cost_usd` is unset by every mode and settable by an operator.

## Non-goals

- Choosing a monetary budget. Explicitly out of scope (ADR-052).
- Wiring a mode into any entry point. The loop that consumes `max_rounds` and
  `max_tasks` is V3.5; this slice makes the numbers exist and be enforceable.
- Tuning. The numbers are estimates against measured anchors — a full company run at
  261-451s, ingestion ~154s, a council 145-190s — and are expected to be tightened once
  real DeepSeek runs are measured. **A default that is wrong but finite is recoverable;
  an unbounded default is not.**

## Rollback

Nothing consumes the module yet; deleting it restores the previous behaviour exactly.

## Dependencies

V3.0.5 (`ResearchBudget`), ADR-052.
