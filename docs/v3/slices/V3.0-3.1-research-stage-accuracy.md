# V3.0 Slice 3.1 — Research-stage accuracy

**Branch:** `feature/v3-0-3-1-research-stage-accuracy` → `develop/v3`
**Status:** `IMPLEMENTED`
**Migration:** none

## Objective

Make the stage a reader is shown the stage that is actually running.

## The defect, in two parts

### 1. The map put the wrong nodes in the wrong stages

Eleven of the twenty mapped graph nodes were `evidence_validation`, including
the five deterministic analysis-council agents (`bull_case_agent`,
`bear_case_agent`, `risk_agent`, `valuation_guard_agent`,
`investment_committee_chair`) and the two that write and log the draft
(`save_draft_report`, `log_agent_steps`). A run reported "Validating and citing
the evidence" while it was forming and challenging an investment view.

### 2. The stage naming the longest part of a run pointed at a node that had already finished

`build_company_snapshot` was mapped to `primary_document_ingestion`. **No issuer
document is read anywhere in that graph.** Deep primary-document ingestion happens
inside `llm.council.maybe_run_council` (`council.py:1597`
`collect_company_source_evidence`), which runs *after* the graph, inside the
final-report generator.

Measured on live data, that one call is ~154s of ingestion plus ~145-190s of
council, against a 261-451s whole-run envelope — the clear majority of a run.
Throughout it the reader was shown the last graph node's stage, and both stages
were then stamped `completed` retroactively on the way out
(`company_research_service.py`), claiming they had happened at a time they had
not.

Naming the stage in flight is the entire value of a stage display. Naming the
wrong one is worse than naming none.

## Changes

**`app/services/research_job.py`**

- `NODE_TO_STAGE` corrected: the council agents, catalyst discovery and scoring
  move to `council_analysis`; the draft-writing nodes move to
  `final_report_assembly`; `build_company_snapshot` moves to
  `financial_extraction`, which is what it does — it assembles a snapshot from
  data already fetched.
- New `PHASE_*` constants and `PHASE_TO_STAGE` / `stage_for_phase` for the
  post-graph phases, which the graph structurally cannot report because it is no
  longer executing.

**`app/services/llm/council.py`** — reports `PHASE_EVIDENCE_INGESTION` before the
evidence collection and `PHASE_COUNCIL_AGENTS` before the agents run.

**`app/services/final_report_generator.py`** — threads the callback through
`generate_from_workflow_state` → `_generate_and_save` → `maybe_run_council`, and
reports `PHASE_REPORT_ASSEMBLY` once the council returns.

**`app/services/company_research_service.py`** — one `advance(stage)` function
now serves both progress sources, `on_stage` is threaded into
`execute_company_research`, and the retroactive stamping is gone.

## Design decisions worth stating

### The producer names the phase; `research_job` decides the words

Exactly the separation the graph's node names already have: the council says
`"council_agents"`, and `research_job` decides that a reader is told "Running the
research council". That is why `council.py` imports no UI string, asserted by
`test_the_council_does_not_import_a_ui_string`.

### Progress reporting can never fail a research run

Both `_report_phase` helpers swallow. A stage display is a convenience; the
report is the product, and a callback that raises — a closed session, a lapsed
lease — must not discard the minutes of ingestion that just completed.

### A run without a council no longer claims one ran

The honest consequence of removing the retroactive stamping. When the council is
off or no provider resolves, `council_analysis` never completes, because it never
happened. Under the old code every run claimed it had.

### The callback is passed only when a caller wants progress

Following the existing `on_node` precedent. A caller that wants no progress must
not force every injected fake in a 4,500-test suite to grow a parameter it never
uses — pinned by `test_no_phase_callback_is_passed_when_nobody_wants_progress`.

## DB migration

**No.**

## Feature flags

**None, deliberately.** This is a correctness fix to a reader-facing statement
that was wrong on both the V2 and V3 paths. Putting a truer status behind a flag
would mean choosing to keep showing the false one.

## Security considerations

None new. Stage names are a closed vocabulary defined in `research_job`; no
provider text, no URL and no identifier enters a stage label.

## Tests

`tests/test_v3_research_stage_accuracy.py` — **19 tests**: the map matches the
work · every mapped node exists in the graph (a map entry for a node that does
not exist is a silent dead letter) · every mapped stage is a real stage · an
unmapped node moves nothing · the council's two phase call sites sit *before* the
operations they describe · the council imports no UI string · a raising callback
cannot fail the council or the generator · no retroactive stamping remains · one
`advance` serves both sources · and an end-to-end assertion that the phases are
observed **in order, as they happen**.

One existing test changed: `test_stages_progress_through_the_workflows_own_nodes`
asserted `primary_document_ingestion` was reached by running
`build_company_snapshot`. It asserted the defect. Its fake generator now reports
phases the way the real one does, so it exercises the reporting rather than the
stamping.

## Live issuer acceptance

**Not performed** — V3 is not deployed. What the offline suite cannot prove is
the wall-clock share of each phase on a real issuer; the ~154s / ~145-190s
figures are carried from previously measured live runs, not from this branch.

## Acceptance criteria

1. **No graph node claims document ingestion.** ✅
   `test_no_graph_node_claims_document_ingestion` — the graph reads no issuer
   document, so no node may say it does.
2. **The council and ingestion report themselves while they run.** ✅
   `test_the_council_emits_ingestion_and_agent_phases` pins both call sites
   *before* the operations they describe; the end-to-end test asserts the order.
3. **No stage is claimed retroactively.** ✅ `TestNoRetroactiveStamping`.
4. **No V2 regression.** ✅ suite 4551 → 4570 (+19, none lost); `ruff` clean;
   `mypy app` 71, unchanged.

## Non-goals

- A percentage. The pipeline cannot know how long a node takes, and "62%
  complete" would be a fabrication — the existing rule, unchanged.
- Stage reporting for the other five `BackgroundTasks` entry points.

## Rollback

`git revert` the merge commit. No migration, no flag, no schema.

## Dependencies

None strictly; lands after Slice 3 so the corrected stages flow through the
durable path's heartbeat as well as the V2 envelope.
