# V3.4 Slice 4.8 — transcripts and IR events from free public sources

## Objective

The canonical transcript and IR-event model [ADR-051](../../DECISIONS.md) asks for, with
the absence of a transcript as a **first-class state**, plus `get_ir_events` and
`get_transcripts`.

## Why now

Management language over time is one of the most valuable inputs V3 planned to add, and
the two obvious vendors are paid subscriptions. The decision was: no subscription, build
the model anyway, acquire from free public issuer sources, and **missing means missing**.

Implementing the model without a vendor is the point. It means a future subscription is an
adapter rather than a schema change, and it means the free path is the **default** rather
than the fallback — the ordering that survives the subscription never being bought.

## Current implementation

Nothing. Transcripts are not represented anywhere at `4b60e07`; `TOOL_GET_IR_EVENTS` and
`TOOL_GET_TRANSCRIPTS` are reserved names with no implementation.

## Proposed changes

Two tables, a service, two tools.

### The distinction the whole slice exists for

Three states a naive schema collapses into one empty result:

| State | How it is represented | What it means to a reader |
|---|---|---|
| The issuer published a transcript | `availability = 'available'` (+ a version id once ingested) | Read it. |
| The issuer published **none** | `availability = 'not_published'` | **A research gap.** A human can close it by other means. |
| Nobody looked | **no row at all** | A task, not a gap. |

Without the middle row, *"CFR published no FY2025 transcript"* and *"CFR held no call"*
are the same absence — and the second is a far stranger fact about a listed company.

Coverage will be uneven and worst exactly where the existing pipeline is already thinnest:
European issuers who publish a presentation but not a transcript. A test covers precisely
that shape.

### The period is the issuer's

`fiscal_period_key` is a `financial_period.ReportingPeriod` key, because an earnings call
is *about* a reporting period and Richemont's FY2025 ends in March. This is the one place
in V3.4 where the financial vocabulary is right and slice 4.7's macro one would be wrong.

### Identity is derived and over-splits

`event_key` comes from the issuer, the event type and the period, so an IR calendar entry
in January and a results release in May converge on one row. With neither a period nor a
date it over-splits — splitting produces a duplicate a reader can merge; merging
attributes one call's transcript to another call.

An `occurred` event is **never demoted**: a later calendar scrape that still calls it
"upcoming" must not un-happen a call the platform saw occur.

## Security considerations

- A transcript is issuer-published text from outside the platform, so
  `get_transcripts` declares `may_contain_untrusted_content = True` and a prompt builder
  fences it. `get_ir_events` returns only structured metadata and declares `False`.
- A paywalled transcript is recorded as `paywalled` and **never scraped** (ADR-051).
- Acquisition itself makes no network call in this slice; when it lands it will go
  through the bounded issuer traversal of slice 4.10 and the existing guarded fetcher.

## Unit tests

Identity convergence and deliberate over-splitting; promotion without demotion; the four
transcript states and which two are research gaps; an `available` material with no
location refused in Python **and** in SQL; a corpus document refused on a `not_published`
row; re-checking updating rather than duplicating; the European presentation-without-
transcript shape; both tools registered; the untrusted-content declaration; the transcript
tool defaulting to event types that produce speech; and the period filter bounding the
population the caller asked for.

## Integration tests

Migration 034 against **real PostgreSQL 16**: eight statements, including that an
`announced` event cannot carry an occurrence time, `available` with no location is
unstorable, `not_published` **is** storable, a presentation and a missing transcript
coexist, two rows for one material type conflict, and deleting an event takes its
materials — a material whose event is gone has nothing to be a material *of*.

## Live issuer acceptance

Not performed. No acquisition path is wired in this slice; see Non-goals.

## Acceptance criteria

1. "The issuer published no transcript" is a stored row that reads as a research gap, and
   "nobody looked" is an absent row that does not.
2. A transcript cannot be recorded as available without saying where it is, and a corpus
   document cannot hang off an absence — both enforced by the database, not only by the
   service.
3. `get_transcripts` returns a **state** per event, never an empty list standing for two
   different facts.

## Non-goals

- **Acquisition.** Discovering events and materials on an issuer's IR site needs the
  bounded same-domain traversal of slice 4.10. This slice is the destination; 4.10 is the
  path to it. Wiring them is one small slice once both exist.
- Any paid transcript vendor. Explicitly excluded (ADR-051).
- Speaker segmentation, Q&A splitting or diarisation. A transcript enters the corpus as a
  document; structure over it is later work with its own acceptance criteria.
- Scheduling. Nothing refreshes an availability on a timer.

## Rollback

Migration 034 downgrades cleanly — verified against real PostgreSQL. The two tools are
additive; unregistering them restores the previous tool surface exactly.

## Dependencies

V3.1.2 (corpus versions, for an ingested transcript), V3.3.1 (the tool contracts),
ADR-051.
