# V3.10 Slice 10.1 — DeepSeek live contract validation

## Status: **BLOCKED ON CREDENTIAL**

No `DEEPSEEK_API_KEY` is configured in this environment. **DeepSeek's wire contract
remains UNVERIFIED**, and this slice records that rather than working around it.

What shipped is the opt-in live contract test that answers the eight questions the moment
a key exists — plus a real defect the act of writing it exposed, which needed no
credential to find or to fix.

## Objective

Verify DeepSeek's actual current API contract against the live service, using one small
public query, and update the adapter **only** from observed behaviour.

## Why now

The RC report names this as one of five critical gaps. The adapter (4.3) models
server-side `web_search` as an OpenAI-compatible tool call, which is the convention and
not a verified fact.

## What shipped

### `tests/test_v3_deepseek_live_contract.py`

| # | Question | Runs when a key exists |
|---|---|---|
| 1 | A standard call returns text and a finish reason | yes |
| 2 | Usage metadata — **which units DeepSeek actually reports**, printed | yes |
| 3 | JSON-mode output parses | yes |
| 5 | A search request is accepted | yes |
| 6 | **The search response shape, recorded verbatim** | yes |
| 7 | Search results carry real URLs, through the real parser | yes |
| 8/9 | Timeout is transient; a bad credential is permanent | yes |

Test 6 deliberately **prints rather than asserts**. An assertion there would encode the
very guess this slice exists to replace; its output is the evidence the mapping should be
rewritten from.

Test 7 **fails loudly** if the parser produces no candidates from a live response, with a
message pointing at the parser warnings and saying explicitly that the mapping must be
updated from *that* evidence rather than from the OpenAI convention it currently assumes.

### Safety

- Opted in **twice**: a real key *and* `ENABLE_INTEGRATION_TESTS=true`. Never in CI.
- Bounded: one public query (Moderna's pipeline — public information, an issuer already
  in the regression set), `max_tokens` 300, a 45s timeout, a documented call ceiling.
- **The key is never printed, never asserted on, never written to an artefact.** Every
  assertion is on a shape or a length.

### Two tests that run with no key at all

They are the honest record: one skips with a message stating in plain terms that the
contract is unverified, and one asserts `V3_DEEPSEEK_SEARCH_ENABLED` is still `False` —
the guarantee that holds either way, because nothing may call an unverified endpoint by
accident.

## The defect writing this exposed

`DeepSeekUnavailableError.job_transient` was an **unconditional class-level `True`**, so
every failure read as retryable — including a **401**. The durable worker reads exactly
that attribute (`worker.py:215`), so a wrong key would have been retried to the attempt
limit: three times the spend for the same failure, and the first place that costs anything
is in front of a real credential.

The class docstring already said *"a missing key is permanent"*. **The code contradicted
its own stated contract**, and no test caught it because no test had ever driven the real
transport.

Fixed by making transience a **per-raise** decision:

```
PERMANENT_HTTP_STATUSES = {400, 401, 403, 404, 405, 422}
```

408 and 429 are deliberately **absent** — a timeout and a rate limit are exactly the cases
a retry exists for. A connection failure stays transient; a non-object response is
permanent, because a provider returning the wrong content type returns it again in four
seconds.

Verified by nine tests that need **no credential**, driving the real transport through its
own injectable `client_factory` rather than monkeypatching a private method.

## Acceptance criteria

1. A live contract test exists, is opt-in twice, never prints the key, and is bounded. ✅

3. The adapter is updated only from observed behaviour. ✅ *vacuously* — no observation
   was possible, and nothing was changed on the strength of a guess.

## What is NOT resolved

**DeepSeek's server-side `web_search` wire contract.** Still modelled as an
OpenAI-compatible tool call. The mapping is isolated to one method and one parser, the
tool name is configuration, the flag is off, and the parser returns no candidates with a
warning naming what it saw. Confirming it is: obtain a key, run this file, read test 6's
output, adjust two functions.

## Non-goals

- Guessing the contract. Explicitly forbidden by the phase brief and by the campaign's own
  rule about unverified claims.
- Making DeepSeek a hard dependency of any V3.10 acceptance run. Slice 10.2 routes the
  Investigator to Azure OpenAI when no DeepSeek key resolves, so the end-to-end work is
  not blocked by this.
