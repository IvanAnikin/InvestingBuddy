# V3.4 Slice 4.5 — the provider benchmark harness

## Objective

A repeatable, scored comparison of research providers whose primary metric is
**`cost_per_verified_finding`** — never price alone.

## Why now

4.3 shipped a provider that produces leads and 4.4 built the gate that verifies them, so
the denominator finally exists. Before 4.4 a "benchmark" could only have counted output,
and counting output rewards the provider that writes the most.

## Current implementation

- `app/services/consumption.py` — `ConsumptionUnits`, `PriceBook`, `derive_cost`. An
  empty price book yields `None`, never `0.0`.
- `app/services/providers/contracts.py` — `ResearchProviderResult`, the lead lifecycle.
- `app/services/providers/leads.py` — the verification gate and
  `verification_survival_rate`.
- `app/services/providers/fakes.py` — a scriptable `FakeResearchProvider`.

## Proposed changes

`app/services/providers/benchmark.py` and `scripts/v3-provider-benchmark.py`.

### The three ways a benchmark lies, and what stops each

1. **Reporting an unpriced provider as free.** `cost_per_verified_finding` is `None`
   whenever the cost is unknown; `cheapest()` ranks only providers that have one, and
   returns `None` when none does. A test asserts an unpriced provider with 100 verified
   findings loses to a priced one with a single verified finding.
2. **Estimating a provider it cannot run.** Exa, Perplexity, Gemini and Anthropic have no
   credentials **by decision**. They appear in the report as `not_approved`, and there is
   **no code path** that produces a number for a provider that did not run. The
   unavailability reasons are a closed vocabulary — "unavailable" aggregated by reason is
   a finding; aggregated by free text it is a list of sentences.
3. **Reporting a rate over nothing.** A provider with no leads has a survival rate of
   `None`, not `0.0`. A vendor that never answered is not a vendor that answered badly,
   and the second is much the better of the two.

### Undecided is not the vendor's fault

4.4 leaves a lead `pending` when the platform could only partly read the source. The
harness counts those separately and keeps them **out of the survival rate**: a gate that
could not read a scanned PDF is a statement about InvestingBuddy's reader.

### Cited hosts

Each task names the hosts an authoritative answer would come from. A provider that
answers well from a content farm is answering a different question, and that is invisible
from the answer.

## Security considerations

- Never in CI, per the acceptance strategy §5.6: a full benchmark is a deliberate,
  budgeted, manually triggered run.
- `--live` is required *and* a provider must actually be configured. Two gates, because a
  benchmark that starts spending on a default is a bill nobody chose.
- Per-task `max_seconds` is passed to the provider, so one task cannot consume the run.
- Nothing prints a credential; the report holds counts, reasons and URLs only.

## Unit tests

Every refusal: unpriced has no ratio, priced-with-nothing-verified has no ratio, a rate
over nothing is `None`, an unpriced provider never wins, no winner is declared when none
is measurable, an invented unavailability reason raises, a provider that raises does not
end the run, and `render_report` prints `unknown` rather than `0`. Plus one that the
script's task set covers the real-issuer regression set (PNDORA, CFR, MRNA, ASML) and
that every task names its expected hosts and its trap.

## Integration tests

None. The live path is the script, opt-in by construction.

## Live issuer acceptance

The fake run was executed and its output recorded in the slice's PR. A **live** run is
not performed: no provider credential is configured in this environment, and the honest
output of the harness in that state is exactly what it printed — every provider
`not_approved` or `not_configured`, no cost, no winner.

## Acceptance criteria

1. The harness produces `cost_per_verified_finding` from a real verification gate, and
   `None` whenever cost or verified count is unknown.
2. A provider that could not run appears in the report with a reason from a closed
   vocabulary, and has no score.
3. No cross-provider result is estimated: the run with no configured provider reports
   nothing rather than an extrapolation.

## Non-goals

- Choosing a winner. Nothing here defaults a provider or changes routing.
- Filling in the price book. Prices are configuration and a price nobody has recorded
  stays unknown.
- Benchmarking search or model providers separately. `ResearchProvider` is the interface
  whose output the verification gate can score; the others get their own harness when
  something needs one.

## Rollback

Delete the module and the script. Nothing imports them at runtime.
