# V3.4 Slice 4.1.1 — Rights-based provider governance

**Branch:** `feature/v3-4-1-1-rights-based-governance` · **Merge target:** `develop/v3` only
**Migration:** no · **Infrastructure:** no · **Provider dependency:** none
**Implements:** [ADR-049](../../DECISIONS.md) (resolves OPEN DECISIONS #4 and #11)

## Objective

Replace the blanket geography rule with the two-gate model ADR-049 specifies: a coarse
*provider × access class* gate, a fine *document rights* gate, and a categorical
exclusion for credentials that no policy can override.

## Why the previous rule was wrong, not merely restrictive

Slice 4.1 shipped `user_private → DENY` for every external provider. That was a
**placeholder for a decision nobody had taken**, not a considered policy, and it tangled
two questions that have different answers:

- *Where does this provider run?* — a fact about infrastructure.
- *What does this document's licence say?* — a fact about the document.

Only the second constrains use, and only the second is answerable per document. ADR-049
settles it: **data rights and explicit source policy govern provider use; provider
geography does not.** China location and storage are explicitly not a blocker for this
project.

## Two gates, and both must open

| Gate | Where | Answers |
|---|---|---|
| **Coarse** | `ProviderGovernance` | "Has anybody evaluated this provider for this *kind* of material?" Denies by default. |
| **Fine** | `ArtifactPolicy` on the document | "Does *this* document's licence permit *this* provider?" Defaults to closed for every non-public class. |

`permits_document` requires **both**, not either. Checking only the coarse gate would
send a licensed report to a provider its licence names nobody for; checking only the fine
gate would send material to a provider nobody evaluated. The coarse reason is reported
first when both close, because "nobody evaluated this provider for licensed material" is
more fundamental than "this particular licence does not name it" and more useful to
whoever has to fix it.

`ArtifactPolicy` gains `permitted_providers` and `external_model_rationale`. Note the
three-way distinction, which a boolean could not express:

- `permitted_providers is None` — any provider `sent_to_external_model` already allows.
- a **non-empty** frozenset — exactly these, which is what a licence saying "may be
  processed by X" translates into.
- an **empty** frozenset — the document was considered and no provider was permitted.
  Meaningfully different from `None`.

## Widening is deliberately awkward; narrowing is not

`allow_external_model` **requires a rationale** — a grant nobody can audit is a grant
nobody reviewed — and it is the only supported way to make a non-public document readable
by a model. `forbid_external_model` takes an optional one. **The asymmetry is the point.**

Granting a private class in the *provider* matrix now requires an authority string citing
`ADR-049` or `#11`. That is what keeps the register auditable after the resolution rather
than merely permitted by it, and it applies to an internal provider too: "it runs in our
tenancy" is a statement about where it runs, not an answer to whether private material
may be sent to it.

Critically, **granting a private class sends nothing.** It records that the provider has
been evaluated for that kind of material. The document's own rights are gate two and
default to closed, so `rights are never inferred from the fact that a file was uploaded`
survives the resolution intact.

## A secret is not an access class

API keys, passwords, credentials, tokens, private configuration and PEM blocks are
refused **categorically** by `assert_no_credentials`, regardless of any policy — because
a policy is something somebody can edit, and the one thing that must not be widenable by
an allowlist change is a credential. A test asserts no access-class name contains
`secret`, `credential`, `key`, `token` or `password`, so the vocabulary cannot acquire one
by accident.

The marker list is deliberately broad: a false positive costs a refusal a human fixes by
removing the secret, a false negative costs a key. This is a backstop in the same spirit
as `assert_registry_safe` and the `RedactingFilter` that exists because root-level INFO
logging once leaked an EODHD `api_token`.

## What changed in the default matrix

- **DeepSeek** is evaluated for every class including the private ones, on an authority
  citing ADR-049 — it is the primary external research provider.
- **Azure OpenAI** likewise, as the strong-model fallback (ADR-050).
- **Exa, Perplexity, Gemini, Claude, OpenAI** stay in the register as **public-only and
  deferred**, each with the reason recorded. They are kept rather than removed so the
  register is a complete statement rather than a list of whatever happens to be switched
  on — and so a future reader can see that Gemini's absence was decided, not forgotten.

## Seven tests changed, and why that is not a weakened guard

Seven slice-4.1 tests asserted the pre-resolution policy and now assert the new one. The
rule changed **by user decision**, not because a guard was relaxed, and the net effect is
stricter in the dimension that matters: two gates where there was one, plus a categorical
credential exclusion. What became more permissive — private classes are grantable — is
the decision itself, and it remains gated per document with an auditable rationale.

The routing test's refused case moved from DeepSeek to a *deferred* provider, since
DeepSeek now passes the coarse gate for private classes and Gemini does not. That keeps
the test testing the same property.

## Acceptance criteria

1. **A private document is unreadable by default** and needs an explicit, rationale-bearing
   widening — for any provider.
2. **Both gates are required**: a widened document still cannot reach a provider that has
   not been evaluated for its class, and a document naming its permitted providers
   excludes the rest.
3. **A credential is refused categorically**, and no policy can override it.
