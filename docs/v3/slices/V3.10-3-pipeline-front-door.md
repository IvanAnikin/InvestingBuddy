# V3.10 Slice 10.3 — the V3 pipeline at the real front door

## Objective

The existing company-research entry point invokes the whole V3 pipeline behind a feature
flag, and the result is a report the existing API and frontend render unchanged.

## What this slice does, precisely

```
company research API -> durable job -> entity -> Director -> playbook -> Ledger
  -> specialist investigations -> tools -> bounded gap follow-up -> Council V2
  -> Red Team -> Chair -> persisted report -> existing report API -> Research Memory
```

Every step of that runs. **The report's narrative is still assembled by the existing
generator**, and the V3 contribution is persisted research state attached to it under
`source_summary_json["v3_research"]`: the ledger run, findings with their evidence ids,
gaps, disagreements, Red Team challenges and the Chair's verdict.

### Why the V2 assembly still writes the narrative

Three reasons, in order of weight:

1. It is what the frontend renders. The frontend reads a ```json block embedded in
   `content_markdown`, whose shape the V2 generator owns.
2. It is what the safety gate, schema validation and server-side numeric verification are
   wired to.
3. It is what makes this reversible. With the flag off, **byte-for-byte nothing changes**.

The phase brief says not to redesign the frontend, and replacing a 5,500-line generator's
output during an acceptance phase would have meant exactly that.

**Stated plainly so the RC report can be read correctly: the V3 Council's verdict is
recorded beside the report, not driving its prose.** Making it drive the narrative is a
further slice with its own compatibility surface.

## The safety property

> **A V3 failure must never cost a report the V2 path would have produced.**

Three things make that true and one test asserts each:

- The pipeline runs **after** the report exists, so the worst case is a report without the
  extra key.
- `run_v3_research` **never raises** — every exception is caught, recorded on the outcome
  and returned.
- The front-door helper catches too, and returns `None`.

Attachment is additive: an existing `source_summary_json` is preserved and exactly one key
is added.

## The defect this slice found

The delta was **silently never computed**. The first draft asked `memory.previous_run`
again at delta time — by then *this* run is the most recent, the guard against comparing a
run with itself fired, and `outcome.delta` stayed `None`.

The feature looked implemented and returned nothing, on every run, forever. Fixed by using
the prior run captured **before** this one opened, with a regression test whose name says
what it is for.

## Degradation is recorded, never silent

`degraded` is populated with a reason for every narrowing: no model resolved, no playbook
applied, the chair fell back. The front door surfaces the first five as run warnings. A
pipeline that narrowed silently is one nobody can widen.

## New modules

`app/services/pipeline/v3_pipeline.py`, `tests/test_v3_pipeline_front_door.py`; plus
`_run_v3_pipeline` in `company_research_service.py` and one config flag.

## DB migration        no
## Infrastructure      no
## Provider dependency none required — the pipeline runs with no model and says so.
## Feature flags       `V3_PIPELINE_ENABLED` (default **off**)

## Security considerations

The flag defaults off and a test asserts it. The pipeline is invoked only when a report was
produced — research state hanging off no report is state nobody can reach. Tool sessions
are built **per role**, so a role's tool policy is the one the platform declared rather
than one the pipeline chose.

## Unit tests

17. The flag off doing nothing; no report doing nothing; the pipeline never raising; a
failure leaving the report untouched; attachment preserving an existing summary and adding
exactly one key; the payload stating what it is and is not; an end-to-end run with **no
model** degrading honestly; the biotech playbook selected for Moderna; an unclassifiable
company recording why none applied; the ledger run persisted and reachable; the loop naming
its limit; the council refusing when there is nothing evidence-linked to reason over; a
second run producing a delta; and a first run having none, which is not a failure.

## Acceptance criteria

1. The real entry point can invoke the V3 pipeline behind a flag. ✅
2. V2 behaviour is unchanged with the flag off. ✅ asserted.
3. A V3 failure never costs a report. ✅ asserted three ways.

## Non-goals

- The V3 Council driving the report narrative. A further slice; see above.
- Changing any existing report section, the safety gate or the numeric verification.
