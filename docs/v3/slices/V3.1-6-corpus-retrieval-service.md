# V3.1 Slice 1.6 — Corpus retrieval service

**Branch:** `feature/v3-1-6-corpus-retrieval-service` → `develop/v3`
**Status:** `IMPLEMENTED`
**Migration:** none.

## Objective

One typed way to ask the corpus a question, returning results that are already
citable, and one way to resolve a recorded evidence identifier back to the exact
span months later.

## Why now

Slice 1.5 fills the index. Nothing yet reads it in a way a research agent could
be given. V3.3's `search_company_corpus` tool is this service with a tool wrapper
around it, so the shape has to be right before an agent depends on it.

## New modules

- `apps/api/app/services/corpus/retrieval.py` — `search_corpus`,
  `resolve_evidence`, `EvidenceReference`, `CorpusSearchResult`,
  `EvidenceContext`.
- `apps/api/tests/test_v3_corpus_retrieval.py`

Plus `scripts/v3-corpus-acceptance.py` extended to chunk, index, search and
resolve an evidence id on the real document.

## DB migration / infrastructure / provider dependency

None, none, none.

## Feature flags

`v3_corpus_enabled` (existing). With it off, `search_corpus` returns `[]` and
`resolve_evidence` returns `None` — a caller degrades to whatever it did before
the corpus existed rather than failing.

## The decision this slice is really about

**The signature is typed primitives, and there is nowhere to put a query
expression.** `search_corpus` takes strings, UUIDs and dates. It does not take a
filter dict, an option bag, a backend expression or a caller-assembled
`CorpusQuery`.

That matters most once the caller is an agent. A retrieval tool that accepts
free-form query syntax is a tool whose behaviour is decided by whatever text
reached the model — including text that came out of a fetched document, which is
attacker-influenced in the general case. The governance document states the rule
as *tool arguments are validated, not interpolated* (§4); this is that rule at the
corpus boundary, and `test_no_backend_query_syntax_is_reachable` enforces it by
inspecting the signature.

It also keeps the backend swappable in practice rather than in principle: a caller
able to pass backend options would couple to the backend through the option names,
and OPEN DECISION #1 would stop being one adapter's worth of work.

## Stable evidence identity

`EvidenceReference.evidence_id` is `ev:` plus the chunk's derived id, so it means
the same thing tomorrow, after a reindex, and in a report written six months from
now. `resolve_evidence` reconstructs the full provenance from the database alone:
the span, its surrounding page — the architecture spec's *"show me where this
number came from" renders the surrounding page* — and, for a table citation, the
**grid** rather than the flattened text the chunk was found by.

This replaces run-local `E1`/`E2` positional handles **for new research only**.
Existing reports are untouched and their handles keep resolving, as the
compatibility plan requires.

An unknown id resolves to `None`. A citation that no longer resolves is a real
answer and must not be papered over with an approximation.

## The citation label names the scope and the period

`"Annual Report 2025, p. 12, Group results (Group, 2025)"`. Not decoration:
"Revenue 32,549" and "Group revenue, FY2025: 32,549" are different claims and only
the second is checkable. A table citation names its table location rather than a
page it has no claim to.

## Security considerations

- No query syntax reaches a backend from a caller (above).
- Entity scoping and the semantic-only refusal are enforced at the service, not
  only at the query object — asserted by `test_the_refusals_hold_at_the_service`.
- `access_classes` is a first-class filter, so a private-content boundary is a
  query constraint rather than a presentation choice.

## Unit tests

`tests/test_v3_corpus_retrieval.py` — **20 tests**, against a real SQLite database
and the real in-memory backend, seeded through the real chunking and indexing
path.

Covers: no backend query syntax reachable · every filter dimension a named
argument · corpus flag off returning `[]` · both refusals at the service · a
result carrying every citation field without a second lookup · per-leg scores ·
the citation label naming scope and period · a table result citing its table ·
period / scope / source-tier filters constraining · **company isolation** ·
deliberate cross-entity search · evidence id round-trip · **a recorded id
resolving back to the exact span and its page** · a table id resolving to the
grid · unknown id → `None` · flag respected · **an id surviving a reindex** · and
the V3.1 phase demonstration in one test: ask for the segment figure, get page 48,
scoped `segment`, section `Segment information`, cited as `p. 48`.

## Real-document acceptance

`scripts/v3-corpus-acceptance.py` now runs the whole corpus on the real Pandora
Annual Report 2025:

```
=== 6. chunk, index, and search ===
  chunks     113 (103 prose, 10 table); prose chars min=76 median=964 max=1998
  identity   113 unique ids of 113 chunks
  indexed    113 chunks
  query 'revenue' -> 3 hit(s)
    Annual Report 2025, p. 11, REPORT > ORGANIC GROWTH (2025)
    Annual Report 2025, pp. 11-12, REVENUE ACROSS REGIONS > DKK (2025)
  evidence id ev:c:2ffcbc1635ca354ef1c5b5a4856245e53d6608bc
  resolves back: True page_text=yes grid=n/a
```

**An honest limitation this surfaced.** A query for "cash flow from operations"
returns the contents page. The corpus holds pages 1-40 of a 169-page annual
report, and pages 1-40 are the management review — the financial statements start
well beyond the live extraction cap. Retrieval is doing the right thing over the
text it has; the text it has is a quarter of the document. The derivation records
`pages_persisted=40, page_count=169, status=partial`, so nothing about this is
hidden, and closing it is exactly what Slice 1.7 exists for: reprocess from the
retained bytes under a larger budget, off the live request path.

## Acceptance criteria

1. **A query returns the right page with citable lineage.** ✅
   `test_a_query_months_later_returns_the_right_page` — page 48, segment scope,
   section path, `p. 48` in the label — and the real-document run above.
2. **A recorded evidence id resolves back to the exact span.** ✅
   `test_a_recorded_id_resolves_back_to_the_exact_span_and_its_page`,
   `test_an_id_survives_a_reindex`, and the real-document run.
3. **No backend query syntax is exposed to a caller.** ✅
   `test_no_backend_query_syntax_is_reachable`.
4. **No V2 regression.** ✅ suite 4899 → **4919 passed**, 12 skipped; `ruff`
   clean; `mypy app` 71 (unchanged, same scope). No migration, no existing module
   changed.

## Non-goals

- The agent tool wrapper (V3.3.4). This is the service it will wrap.
- Any production search backend (OPEN DECISION #1).
- Retiring `E1`/`E2` from existing reports. New research gets stable ids; old
  reports keep resolving, unchanged.

## Rollback

script is touched.
