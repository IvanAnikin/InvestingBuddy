# V3.0 Slice 1 — Durable job contract

**Branch:** `feature/v3-0-1-durable-job-contract` → `develop/v3`
**Status:** `IMPLEMENTED`
**Migration:** 019 (created; **not applied to any deployed environment**)

## Objective

Establish the durable job record and the pure state machine that governs it:
idempotent submission, leased execution, bounded retries, dead-letter,
cooperative cancellation, and read-time derivation of `interrupted`.

## Why now

Every later V3 phase makes runs longer. Building autonomous multi-round
investigation on FastAPI `BackgroundTasks` — which is what all six current async
entry points use — means building it on something an App Service recycle
deletes. Execution durability comes before research methodology.

## Security considerations

- No secrets. `payload_json` carries job inputs; the store must never be given
  credentials, and no logging path prints it.
- `lease_owner` is operational identity and is deliberately excluded from the
  reader-facing envelope — asserted by test.
- Both FKs are `SET NULL`, never `CASCADE`: deleting a company must not delete
  the record that research was performed for it (CLAUDE.md rule 15).

## Acceptance criteria

1. **The V3 status vocabulary is a strict superset of V2's, and `interrupted` is
   never stored.** ✅ asserted by `TestVocabulary`; `interrupted` is absent from
   `STORED_STATUSES` and from the table.
2. **A lapsed lease is reclaimable by exactly one other worker, consumes an
   attempt, and reads as `interrupted` without mutating the job.** ✅
   `TestClaiming`, `TestDerivedStatus`.
3. **Migration 019 applies and rolls back cleanly, and the database itself
   rejects a duplicate `idempotency_key`.** ✅ verified against real PostgreSQL:
   `upgrade head` → `downgrade 018` → `upgrade head`, and a second insert with
   the same key raised `duplicate key value violates unique constraint
   "uq_research_jobs_idempotency_key"`.
4. **No V2 regression.** ✅ full suite 4433 passed / 12 skipped; `ruff` clean;
   `mypy app` 71 errors on both `develop/v3` and this branch (unchanged, same
   scope); test count 4376 → 4445, i.e. +69 and none lost.

## Non-goals

- Wiring any entry point (Slice 3).
- The worker loop itself (Slice 2).
- Service Bus (Slice 6).
- Changing V2 behaviour in any way.

## Rollback

`git revert` the merge commit on `develop/v3`, then `alembic downgrade 018` if
019 was ever applied anywhere. Since nothing reads or writes the table, a revert
is inert.
