# V3.4 Slice 4.10 — bounded issuer-site traversal

## Objective

A bounded, same-domain walk of **one issuer's own site** on the platform's existing
guarded fetcher, that always reports which bound stopped it.

## Why now

Slice 4.8 built the destination for transcripts and IR-event materials and deliberately
left acquisition out, because finding them means walking an IR site. This is that walk.
It is also what makes the off-domain-CDN case reachable — Pandora's documents live on one
and V2 could not follow it.

## Current implementation

- `safe_web_fetcher.safe_fetch_page` — one bounded, allowlisted, DNS-pinned page fetch
  that returns the byte-capped body and extracted links, and never raises.
- `safe_web_fetcher.extract_links` — absolute-resolves, keeps HTTPS-only allowlisted
  hosts, de-dups, caps the count.
- Neither walks. `document_discovery` follows a fixed one-hop pattern per connector.

## Proposed changes

`app/services/traversal/issuer_site.py`: a breadth-first walk with a frontier, a visited
set, and four finite bounds.

### What this is not

Not a crawler, not a spider, not a browser. The 2026-09-05 decisions rule out a paid
crawler service and governance §3 makes browser automation a last resort that is not
available. A JS-only IR page is therefore recorded as **partially inaccessible**, with
the reason, which is a research gap somebody can act on. Phase 32A slice 5A already
measured the alternative: zero successful native extractions across seven live issuers,
with the success path existing only in unit tests.

### Every walk ends, and says which bound ended it

`max_pages` · `max_depth` · `max_links_per_page` · `max_seconds` · the frontier.
`stopped_by` is never empty — `exhausted` when the frontier emptied, a bound's name
otherwise — because a result reporting "12 pages" without saying it hit its page cap
invites a reader to conclude the site has twelve pages. `completed` is True **only** for
`exhausted`.

Depth is deliberately not a stop reason: reaching `max_depth` bounds a page's *children*,
and the walk continues through the rest of its frontier.

### robots.txt is obeyed by not requesting

Governance §10 requires it. A disallowed path is skipped and counted — not fetched and
discarded, because "we obeyed robots.txt" has to mean the request did not happen. An
**unreachable** robots.txt is not a prohibition and the walk proceeds; a retrieved one
that disallows is final.

### The allowlist is the issuer's own domain

Plus whatever the caller explicitly adds. `extra_domains` is how an off-domain CDN is
reached, and it is explicit rather than inferred — inferring it from a redirect would let
any site widen its own allowlist. Everything else the guarded fetcher already refuses:
non-HTTPS, internal hosts, IP literals, an off-allowlist redirect, and the byte cap.

### Documents are candidates, never fetched here

The walk collects document-looking links and stops. Turning a URL into bytes with a hash
is `safe_fetch_document`'s job and its guards are the ones that matter for a 30 MB PDF.

## Security considerations

The whole slice is a security surface, so the bounds *are* the design:

- With the flag off, **no request is made** — asserted, not assumed.
- Every fetch is `safe_fetch_page` with `resolve_ip=True`: HTTPS-only, safe-public-host,
  DNS-pinned, redirect-guarded to the same allowlist, byte-capped.
- `robots.txt` disallow means the request does not happen.
- The frontier is de-duplicated and bounded; one bad page is counted and skipped rather
  than ending the walk, so a hostile page cannot deny the rest of the walk.
- The result carries no body HTML and no secret — `to_dict` is counts, reasons and URLs.

## Unit tests

A zero bound refused at construction; the flag-off path making no request; each of the
four bounds stopping or limiting the walk and being named; an emptied frontier reported as
complete; robots disallow skipping **without requesting**; an unreachable robots.txt not
being a prohibition; the named user agent honoured; blocked and failing pages counted;
one bad page not ending the walk; an off-domain link not followed; an off-domain CDN
reachable only when named; a non-HTTPS start refused; documents collected and never
fetched; a document found twice listed once; a JS-gated page recorded rather than worked
around; an ordinary long page not mislabelled; and the result serialising without a body.

## Integration tests

None. There is no database and no schema; the network is the injected seam.

## Live issuer acceptance

Not performed. `V3_ISSUER_TRAVERSAL_ENABLED` is off and no live issuer site was walked —
walking a real company's site is an outward-facing action, and the flag exists so the
mechanism can be accepted first.

## Acceptance criteria

1. Every walk terminates and names the bound that stopped it; only an emptied frontier
   reads as complete.
2. A `robots.txt` disallow results in no request for that URL.
3. A JS-gated page is reported as partially inaccessible with a reason, and no browser or
   paid crawler is required or invoked.

## Non-goals

- Wiring the walk to IR-event discovery (slice 4.8's destination). One small slice once
  both are accepted.
- A public-suffix list. `registrable_domain_of` is the naive last-two-labels rule already
  used elsewhere here; the failure direction is a broader domain that the other guards
  still bound, and a caller can pass an explicit allowlist instead.
- Politeness delays, per-host rate limiting or a crawl scheduler. Nothing schedules this;
  it is called once per research task under the task's own budget.
- Browser rendering. Not available and not wanted.

## Rollback

Set `V3_ISSUER_TRAVERSAL_ENABLED=false` (the default). Nothing else reads the module.

## Dependencies

Phase 32A slice 5B.1 (the guarded fetcher and DNS pinning), slice 4.8 (the destination
this eventually feeds).
