# V3.8 Slice 8.1 — research memory

## Objective

Prior research state, retrievable by entity, **labelled as memory** and never merged into
a new run's findings.

## Why now

Every V2 run starts from zero: there is no prior-research read path, so a refresh
re-derives everything and cannot say what changed. 8.2's `ResearchDelta` needs a "before"
to compare against, and 5.2's Director already consumes `prior_open_gaps` — a parameter
with no producer.

## Current implementation

None. `company_research_service.execute_company_research` reads no prior run.

## Proposed changes

`app/services/memory/store.py`: `recall(company_id) -> PriorResearch`.

### There is no snapshot table, and that is the design

A copy of the prior run's conclusions would be a second source of truth that drifts from
the first — and drift here is **uniquely bad**, because the copy is what a later run would
trust while the original is what a citation resolves against. So memory reads the prior
run's **ledger**: findings, gaps and disagreements that are already evidence-linked and
already refused if they were not. `research_runs` is indexed on `(company_id, started_at)`,
which is exactly what "retrievable by entity" needs. A test asserts no such table exists.

### The three rules, made executable

| Rule | How |
|---|---|
| **New primary evidence outranks stale memory. Memory proposes; evidence disposes.** | A recalled finding is a `RecalledFinding`, not a `ResearchFinding`: it names the run it came from, carries its age, and is **never merged** into the new run's findings. Merging would make provenance a matter of reading the statement text. |
| **Memory is never a citation source.** | It points at evidence ids, and `recall` reports `stale_evidence_ids` rather than quietly returning a finding whose support has gone. Which ids still resolve is **injected**, because "does this chunk still exist" is a corpus question and memory must not become a second implementation of it. |
| **A gap is what carries forward.** | `carry_forward_questions` returns `(question_key, text)` — the exact shape `plan_research` consumes, stamped `origin=prior_gap`. Only **closable** gaps: one no source can close would be re-asked every run forever, which is a memory that has learned nothing. |

### Two smaller decisions

- A **stopped** run still counts as memory. It stopped on a budget and still learned
  things; discarding it would throw away the work the budget paid for.
- A **withdrawn** finding does not return through memory. One the Red Team retired must not
  come back a quarter later wearing the authority of memory — and memory is the path it
  would otherwise return by.

## Security considerations

Recall is bounded in both dimensions and reports truncation: a new run handed nine hundred
remembered statements is a run reading a corpus of its own past. Nothing recalled is
citable on its own — every payload is stamped `kind: prior_research_memory`, in the dict
rather than only in the type, because the dict is what a prompt builder sees.

## Unit tests

Finding the prior run: absence as a state; a never-investigated run excluded; the most
recent qualifying run; a stopped run counting; `before` letting a replay see only what
existed then. Labelling: the source run named; age reported and staleness marked; a
withdrawn finding not returning. Citations: stale evidence reported, and **no staleness
claimed when none was checked**. Gaps: an open one becoming the next run's question, an
unclosable one remembered but not re-asked, a closed one not remembered as open, and the
carry-forward shape flowing into `plan_research` with `origin=prior_gap`. Plus bounds, the
serialised summary, and the assertion that no snapshot table exists.

## Integration tests

None new. Every read is over the ledger, whose guarantees were exercised against real
PostgreSQL in 5.1.

## Live issuer acceptance

Not performed. Nothing calls `recall` on a live path.

## Acceptance criteria

1. A prior run's conclusions are retrievable by entity and arrive **labelled as memory**,
   with their age and their source run.
2. Evidence that no longer resolves is reported rather than silently returned.
3. An open closable gap becomes the next run's question, in the shape the Director already
   consumes; an unclosable one does not.

## Non-goals

- Computing what changed. That is 8.2.
- A prior *thesis* or chair synthesis. Those live in `reports`, not the ledger, and
  bridging them is report-layer work with its own compatibility surface.
- Cross-entity memory ("what did we learn about luxury"). Per-entity first.

## Rollback

Delete the module. Nothing imports it at runtime.

## Dependencies

V3.5.1 (the ledger), V3.5.2 (`prior_open_gaps`), V3.7.2 (the withdrawn status it honours).
