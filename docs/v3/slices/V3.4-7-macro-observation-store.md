# V3.4 Slice 4.7 — the macro observation store

## Objective

`DatasetDefinition` / `SeriesDefinition` / `Observation` with **vintages**, one live
source, and the `get_macro_series` tool that reads them.

## Why now

Fifteen macro sources are in the registry today and every one is **reference-only by
design**: it emits a bounded pointer plus an honest gap and makes no network call at
report time. That was the right call when nothing could store a time series. This is the
somewhere for one to land.

## Current implementation

- `app/services/sources/connectors/macro_reference.py` — 15 `MacroSourceSpec` entries,
  each a fixed public landing page with no credential and no figure.
- `app/services/agent_tools/contracts.py:73` — `TOOL_GET_MACRO_SERIES`, reserved by
  V3.3 and unimplementable then because nothing had a series to return.

## Proposed changes

Three tables, a store, a source interface, one live source, one tool.

### Vintages are the whole design

A macro series is **revised**. Euro-area GDP for Q2 is one number in July and a different
number in October, and both were correct when published. A store that overwrote the first
would silently change the macro context of every report that cited it, months after that
report was signed off.

So an observation is keyed on `(series, period, vintage)`, a revision is a **new row**,
and `as_of(series, when)` returns what the platform knew then. Two database guarantees
carry it:

| Index | What it makes impossible |
|---|---|
| `ix_macro_observations_series_period_vintage` (UNIQUE) | Overwriting a vintage. "The publisher re-released" and "our connector ran twice" become different events. |
| `ix_macro_observations_one_current` (partial UNIQUE) | Two current readings of one period, without the superseded vintages contending for the slot. |

### A separate period vocabulary, deliberately

`financial_period.ReportingPeriod` is **not** reused. An issuer's fiscal half has no
statistical analogue and a statistical month has no fiscal one; a shared vocabulary would
invite comparing Richemont's FY2025 — which ends in March — with a calendar 2025 macro
reading as though they covered the same twelve months. A test asserts each vocabulary
refuses the other's exclusive keys.

`parse_macro_period` **raises** on an unrecognised key, which is the opposite of
`parse_period`'s unknown-is-a-state behaviour, and for a reason: a financial period comes
from a *document*, where "not stated" is real; a macro period key was built by a connector
from a publisher's structured response, so an unrecognised one is a defect in the
connector.

### One source, wired correctly

The **World Bank Indicators API**: free, public, **no credential**, CC BY 4.0, a stable
documented JSON contract. The platform already learned the alternative the expensive way —
28 reference-only connectors, none of them queried.

Two things the parser refuses:

- **A response with no `lastupdated` is refused, not stamped with the current time.** A
  vintage of "now" on a three-year-old release makes every historical reading look
  freshly published, which is precisely the lie the column exists to prevent.
- **An indicator whose name states no unit yields `unknown`, never dollars.** The
  Indicators API has no unit field; the name carries it, and guessing would hand a
  reader a number in a currency nobody published.

A published `null` **is** retained as an observation. "The Bank has no figure for 2025" is
information; dropping it makes the gap indistinguishable from the platform never asking.

## Security considerations

- The fetch is the platform's own guarded one: HTTPS-only, host-allowlisted to
  `api.worldbank.org`, DNS-pinned, redirect-guarded, byte-capped.
- **Indicator and country codes are refused rather than escaped.** They become URL path
  segments, and a segment built by escaping is one encoding bug away from a different
  request. Only alphanumerics, dots, hyphens and underscores pass.
- **The tool never fetches.** A read-only tool that could trigger a network call would be
  an agent-controlled outbound request, which is what the closed tool list exists to
  prevent. A test parses the module and fails if a fetch symbol appears in it.
- With the flag off nothing makes a network call and a fetch returns `not_configured` —
  an honest state, never an empty series.

## Unit tests

Period parsing including a leap February; each vocabulary refusing the other's exclusive
keys; a revision as a new row; `as_of` returning the July number in August; `as_of` before
any vintage returning nothing rather than the first value; a backfilled older release not
becoming current; the same vintage twice conflicting; one current row per period; a
published NULL kept; a frequency mismatch refused; a unit change refused as a rewrite; the
period filter in the same statement as the limit; the World Bank parser's five outcomes;
the flag-off path making no call; a bad code refused before any call; and the tool's
`as_of`, `revisions`, missing-series and no-fetch behaviours.

## Integration tests

Migration 033 against **real PostgreSQL 16**: eight statements exercised, including that
two vintages of one period are both storable, the same vintage twice is a conflict, two
*current* readings are refused by the partial unique index, a NULL value is storable, and
deleting a series takes its observations with it — a value whose unit is gone is not a
partial record, it is uninterpretable.

## Live issuer acceptance

Not performed. `V3_MACRO_SOURCES_ENABLED` is off and no live World Bank call was made;
the parser is exercised against a recorded response shape.

## Acceptance criteria

1. A revised observation is a new row; the previous vintage survives and `as_of` returns
   it for a date before the revision.
2. Exactly one reading per `(series, period)` is current, enforced by the database.
3. The `get_macro_series` tool returns every value with its unit, frequency and vintage,
   and never fetches.

## Non-goals

- Wiring the other 14 macro sources. One source correctly bounded beats four half-wired
  ones; that is the lesson the 28 reference-only connectors already taught.
- `get_industry_series`. It needs an industry source, and this slice adds one macro one.
- Scheduling a refresh. Nothing calls the source on a timer; ingestion is a deliberate
  call.

## Rollback

Migration 033 downgrades cleanly — verified by dropping and re-adding all three tables
against real PostgreSQL. Set `V3_MACRO_SOURCES_ENABLED=false` (the default) to stop any
fetch.

## Dependencies

V3.3.1 (the tool contracts and registry), Phase 29C (the macro reference registry this
gives a destination to).
