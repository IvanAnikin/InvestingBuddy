# V3.11 Slice 11.3 — real playbook completion

## The question this slice answers

V3.10 reported that **no playbook-gated Council had ever convened on real data**. All
three real-issuer runs refused on a blocking question, and the report read those refusals
charitably: the evidence probably was not there.

The acceptance brief asked for the harder answer — *for each refusal, does the required
evidence genuinely not exist, or did V3 fail to retrieve or interpret it?* — and to **fix
only the latter**.

Three of the four causes turned out to be the latter.

## Result

| Issuer | Playbook | Before | After |
|---|---|---|---|
| **CFR** | luxury | refused `blocking_question_open` | ✅ **convened**, 11 findings |
| **MRNA** | biotech | refused `blocking_question_open` | ✅ **convened**, 8 findings |
| **ASML** | semiconductors | refused `blocking_question_open` | ✅ **convened**, 3 findings |

All three now reach `stopped_by=completion_rules_satisfied` and `council_may_convene=True`
on real public data, with a real model Chair (`fallback=False`).

## The four defects

### 1. An allowlist entry with a `www.` prefix matched nothing

`registrable_host_allowed` stripped `www.` from the **host** but not from the **allowed
domain**, so `www.example.com` in an allowlist could never match anything. It failed
closed, so it was never a security hole — it was a correctness one, and it made the real
Richemont annual report unfetchable. Both sides are now normalised, and the prefix,
suffix and empty-host attacks are still refused.

### 2. The playbook's required calculations never reached the tool

`get_calculated_metrics` refuses without a metric name — its vocabulary is closed, and a
model choosing from it would be a model choosing a filter. The playbook question already
declares which calculation it needs, but `PlannedQuestion` **dropped
`required_calculations`** on the way through the planner. So every calculated-metrics call
was refused `invalid_arguments`, and the calculation leg of every playbook question
silently never ran. The field is now carried through and used.

A new test asserts that **every calculation any playbook declares is implemented** — a
playbook naming a metric the engine lacks would block its Council forever, which is
exactly how this class of defect presents.

### 3. Grouped tool payloads were discarded whole

This is the one that mattered most.

`get_segment_facts` returns **groups**, and the citable ids are one level down:

```json
{"items": [{"scope_key": "segment:specialist watchmakers",
            "facts": [{"fact_id": "…", "period_key": "2026", …}]}]}
```

`_harvest` only looked at the top level. Finding no id there, it skipped every group — so
the tool reported `ok, items=2` while the investigator received **zero citable evidence**,
and the luxury playbook's blocking question was permanently unanswerable *by a tool that
was working correctly*.

The harvester now descends one level when the item carries no id of its own, and **each
nested record keeps its own period and scope**: a segment group's facts are not
interchangeable, and inheriting the group's identity instead of the record's would be the
mixing the invariants forbid.

### 4. A modern SEC filing yielded zero text

A current Inline-XBRL 10-K is built almost entirely from styled `<div>`s. The HTML parser
treated only `p`, `li`, `caption`, `blockquote`, `dd`, `dt` and `h1`–`h6` as blocks, so
Moderna's 2.7 MB 10-K produced **0 text blocks and 0 characters** while still yielding its
76 tables. No US filing could contribute narrative evidence to the corpus at all.

With container tags included:

```
blocks       0  →  1,307
characters   0  →  595,941
'mRNA-1'     0  →  103        'Phase 3'  0 → 28
```

**Opt-in**, enabled only by the corpus path. V2 is the deployed, approved product and this
changes which excerpts it ranks, so V2 stays byte-identical. Nesting is safe because
`handle_starttag` already flushes the open block, so a container div emits nothing and
only the leaf carries text — a regression test pins that a triple-nested div produces
exactly one block.

> **Finding for the user, not fixed here:** V2's own HTML excerpt path gets nothing from
> these filings either. Fixing it would change deployed report content and is out of this
> phase's scope.

## Where the evidence genuinely was absent

Not everything was a defect, and the honest cases are recorded rather than engineered
around.

- **ASML `cycle_position`.** The 20-F mentions "backlog" **once**, in a glossary. ASML does
  not discuss bookings or book-to-bill in that document, so no retrieval change could have
  found it. Seeding the quarterly earnings release — a different, equally public document
  — let the question be *answered*, and the answer the investigator gave is itself honest:
  *"The evidence does not provide specific figures or details on bookings, backlog, or
  book-to-bill ratios"*, **with citations**. It looked and said so.
- **MRNA `pipeline_state`.** Genuinely unanswerable until the 10-K's prose existed, which
  is defect 4. With it, the finding is real: *"The clinical pipeline includes the RSV
  vaccine mRNA-1345 (mRESVIA)… approved by the FDA"*, citing a corpus evidence id.

## The measurement gap this also closed

V3.10's harness seeded the **corpus** but never ran **fact validation**, so
`extracted_facts` was empty and the whole facts tool surface had nothing to return. That
was a gap in the measurement, not the product — a real company-research run persists those
facts before V3 starts. The harness now runs the same validation and persistence path, and
on the real Richemont report produces 20 validated facts, 7 scope-carrying, 11 persisted:

```
group                        | revenue          = sales reached € 22.4 billion
group                        | operating_profit = operating profit came in at € 4.5 billion
segment:jewellery maisons    | operating_margin = operating margin of 30.5%
segment:specialist watchmakers | revenue        = sales of € 3.1 billion
```

**The Specialist Watchmakers figure is `segment`, not `group`** — the mandatory regression
holding in the facts store, not only in chunk labels.

And it holds all the way to the Council's output:

```
finding [segment:specialist watchmakers|2026] The Specialist Watchmakers segment
        reported sales revenue of €3.1 billion for FY2026.
        cites ['f07078e9-c0d7-4d9e-9373-635055a318bd']
```
