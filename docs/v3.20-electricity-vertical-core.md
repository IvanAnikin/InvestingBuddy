# V3.20 Phase 5 — Electricity vertical core

Spec: [§3.5](v3.20-electricity-vertical-spec.md). Plan: [Phase 5](v3.20-implementation-plan.md).
This page describes what is built. It grows as each slice lands.

## 5.1 Taxonomy (`apps/api/app/services/electricity/taxonomy.py`)

Versioned configuration (`TAXONOMY_VERSION`), in the same spirit as the playbooks: a file
that can be diffed, reviewed, pinned into a run record and asserted against.

| Layer key | Sub-segments |
|---|---|
| `generation_fuel` | nuclear, uranium, gas_turbines, hydro, wind, solar, geothermal |
| `transmission` | hvdc, hv_cables, overhead_lines, power_transformers, hv_substations |
| `distribution_grid_edge` | distribution_transformers, mv_lv_switchgear, mv_lv_cables, metering, line_hardware |
| `sensing_protection_digital` | protection_relays, grid_monitoring, grid_software, ot_security |
| `storage` | battery_cells, bess, long_duration, battery_recycling |
| `power_electronics` | inverters, converters, power_semis, ups_power_quality, facts |
| `demand_side_decentralised` | data_centre_power, ev_charging, onsite_generation, heat_pumps, demand_response |
| `utilities_grid_services` | regulated_utility, ipp, grid_contracting |
| `upstream_electrical_materials` | copper_conductors, electrical_steel, insulation, magnets_rare_earths, battery_materials |

**Anchors.** Each layer and sub-segment lists the words a company's own disclosure must
contain before the layer can be assigned. Matching is whole-word and plural-aware; a
space in an anchor also matches a hyphen. An anchor with an upper-case letter (`HVDC`,
`UPS`, `SiC`) is matched case-sensitively, so ordinary prose ("ups and downs") does not
read as equipment. The matched span is kept as the quote — the evidence a classification
cites.

**Exclusions.** `general_mining`, `oil_gas_upstream_refining` and `coal` are out of scope
unless the dominant-end-market test passes: a *disclosed* power-related revenue share of at
least `DOMINANT_END_MARKET_SHARE` (0.5). An undisclosed share does not pass. Exclusion
anchors name the business ("oil refinery", "petroleum refining"), so a copper refiner is
not caught by an oil rule.

**Theme tags.** Each layer and sub-segment maps to members of the `theme_tags` enum in
`packages/research-contracts/real_asset_equity/v1/report_schema.json`; a test pins every
mapping against the schema file. The schema-completion layer
(`real_asset_report_completer.py`) now takes its tags from an
`electricity_classification` on the draft (primary layer first). It falls back to the
taxonomy's declared stand-in `reshoring_supply_chain` — still disclosed as a stand-in in
`candidate_emerged_from` — only when nothing classified the company.

## 5.2 Layer classifier (`services/electricity/classifier.py`, `pipeline/electricity_step.py`)

Deterministic; no model call and no network call. Inputs are what the platform already
holds:

- the stored company description (`companies.description`, source kind `company_profile`);
- active segment-scoped `revenue` facts from the company's own extracted documents
  (`company_documents_clause`), inline XBRL first, then by confidence.

**Rules.**

| Rule | Value |
|---|---|
| A layer from segment revenue | a segment whose *name* contains one of the layer's anchors |
| A layer from text | at least `MIN_TEXT_ANCHORS` (2) distinct anchors of that layer |
| Revenue share basis | one period (newest by document date), one currency, one scale, one axis — business-segment or product, whichever maps more revenue; geographic members never map; a segment read twice counts once |
| Primary layer | largest revenue share; with no mapped segment, the most distinct text anchors (ties: taxonomy order). `primary_basis` = `segment_revenue` / `text_anchors` |
| Exclusion | a matched exclusion rule makes the status `excluded` unless the *mapped segment share* passes the dominant-end-market test; a text-only classification cannot pass it |

**Status.** `classified`, `excluded` (candidate layers still listed), `not_electricity`
(text or segments held, nothing supports a layer), `no_evidence` (nothing held).

**Report.** `section(business_model).electricity_layers` — added only when
`V3_ELECTRICITY_CLASSIFIER_ENABLED` is on (default on), so every other report is
byte-identical. Each layer carries its quotes (anchor span plus surrounding words, passed
through `neutralize_forbidden_terms`), source kind, URL and date; `revenue_by_layer` lists
every segment row with its fact id and filing URL. Web: `electricityLayers.ts` →
`ElectricityLayersSection`.

**Known limits.** The annual report's business section (Item 1) is not read yet — only the
stored description. A segment name with no anchor ("Industrial", "Services") stays
unmapped, which lowers `mapped_share`; it is never guessed.

## 5.3 Electricity playbook (`playbooks/industries.py` → `ELECTRICITY`, id `electricity_value_chain`)

The eighth playbook. **Selection:** sector `Utilities`; industries Electrical Equipment,
Electrical Components & Equipment, Heavy Electrical Equipment, Electric Utilities,
Independent Power Producers & Energy Traders, Renewable Electricity; and the business-model
signal `electricity_value_chain`. The pipeline adds that signal before playbook selection
when the slice-5.2 classifier returns `classified` for the company (never for `excluded`),
so a cable maker classified "Industrials" or a copper-rod producer classified "Materials"
still gets the electricity methodology. An Industrials company also keeps
`industrial_defense`; questions union (ADR-054).

| Question key | Priority | Blocking |
|---|---|---|
| `elec_revenue_visibility` — backlog, book-to-bill, conversion period; or regulated/contracted share | 1 | **yes** |
| `elec_capacity_natural_unit` — MVA/GVA, km, tonnes, units/yr, MW/MWh; utilisation; expansions | 1 | **yes** |
| `elec_backlog_quality` — cancellable, price-indexed, margin disclosed, financed/permitted | 1 | no |
| `elec_contracted_vs_merchant` — PPAs, capacity payments, frameworks, expiries | 1 | no |
| `elec_qualification_evidence` — type tests with dates, grid-code approvals, OEM/TSO vendor status | 1 | no |
| `elec_customer_concentration` | 1 | no |
| `elec_input_cost_pass_through` — copper, aluminium, electrical steel; indexation, lag | 2 | no |
| `elec_capex_cycle_stage` — grid plans, utility capex, queues, data-centre build-out | 2 | no |
| `elec_competitor_capacity` — competitors' announced additions (disclosures, press releases; D7) | 2 | no |

**Deviation from the spec, on purpose.** Spec §3.5 calls all nine "blocking". A blocking
question stops the Council, and the platform rule (`test_blocking_is_used_sparingly`) is at
most two per playbook, so the nine are mandatory and two block: secured revenue and
capacity — the two every layer can answer, and without which the analysis is of the wrong
thing. Preferred sources `tso_grid_plans` and `interconnection_queues` are not connectors
yet (phase 7) and produce honest gaps.
