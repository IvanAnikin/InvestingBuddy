# V3.20 Phase 6 — Vertical discovery

Spec: [§3.6](v3.20-electricity-vertical-spec.md). Plan: [Phase 6](v3.20-implementation-plan.md).
This page describes what is built. It grows as each slice lands.

## 6.1 Drivers, bottlenecks and supply-chain laddering

**Catalogue** (`apps/api/app/services/electricity/drivers.py`, `CATALOGUE_VERSION`) —
versioned configuration.

| Driver | Bottlenecks |
|---|---|
| `data_centre_load` | short_circuit_testing, bushings_tap_changers, goes, queue_position, hv_labour |
| `offshore_wind_connection` | subsea_cable_capacity, hvdc_valves, hv_labour |
| `transformer_replacement` | short_circuit_testing, bushings_tap_changers, goes |
| `interconnection_reform` | queue_position, sic_substrates |
| `capacity_market_tightness` | non_china_lfp, sic_substrates, queue_position |

Each bottleneck names its taxonomy layer and sub-segment (a test checks them against the
taxonomy) and its upstream inputs, each optionally with inputs of its own — up to three
steps above the bottleneck.

**Laddering** (`apps/api/app/services/discovery/laddering.py`).

- `ladder(session, seed_entity_id, max_hops=3)` — breadth-first over `entity_relationships`
  `supplier_of` edges upstream of the seed (an edge `A supplier_of B` with `B` on the
  frontier makes `A` one hop further up). Shortest path wins, cycles are cut, an edge whose
  `effective_to` has passed is not walked, and each step reads at most 500 edges
  (`truncated` says when that bound was hit). Every candidate carries its path edge by
  edge, with source, source URL, evidence ref and date.
- `query_plan(driver, bottleneck_keys=None, max_steps=3)` — the value-chain queries per
  step: step 1 the bottleneck's makers, step 2 suppliers of each upstream input, step 3
  suppliers of the inputs' inputs.
- `distance(hops)` — the schema's `supply_chain_distance_from_obvious` (0–5).

**Report.** The schema-completion layer sets `discovery_profile.entry_path =
supply_chain_laddering` and the real hop count when the draft carries
`supply_chain_laddering: {hops, …}`; otherwise the disclosed stand-in (`other`, 0) is
unchanged.

**Operator.** `python scripts/ladder_candidates.py --list | --driver <key> [--bottleneck <key>] | --ticker <T> [--hops N]`
— read-only, no network call.

**Not in this slice.** The plan's queries are not executed, and laddered candidates are not
yet fed into a discovery run's admission path. The walk is only as deep as the held
`supplier_of` edges (slices 2.4–2.5 write them from disclosures).

## 6.2 Change events (`services/discovery/change_events.py`, `integrations/sec_form4.py`, `pipeline/change_events_step.py`)

Static filters converge; change does not. Two inputs label events with the report schema's
`event_trigger` vocabulary (`first_offtake`, `permit_granted`, `insider_cluster_buy`,
`maturity_refinanced`, `strategic_or_state_investor`, `government_contract_award`,
`patent_cluster`, `export_control_or_stockpile`, `customs_flow_shift`,
`capacity_qualification`).

**Held disclosures** (`V3_CHANGE_EVENTS_ENABLED`, default on, no external call). The titles
of the company's held primary disclosures (`document_coverage.current_inventory`) dated in
the last 180 days are matched against ordered keyword rules (`RULES`, `RULES_VERSION`); the
first rule that matches labels the title. The rules are narrow on purpose:

- a title that also says the event ended or failed (terminated, cancelled, withdrawn,
  revoked, refused, suspended, expired, …) is listed under `negated`, never as an event;
- a permit needs permit wording plus a grant verb, and a corporate-action title (shares,
  securities, meeting, resolution, options, dividend) is never a permit;
- a contract, award, grant or loan is a `government_contract_award` only when the title
  names a public body (government, federal, ministry, department of, `DOE`/`DoD`
  case-sensitive, Loan Programs Office, armed forces); an option grant is not;
- "tariff" alone is not a customs event (a feed-in tariff is a power price); only
  trade-remedy wording is (anti-dumping, countervailing, section 232/301, import duty);
- "qualified opinion", "qualified person" and "qualified institutional buyer" are not a
  qualification;
- one patent grant is not a `patent_cluster`; three grant disclosures within 365 days are.

Each event keeps the document's date, title (neutralised), type, URL and tier, plus the rule
key. `source_kind` is `issuer_disclosure`: the issuer's own announcement, not the
regulator's register, which the schema prefers and which a later slice can add.

**SEC Form 4** (`V3_INSIDER_CLUSTERS_ENABLED`, default on; needs a CIK). One EDGAR
submissions request, then up to 40 Form 4 / 4/A filings from the last 365 days, each read as
its raw ownership XML (the XSL folder stripped from the primary document name), through the
SEC rate limiter with the research User-Agent. The parser refuses a DTD or entity and a body
over 1 MB. Only non-derivative open-market purchases count (code `P`, acquired). A
**cluster** is 3 or more distinct insiders buying within 30 days of the run's first
purchase; overlapping qualifying windows merge into one cluster. A joint filing is one
insider (keyed by its first reporting owner), so one economic buyer never makes a cluster.
`value_usd` is given only when every purchase in the cluster reported both shares and price;
it is never a partial sum. Every transaction keeps its filing URL, accession and filing date.

**Report.** `sections[growth_and_catalysts].change_events` — present only when an event or a
cluster was found, so every other report is byte-identical. Web: `ChangeEventsSection`.

**Not in this slice.** Event-derived candidates are not yet fed into discovery admission,
and the completer does not set `discovery_profile.event_trigger` (an event found while
researching a company is not proof that it is how the company was reached). Permit
registers, procurement feeds (USAspending, EU TED), customs data and patent offices are not
read; titles only, not document bodies.

## 6.3 Obscurity score (`services/discovery/obscurity.py`, `pipeline/obscurity_step.py`)

A positive discovery input, built from components that are each shown with value, source,
date and points (0–1, 1 = most obscure). Version `SCORE_VERSION`.

| Component | Value | Points |
|---|---|---|
| `analyst_count` | EPS analyst count, newest consensus snapshot (4.2) | 0 → 1.0 · 1–2 → 0.8 · 3–5 → 0.5 · 6–10 → 0.2 · >10 → 0 |
| `passive_ownership_pct` | % of shares held by US-registered funds (N-PORT, 3.4) | <5 → 1.0 · <15 → 0.6 · <30 → 0.3 · else 0 |
| `theme_fund_holders` | listed fund holders whose name carries a theme flag | 0 → 1.0 · 1–2 → 0.6 · 3+ → 0.2 |
| `english_news_volume` | GDELT English articles, **3-month** window (the DOC API's limit) | <20 → 1.0 · <100 → 0.6 · <500 → 0.3 · else 0 |
| `sector_mis_tag` | classified into a layer (5.2) while the sector/industry label is not an electricity label | yes → 1.0 · no → 0 |
| `primary_disclosure_language` | by listing country | English 0 · bilingual (Nordics, NL, CH, HK) 0.5 · local only 1.0 |

`score` = 100 × mean of the **available** components. A component with no data is
`not_available` and left out — never counted as zero. With fewer than 3 available
components there is no score.

**Report.** `sections[valuation_context].obscurity` when `V3_OBSCURITY_SCORE_ENABLED`
(default on); every other report unchanged. The passive-ownership block is computed once and
shared with this score. The GDELT component is one DOC API call per run, behind
`V3_OBSCURITY_NEWS_VOLUME_ENABLED` (default **off**). Web: `obscurity.ts` →
`ObscuritySection`.
