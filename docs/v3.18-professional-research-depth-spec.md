# V3.18 — Professional Research Depth: Technical Specification

**Status:** `IN PROGRESS` — opened 2026-09-21 on `main` = `371aa7f`, deployed API = `e9900ea`
(the difference is docs only). Alembic head in source and production: **040**.

**Companion documents:** [implementation plan](v3.18-implementation-plan.md) ·
[acceptance report](v3.18-acceptance-report.md).

Status labels follow [`docs/v3/README.md`](v3/README.md): `CURRENT` means verified against
the code on `main` on the date above, `V3.18 TARGET` means designed here and not yet built.

---

## 1. Why this phase exists

The V3 platform infrastructure works and is production-proven (durable jobs, external
research with platform-side verification, filings → corpus, the Research Ledger,
playbooks, the Investigator, Council V2, Red Team, escalation, cost attribution, price
classes). The first serious deep-research acceptance on **SCCO** showed that the *research*
it produces is not professional grade. The report behaves like:

```text
financial snapshot → eight agents read the same 20 evidence items
                   → eight variations of margins / net income / cash flow
                   → Chair summarises the repetition
```

V3.18 changes the organising principle from *"a financial snapshot with commentary"* to
*"a bounded graph of research questions, each with an owner, an evidence contract and an
acquisition loop"* — with financial statements as one analytical domain among fifteen.

### 2.2 Defect D1 — period contamination (root cause confirmed)

The report states FY2025 gross profit **$2,914.8m** beside FY2025 operating income
**$7,001.7m**. Verified against the primary filing (10-K accession `0001104659-26-021492`,
filed 2026-02-27, *Consolidated Statements of Earnings*):

| USD m, 12 months to 31 Dec | 2025 | 2024 | 2023 |
|---|---|---|---|
| Net sales | 13,420.0 | 11,433.4 | 9,895.8 |
| Cost of sales (excl. DD&A) | 5,359.2 | 4,841.4 | 4,687.7 |
| Operating income | 7,001.7 | 5,554.7 | 4,192.3 |
| Net income (incl. NCI) | 4,348.2 | 3,388.6 | 2,434.7 |
| Net income attributable to SCC | 4,334.9 | 3,376.8 | 2,425.2 |
| Operating cash flow | 4,752.1 | 4,421.7 | 3,573.1 |
| Capital expenditure | 1,325.3 | 1,027.3 | 1,008.6 |
| Dividends paid | 2,485.1 | 1,637.2 | 3,092.4 |

**The statement has no gross-profit line.** SCCO last tagged `us-gaap:GrossProfit` for
**FY2019** (2,914.8, frame `CY2019`, 10-K filed 2020-02-28). The mechanism:

1. `integrations/sec_fundamentals_normalizer.py:69` — `_GROSS_PROFIT = ["GrossProfit"]`.
   `_select_metric` takes the freshest entry *within the concept*. The V3.14 fix
   ("freshness beats alias order") only helps when a newer **alias** exists; a concept the
   filer simply stopped tagging wins with its last year, for ever.
2. `:669-686` — the multi-fiscal-year spread warning checks only `revenue`,
   `operating_income`, `net_income`, `total_assets`. `gross_profit`, OCF, capex, cash and
   debt are not covered.
3. `:739` — `gross_margin = gross_profit / revenue` mixes FY2019 with FY2025 with no
   period check. FCF, the other margins, ROE and debt/equity are equally unguarded.
4. `workflows/snapshot_builder.py:470-503` — `_val()` keeps `dp["value"]` and **drops the
   fact's own `as_of`**. The truth existed up to this line.
5. `services/final_report_generator.py:1914-1946` — `_sec_dp()` stamps **every** SEC slot
   with the headline period ("annual FY2025"), provenance `sourced_fact`, tier T2.
6. Nothing downstream can catch it: `report_consistency` period invariants and
   `numeric_verification` index only `*_primary_filing` / `*_current_period` slots, and
   **no accounting-relationship check exists anywhere in the codebase**.

This is the third instance of the same class (Moderna FY2022 revenue as FY2025 was the
first). The class is: *a value's own period is discarded, and the headline period is
stamped on it.*

### 2.3 Defect D2 — a ratio with no definition

Agents wrote "net income … 88.4% of net operating cash flow" and one interpreted the
decline from 113.4% as *weakening* cash conversion. **The platform computes that ratio
nowhere** — the model divided two evidence items itself. A falling NI/OCF means OCF rose
relative to NI, which is *better* conversion on the conventional OCF/NI definition; the
interpretation was inverted. `calculations/definitions.py` has ten definitions, none with
directionality or an interpretation rule, and `fcf_conversion` is the only conversion
metric. `numeric_verification` leaves a percentage beside an amount metric unchecked.

### 2.4 Defect D3 — "we did not acquire it" reported as "the company lacks it"

No vocabulary anywhere distinguishes *the issuer does not disclose X* from *InvestingBuddy
has not acquired X*. `evidence_pack._known_gaps` hands the model bare field names, so it
can only phrase them as absence. SCCO's 10-K contains segment and geographic notes, a
dividend history and mine-level production data; none were in the pack.

### 2.5 Defect D4 — external research is structurally shallow

* Web search is triggered by exactly **one** question (`recent_external_developments`),
  with budget `search_web: 2`. No playbook question requires `search_web`.
* Follow-up rounds re-run the identical deterministic tool arguments; a gap never
  reformulates a query.
* A promoted `ev:x:` item is *(provider sentence, URL, content hash)*. No excerpt is
  kept, the number is not tied to its metric (any occurrence on the page verifies), unit
  and currency are dropped, and `promoted_fact_id` has never been written.
* `ResearchBudget.check` has no caller: `max_web_searches`,
  `max_provider_research_runs`, `max_documents` and token ceilings are **not enforced**.
* A claim verified in an earlier run is re-rejected as `duplicate` and can never be cited
  again.
* Macro/commodity sources (World Bank Pink Sheet, USGS, FRED, IEA …) are
  **reference-only**: none fetches a number. The macro observation store has no production
  writer, and the Investigator passes `None` arguments to `get_macro_series`.
* Six tools are declared and unimplemented: `get_company_profile`,
  `get_previous_research`, `get_open_research_gaps`, `get_peer_set`,
  `get_peer_financials`, `get_industry_series` — so the competitive and valuation-context
  roles can never be seated on their own questions.
* SEC ingestion selects only the primary body document; 8-K EX-99.1 earnings releases
  are never ingested.

### 2.6 Defect D5 — council repetition is by construction

`services/llm/council.py:705` `_messages_for` sends the identical `evidence_json` to all
eight V1 agents; the pack is budgeted with a *financial floor of 12 of 20 items*. Eight
specialists given the same twelve financial facts produce eight financial commentaries.
V3 findings carry no topic or ownership key and nothing deduplicates them.

### 2.7 Defect D6 — the originating thesis never reaches research

`run_candidate_analysis` builds a lineage dict with `thesis_text` and `thesis_match_json`
and the final report renders it into two sections — and that is all. **No prompt in any
layer receives it** (V1 evidence pack, V3 Director, Investigator, Council, Chair). On the
escalation path the job payload carries no discovery ids at all. The reader-facing report
page renders neither section.

### 2.8 Structural facts that shape the design

* **S1 — V3 runs after the report is saved and cannot influence its prose**
  (`company_research_service.py:803`). By design in V3.10; it is now the main obstacle.
* **S2 — the candidate-launched path never runs V3.** Only
  `process_company_research_by_id` calls `_run_v3_pipeline`. The SCCO baseline had no V3
  state for this reason.
* **S3 — no playbook covers Materials / Metals & Mining**, and the sector fallback is
  suppressed whenever an industry is known, so a mining company gets baseline questions
  only.
* **S4 — `Playbook.mandatory_questions()` drops `required_calculations`**
  (`playbooks/schema.py:243-258`), so `get_calculated_metrics` is never called for any
  playbook question. `get_financial_series` and `get_macro_series` always receive `None`
  arguments, so the baseline `revenue_trajectory` question can only end as a gap.
* **S5 — a refused Council empties the report's findings.** When a blocking question
  stays open the payload's `findings` is `[]` while the ledger holds them (observed on
  MRNA: 10 ledger findings, 0 on the report).
* **S6 — nothing ever sets `verification_status='verified'`**, so
  `FindingRef.is_verified` is always false.

## 3. Goals and non-goals

**Goal.** Once a company enters deep research, investigate it the way a strong equity
analyst would: understand the business, quantify the industry, compare peers, map growth
projects, test financial capacity, name real risks, evaluate the originating thesis, and
say precisely what remains unknown — every claim cited to evidence the platform holds.

**Non-goals (explicit).**

* No open-ended issuer discovery engine (a later phase). Thesis **carry-forward** is in
  scope.
* No valuation engine, price target, fair value, rating or return projection. Sensitivities
  are *business-metric* sensitivities only.
* No new paid provider, no new cloud infrastructure. Every new data source is public,
  keyless and fetched through the existing guarded fetcher.
* No issuer-specific branches. SCCO is the regression case, never the implementation.
* No weakening of any evidence gate.

## 4. Target architecture (`V3.18 TARGET`)

```text
discovery thesis ─┐
                  ▼
company ──► Research Director ──► QUESTION GRAPH (domains × owner roles × contracts)
                                      │
             ┌────────────────────────┼─────────────────────────┐
             ▼                        ▼                         ▼
      canonical facts           company corpus            external research
      + calculations            (filings, exhibits)       (search → OUR fetch → verify)
             │                        │                         │
             └──────────► evidence contract satisfied? ◄────────┘
                                  │ no → next rung / reformulated query (bounded)
                                  ▼ yes
                     owner role writes findings under TOPIC KEYS
                                  │ (dedup: reference, don't restate)
                                  ▼
                 Council V2 → Red Team → Chair (thesis-aware)
                                  │
                                  ▼
                 PROFESSIONAL REPORT sections assembled FROM THE LEDGER
                 (13 sections; platform gaps separated from business risks)
```

### 4.1 Research Question Graph

Extends the existing flat question model rather than adding a parallel one:
`PlaybookQuestion` → `PlannedQuestion` → `research_questions` row.

| Field | Where | Notes |
|---|---|---|
| `question_key` | exists | stable id within a run |
| `domain` | **new** | closed vocabulary, §4.2 |
| `text` | exists | |
| `why_it_matters` | **new** | shown in the audit trail and the gap section |
| `priority`, `blocking` | exist | blocking remains playbook-only |
| `owner_role` | **new** | the role that owns findings under this question |
| `depends_on` | **new** | question keys; a dependant is scheduled after its parents |
| `required_metrics` | **new** (was `required_calculations`) | closed calculation vocabulary |
| `evidence_contract` | **new** | §4.4 — source classes, min items, min distinct sources, min tier |
| `search_intents` | **new** | ordered deterministic query templates, §4.5 |
| `status` | extended | `open` · `answered` · `partially_answered` · `unanswerable` |
| `unresolved_reason` | **new** | closed vocabulary: `not_acquired`, `budget_exhausted`, `source_unreachable`, `not_disclosed_verified`, `tool_unavailable`, `contract_unmet` |
| `acquisition_log` | **new** (JSONB) | every rung tried, in order, with counts — answers *"why did the agent search for this source?"* and *"why did it stop?"* |
| evidence / finding ids | derived | joined from `research_findings.question_key` |

Persisted on `research_questions` via **migration 041** (nullable, additive columns only;
no existing column changed). The graph is bounded by the existing caps
(`ABSOLUTE_MAX_QUESTIONS = 40`, mode limits).

### 4.2 The generic base research model

Fifteen domains, a closed vocabulary (`services/director/domains.py`):

`business_model` · `industry_economics` · `products_services` · `customers_end_markets` ·
`operations_assets` · `competitive_position` · `growth_pipeline` · `financial_capacity` ·
`capital_allocation` · `valuation_context` · `governance` · `risks` · `catalysts` ·
`thesis_fit` · `counter_thesis`

The baseline plan asks at least one question per domain for every company (replacing
today's five financial-centric baseline questions). Sector playbooks **add** questions
inside these domains; they do not replace the base model.

### 4.3 Roles — distinct missions, adapted not duplicated

Existing `RoleSpec` records are re-scoped; one role is added
(`industry_analyst`, splitting the overloaded "Business / Industry Analyst").

| Role | Owns domains | Primary evidence |
|---|---|---|
| `financial_analyst` | financial_capacity, capital_allocation | canonical facts, calculations |
| `business_analyst` | business_model, products_services, customers_end_markets, operations_assets | issuer filings, corpus |
| `industry_analyst` (new) | industry_economics | **external independent** statistical / benchmark data |
| `competitive_analyst` | competitive_position | peer filings, peer facts |
| `event_analyst` (growth/catalyst) | growth_pipeline, catalysts | filings, issuer releases, external |
| `risk_analyst` | risks, governance | filings risk factors, external |
| `valuation_context_analyst` | valuation_context | facts, peer facts — never a value |
| Red Team / source critic | counter_thesis | the ledger itself |

A role may **reference** another domain's finding by id; it may not restate it (§4.6).

### 4.4 Evidence contracts

A question is *answered* only when its contract holds — not when a model produced prose.

```python
EvidenceContract(
    min_items=2,                       # citable evidence items behind the findings
    min_distinct_sources=2,            # distinct documents / hosts
    required_source_kinds=("authoritative_statistical", "issuer_primary"),
    min_tier="T2",                     # best acceptable tier floor for ≥1 item
    allow_partial=True,                # unmet ⇒ partially_answered + named missing dimension
)
```

Contracts are declared per question and are sector-aware; there is no universal count.
An unmet contract produces `partially_answered` with the *missing dimension named* — never
a silent pass and never a fabricated fill. Examples: industry quantitative claim ⇒ one
authoritative benchmark/statistical source + one company exposure source; peer comparison
⇒ ≥3 verified peers × ≥2 comparable metrics, else the comparison is reported as
incomplete with the peers actually verified.

### 4.5 Active evidence acquisition

Per question, a bounded ladder; each rung runs only if the contract is still unmet:

1. **Canonical evidence** — facts, series, calculations, structured industry series.
2. **Company corpus** — lexical search with the question's search intents (not the
   question sentence verbatim).
3. **External research** — `search_web` with a *deterministic, question-specific* query
   built from a template + company identity (the model still chooses no arguments);
   each lead is re-fetched and verified by InvestingBuddy (unchanged ADR-056 rule).
4. **Reformulation** — a follow-up round uses the *next* search intent, not the same one.

Bounds, all enforced (today several are decorative): per-question query cap, per-run
`max_web_searches` / `max_documents` / wall clock / tool calls, the no-improvement stop,
and the existing cost cap semantics (unknown cost ≠ zero).

Verification is **tightened, not loosened**: a numeric claim verifies only when the value
appears *near the claimed metric's terms* in the fetched text; the matched excerpt is
stored with the lead; unit and currency travel with the evidence. A lead verified in a
previous run is *re-citable* (same evidence id) rather than rejected as a duplicate.

### 4.6 Finding ownership and deduplication

`research_findings` gains `topic_key` (e.g. `financial.cash_generation`,
`industry.copper.price`, `growth.project.<slug>`), `domain`, and
`references_finding_ids`. Before a finding is recorded:

1. a deterministic normalised claim key (topic + metric + period + rounded value) is
   compared with existing findings in the run;
2. a match from a **non-owner** role is converted into a *reference* to the owner's
   finding instead of a second finding;
3. a match from the owner is dropped as a duplicate (counted).

No embeddings, no issuer regex. The V1 council receives **role-scoped evidence packs**
(common core + domain slice) so the same twelve financial facts stop reaching all eight
agents.

### 4.7 Structured external facts

Reuses the macro observation store (`macro_datasets` → `macro_series` →
`macro_observations`: unit, currency, scale, geography, frequency, vintage, source ref),
extended with a `commodity` dimension on the series key — no new fact table. New keyless
`MacroSource` implementations, each fetched through `safe_fetch_document` with the
publisher host as the allowlist:

| Source | What | Tier |
|---|---|---|
| FRED graph CSV (IMF primary commodity prices) | monthly benchmark price series | T2 |
| World Bank Commodity Price Data ("Pink Sheet") | monthly prices, broad commodity set | T2 |
| USGS Mineral Commodity Summaries | world mine production, reserves, US salient stats, by country | T2 |

Verified fetchable on 2026-09-21 without a key. Company operating KPIs (production,
unit cost, reserves, project capex) are issuer-scoped and travel as verified evidence
with metric/unit/period attached; where a number must feed a calculation it is promoted
through the lead's `promoted_fact_id` path.

### 4.8 Deterministic calculations and metric semantics

`CalculationDefinition` gains `numerator`, `denominator`, `directionality`
(`higher_is_better` | `lower_is_better` | `contextual`) and `interpretation`. New
definitions: `cash_conversion` (OCF / net income), `capex_to_ocf`, `fcf_margin`,
`dividend_cover`, `series_change_pct` (3m/12m/36m price change), `production_growth_pct`,
`exposure_share_pct`, `capacity_increase_pct`, `price_sensitivity`. Missing input ⇒
refusal, never zero. Models receive the *definition and interpretation rule with the
value* and are told not to compute ratios; a self-computed ratio not backed by a
calculation record is moved to `unsupported_claims` by a deterministic guard.

### 4.9 Data-sanity and accounting guards

`services/statement_consistency.py` — same-period, same-scope relationship checks over
the fact set *before* it reaches any report slot or prompt:

* **own-period rule** — every statement metric carries its own period; a metric whose
  latest period is older than the headline period is reported **missing for the headline
  period**, never relabelled;
* relationship checks (`gross_profit ≥ operating_income`, `revenue ≥ gross_profit`,
  `|FCF − (OCF − capex)| ≈ 0`, duplicate facts with conflicting values, unit/currency
  mismatch, implausible ratios). These are *plausibility* checks with declared
  exceptions, not universal laws: a violation marks the involved facts
  `inconsistent`, withholds derived metrics built on them, and surfaces the conflict in
  the report — it never silently picks a winner.

### 4.10 Thesis carry-forward

`discovery_run_id`, `candidate_id`, thesis text, parsed themes/industries/regions, the
candidate's match reason and the discovery council's rationale are persisted into the
research job payload and the run record, on **both** entry paths (candidate-launched and
escalation). The Director adds `thesis_fit` questions — one per thesis dimension (for the
SCCO thesis: critical materials, electrification, EV, AI/data-centre, semiconductor supply
chain) — each requiring evidence. The allowed conclusions include *weak or indirect fit*.

### 4.11 The professional report

Thirteen reader-facing sections assembled **from the ledger** after V3 research
completes (which resolves S1 without rewriting the 7,000-line generator): executive
synthesis · thesis fit · business model · industry & market · products/assets/operations ·
competitive position · growth pipeline & catalysts · financial capacity · valuation
context · risks & counter-thesis · sensitivities · what would change the thesis ·
evidence quality & unresolved gaps. Each section lists the finding ids and evidence it
rests on; the final section separates **platform evidence gaps** from **business risks**
and shows source diversity by category. The assembled block passes the existing safety
gate and numeric verification before it is attached. The candidate-launched path runs the
same V3 pipeline (closes S2).

### 4.12 Platform-gap language

A closed `knowledge_state` on every gap: `not_acquired_by_platform` (default),
`not_disclosed_by_issuer` (only with cited evidence), `not_applicable`. Gaps reach prompts
labelled with their state, and a deterministic guard rewrites or quarantines absence
claims about the company that cite no evidence.

## 5. Invariants preserved

Evidence before prose · model output is not evidence · a search result is a lead ·
missing means missing · unknown cost ≠ zero · human review required · period integrity ·
scope integrity · provenance on every fact · no recommendation labels · no fabricated
values · no silent annualisation · no stale value relabelled current · no private document
to a public model · no unapproved paid provider · durable job attribution · one money
table · cost derived never accumulated · unpriced class ⇒ `cost=None`.

New invariants added by this phase (each with a mutation test):

1. A fact's own period is never replaced by a headline period.
2. A derived metric has a definition with directionality; an undefined ratio is unsupported.
3. A gap states whose gap it is.
4. A question is answered by its contract, not by prose.
5. A finding has one owner; others reference it.
6. The originating thesis reaches the Director and the Chair.
7. A quantitative industry claim carries value, unit, period, geography and source.

## 7. Cost and budget

A measured standard run costs ≈ $0.01. V3.18 raises external calls per run from ≤2
searches to a bounded per-domain budget (default deep-research ceiling: 12 searches,
30 fetches — the existing `STANDARD`/`DEEP` mode limits, now enforced). Per-domain units are
derivable from `research_tool_calls.task_ref` (`role:question_key` → domain) without a
second cost system. `azure_openai` remains deliberately unpriced, so a run whose council
convenes still reports unknown cost — unchanged and correct.
